## 개요
### 프로젝트 이름 : ISE-LM1**
정보보안기사, 리눅스마스터를 공부하면서 가장 어렵고 문제가 되었던 것은 실습이다.
하지만 해당 시험들의 실기를 준비하려면 실습이 필수이며 정보보안기사의 경우 해당 상황들을 테스트하기 위한 환경 설치가 귀찮고 번거롭다. 그래서 

제공하는 기능은 다음과 같다.
- 기본적인 정보보안기사/리눅스 마스터 1급 취득에 위한 기초 개념 지식 설명 및 문제 풀이
- 실기 대비용 파트
	- 리눅스 마스터 1급과 정보보안기사는 공통으로 둘 다 리눅스 운영체제를 사용한다. 그러므로 웹에서 리눅스 환경을 재현할 수 있어야 한다. 정보보안기사의 경우 유닉스/솔라리스 또한 제공이 가능하면 좋겠지만 굳이 싶어서 미룸.
	- 리눅스 마스터는 주로 명령어 사용 및 애플리케이션 설정과 관련한 문제들을 낸다. 이를 실습할 수 있어야 한다.
	- 정보보안기사의 경우 시스코 패킷 트레이서, 와이어샤크, 트립와이어 등 여러 프로그램을 전부 실습할 수 있어야 한다.

## Frontend
- **React + Vite:** 웹 기반 보안 실습 플랫폼의 UI를 구성하고, 빠른 개발 및 번들링 환경을 제공
- **xterm.js (`@xterm/xterm`, `@xterm/addon-fit`):** 브라우저 화면에서 실제 리눅스 셸과 동일한 터미널 입출력을 렌더링하고, 화면 크기에 맞춰 터미널 크기를 자동 조정
- **WebSocket & SSE (EventSource):** 터미널의 실시간 양방향 입출력은 WebSocket으로, 서버가 밀어주는 eBPF 커널 로그는 단방향 스트리밍(SSE)으로 수신

## Backend
- **Java / Spring Boot:** 웹 터미널 중계, 컨테이너 수명주기 제어, eBPF 로그 스트리밍을 담당하는 메인 백엔드 서버
- **docker-java:** Spring Boot에서 Docker 데몬 API를 제어해 접속 시 사용자별 독립 컨테이너를 생성·TTY 셸 연결하고, 연결 종료 시 즉시 삭제
- **Spring WebSocket & SSE:** React 클라이언트와 도커 컨테이너 표준 입출력(stdin/stdout), eBPF 로그 스트림을 실시간으로 연결

## eBPF 모니터링
- **eBPF & bpftrace:** 리눅스 커널 레벨에서 컨테이너 내부의 프로세스 실행(`execve`)과 TCP 연결(`inet_sock_set_state`) 이벤트를 `cgroup ID`와 함께 실시간 추적
- **Python (`ebpf_agent.py`):** 서버에 `bpftrace` 프로세스를 단 1개만 띄워두고, 수집된 커널 이벤트를 `cgroup ID` 기준으로 분류해 각 컨테이너의 HTTP 스트림으로 분배(Fan-out)하는 경량 에이전트

## 인프라 및 DevOps
- **Oracle Cloud Infrastructure (ARM64 Ubuntu 24.04):** 실습용 Docker 컨테이너와 eBPF 모니터링 에이전트를 구동하는 리눅스 호스트 서버
- **Docker (Custom Image):** 사용자마다 격리된 리눅스 실습 환경을 제공하기 위해 `nmap`, `tcpdump` 등 보안 도구를 사전 설치한 커스텀 이미지(`sec-lab-ubuntu:1.0`)를 빌드해 사용
- **Tailscale VPN:** Docker 원격 포트 및 eBPF 에이전트 포트(9000)를 공인 인터넷에 노출하지 않고, 로컬 개발 환경과 오라클 서버를 암호화된 사설망으로 연결
- **systemd:** `ebpf_agent.py`를 리눅스 시스템 서비스(`ebpf-agent.service`)로 등록해 SSH 종료나 서버 재부팅 후에도 백그라운드에서 상시 가동
- **iptables & netfilter-persistent:** `tailscale0` 인터페이스를 통한 9000번 포트 접근만 허용하도록 방화벽을 구성하고, 재부팅 시에도 규칙이 유지되도록 영구 저장
- **Git / GitHub:** 프론트엔드와 백엔드 레포지토리를 분리해 소스 코드 버전 관리
