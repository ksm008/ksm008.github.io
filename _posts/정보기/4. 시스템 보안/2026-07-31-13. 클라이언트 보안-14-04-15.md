## 1. 악성 소프트웨어(악성 코드)
### (1) 개요
#### 1) 악성 소프트웨어의 기본 개념
- 의도적으로 컴퓨터의 보안속성을 침해할 목적으로 작성된 프로그램.

#### 2) 악성 소프트웨어의 분류
- **(가) 독립형과 기생형**
	- 하나는 호스트를 필요로 하고, 하나는 필요로 하지 않음.
	- 전자의 경우 기생형(parasitic)이라고 하는데, 프로그램 단편으로 다른 실제 응용프로그램이나 유틸리티나 시스템 프로그램 없이 독립적으로 존재할 수 없다. 바이러스, 논리폭탄 그리고 백도어가 이런 예시.
	- 후자는 자체적으로 구동될 수 있는 프로그램. 운영체제에 의해 스케줄 되어 구동될 수 있음. 웜과 좀비 프로그램이 여기에 속함.
- **(나) 자기 복제 여부**
	- 악성코드는 자기 복제 여부에 따라 바이러스성, 비-바이러스성으로 나뉨.
	- 바이러스성은 웜과 바이러스
	- 비-바이러스는 트로이목마와 백도어.
	- 웜은 자기 복제를 한다는 측면에서 바이러스와 공통점을 가짐.
		- 하지만 바이러스와 달리 숙주 파일 없이 자체 실행코드를 사용해 네트워크를 통하여 자신을 복제해 전파시키며 다른 프로그램을 감염시키지 않음.
	- 하지만 바이러스는 정상적인 프로그램이나 데이터를 파괴할 목적으로 시스템 부트, 메모리, 파일 영역 등에 기생하다 다른 프로그램을 감염시킨다.

### (2) 바이러스(Virus)
#### 1) 개요
- 컴퓨터 바이러스는 다른 프로그램을 변형시키도록 하여 감염시키는 프로그램 단편. 자신을 변형시켜 실행 가능한 형태이기도 함.
- 변형이란 원래 프로그램에 루틴을 주입하여 바이러스 프로그램의 복제를 만들어내어 다른 콘텐츠를 감염시키는 것.
- 컴퓨터 바이러스는 자신을 완벽히 복제할 수 있는 비법을 가진 명령 코드를 가짐. 전형적으로 바이러스는 컴퓨터 상의 프로그램이나 실행 콘텐츠의 전송자 속에 내장됨.

#### 2) 세대별 분류
- **1세대 원시형 바이러스(Primitive)**
	- 프로그램 구조가 단순하여 분석이 쉬움.
	- 코드의 변형이나 변화 없이 고정된 크기를 가지며 기억장소에 상주해서 부트 영역이나 파일을 감염시킨다.
- **+ 일시적 바이러스와 상주 바이러스**
	- 일시적 바이러스(transient)는 호스트의 생명주기에 의존하며 프로그램이 실행될 때 동작, 종료될 때 끝남.
	- 상주 바이러스(resident)는 메모리에 상주하며 프로그램의 뒷 부분에 첨부된다. 독립적으로 활성화, 비활성화함
- **2세대 암호화 바이러스(Encryption)**
	- 백신 프로그램이 진단할 수 없도록 프로그램의 일부나 대부분을 암호화시켜 저장함. 실행 시작점 부분에 위치하는 암호해독 데이터는 항상 일정.
- **3세대 은폐형 바이러스(Stealth)**
	- 기억장소에 존재하며 감염된 파일의 길이가 증가하지 않은 것처럼 보이게 함. 백신 프로그램이 감염된 부분을 읽으려고 할 때 감염된 부분을 읽으려고 할 때 감염되기 전 내용을 보여줌으로서 바이러스가 없던 것처럼 백신이나 사용자를 속임.
- **+ 다형성 바이러스(Polymorphic)**
	- 바이러스 스캐너가 검사하기 어렵게 자신의 모습을 스스로 바꾸는 컴퓨터 바이러스. 다형성 바이러스가 모습을 바꾸면 스캐너는 새로운 바이러스라고 인식하게 된다.
- **4세대 갑옷형 바이러스(Armour)**
	- 백신 프로그램 제작자에게 공격의 화살을 돌려 백신 프로그램을 숨기기보다, 여러 단계의 암호화나 다양한 기법을 동원하여 바이러스 분석을 어렵게 하고 백신 개발을 지연시킴
- **5세대 매크로형 바이러스(Macro)**
	- 매크로 기능이 있는 다양한 프로그램 (MS 오피스, 오토캐드 등 VBS을 지원하는 프로그램)에서 활동하기 때문에 현재 등장하고 있는 바이러스 중 가장 높은 비중을 차지하고 있음.

#### 3) 매크로 바이러스
- 매크로 바이러스가 위협적인 이유는 다음과 같다.
	- 플랫폼과 무관하게 사용됨
	- 문서를 감염시키고, 코드의 실행 부분은 감염시키지 않음
	- 전자메일 등을 통해 쉽게 퍼짐
	- 실행 파일을 다룰 때보다 주의를 덜한다.
- PDF는 자바스크립트 같은 다양한 스크립트를 포함할 수 있으므로 PDF 문서도 조심해야한다.
- 매크로 바이러스는 데이터 파일 중 명령어를 실행시키는 워드, 엑셀 등에 붙어 그 파일이 열릴 때 실행된다. 매우 흔하지만 대부분 데이터 파일에 의해 감염되지 않는다 생각하기 때문에 취약하다.

#### 4) 바이러스 방지책
- **(가) 안티 바이러스 방지법**
	- 바이러스 위협에 대한 해결책은 예방. 예방을 하면 바이러스 공격의 성공률은 줄일 수 있지만 일반적으로 이 목적을 달성하는 것은 불가능. 그 다음으로 좋은 해결책은 아래를 수행할 능력을 갖추는 것.
		- 탐지 : 일단 감염되면 바이러스가 있는지 판단하고 위치를 파악한다
		- 식별 : 탐지되면 프로그램을 감염시킨 특정 바이러스를 식별한다.
		- 제거 : 바이러스를 모든 감염된 시스템에서 제거하여 퍼지지 않도록 한다.
- **+ 바이러스 증상**
	- 파일의 사이즈가 증가
	- 업데이트(갱신) 타임스탬프의 변경
	- 저장장치의 잔여 공간이 단시간내에 급격히 변경
	- 디스크 접근횟수의 급격한 증가
- **+ 바이러스 감염경로**
	- 불법복제를 통한 감염률이 가장 높음.
	- 컴퓨터 통신에 의한 감염
	- 회사, 학원, 학교 등 공공장소에서의 컴퓨터 공유의 의한 감염
	- 상업용 소프트웨어가 감염되어 전파됨
- **(나) 안티 바이러스 필터링 방법**
	- 바이러스를 검출하기 위해 virus signature 방법과 behavioral virus scanning 이라는 방법이 사용된다
	- signature scanning 방법
		- 특정 바이러스만이 가진 유일한 형태의 signature를 찾아내는 방법. 이런 시그니처는 실행 가능한 코드의 경우에는 이진 스트링으로 표현되고 스크립트 등의 언어로 된 바이러스에서는 명령어의 나열로 나타남. 이 방법은 현재까지 대부분의 안티바이러스 프로그램이 채택하고 있는 방법.
	- behavioral virus scaninng 방법
		- 바이러스가 수행 중 어떤 행동을 보이는지 추적하는 방법.
		- 시그니처 스캐닝 방법에서 불가능했던 새로운 바이러스와 웜에 대한 대처능력을 가질 수 있음.
- **+ 악성코드를 운반하는 페이로드(화물)의 네 가지 분류**
	- 시스템 파괴(오염) : 논리폭탄, Stuxnet, 랜섬웨어
	- 공격 에이전트 : 좀비, 봇
	- 정보 유출 : 키로거, 피싱, 스파이웨어
	- 잠입(스텔스) : 백도어, 루트킷
- **(다) 바이러스 예방**
	- 신뢰성 있는 업체에서 구입한 상업용 소프트웨어 사용
	- 첨부파일 함부로 열지 말기
	- 스크립트 비활성화
	- 바이러스 스캐너 정기 검사/업데이트
	- 악성코드에 대응하는 보안정책 수립과 교육

### (3) 웜(Worm)
#### 1) 개요
- 자신을 복제하여 네트워크 연결을 통해 컴퓨터에서 컴퓨터로 그 복제본을 전송한다.
- 한 컴퓨터에 도착하면 웜은 복제를 시작하고 다시 확산되기 시작.
- 웜은 보통 원하지 않는 기능을 수행함. 전자메일 바이러스는 시스템에서 자신을 확산시키기 때문에 웜의 성격을 어느 정도 가지고 있다고 여겨진다.
- 웜은 다른 시스템에 직접적인 영향을 미치지 않는다는 점에서 트로이 목마와 구분되며, 다른 프로그램에 기생하지 않는다는 점에서 컴퓨터 바이러스와 구분된다.
- **웜의 전파/확산 수단**
	- 메일, 파일 공유, 원격 실행, 원격 파일 전송, 원격 로그인, 모바일 코드

#### 2) 웜 확산 모델
- 확산은 3단계로 이루어짐. 
- 감염된 호스트는 각각 2개의 호스트를 감염시키고, 이후 감염 호스트의 수는 지수적으로 증가하게 된다.
- 시간이 경과하며 감염된 호스트는 이미 감염된 호스트를 공격하는데 시간을 허비하므로 감염 속도가 줄어든다.
- **+ 래빗(rabbit)**
	- 컴퓨터의 자원을 고갈시킬 목적으로 제한 없이 자기 자신을 복사할 수 있는 바이러스 혹은 웜

#### 3) 웜의 실행
- 전파된 시스템에서 접근 권한을 획득하고 자신을 실행하기 위해 버퍼 오버플로우, 포맷 스트링, SQL 인젝션, PHP 인젝션 등 공격 가능한 시스템의 취약점을 이용함.
- 간단하게 시스템의 취약점을 통해 권한을 확보하고 나머지 코드를 실행한다.
- 접근 권한이 확보되면 웜을 백도어로 설치하거나, DDoS 공격에 사용할 봇이나 좀비 프로그램을 다운하여 실행 가능. 또는 키로거 같은 악성 소프트웨어도 설치 가능.

#### 4) 웜 대응책
- **(가) 개요**
	- 웜이 머신 안에 상주하게 되면 안티 바이러스 소프트웨어는 이를 감지 가능. 바이러스에 대한 대처 기술과 유사.
	- 웜 확산이 이루어지면 네트워크 활동이 활발해지기 때문에 네트워크 활동, 사용을 모니터링하면 기본적인 방어형태를 갖출 수 있음.
- **(나) 네트워크 기반 웜 방어**
	- 네트워크 기반 웜 방어는 웜 모니터링 소프트웨어. 두 가지 유형의 모니터링 소프트웨어가 필요하다.
		- 진입 모니터(Ingress monitors)
			- 엔터프라이즈 네트워크와 인터넷 사이의 경계에 위치함. 경계 라우터나 외부 침입 차단 시스템이나 독립된 수동 모니터의 진입 필터링 소프트웨어의 일부.
		- 진출 모니터(Egress monitors)
			- 나가는 트래픽에서 스캐닝의 흔적이나 기타 의심스러운 행동을 모니터링해서 웹 공격의 출처를 잡아내도록 설계됨.

### (4) 트로이목마
#### 1) 개요
- 일반적인 프로그램으로 위장한 악성 프로그램.
- 자기 복제나 다른 파일을 감염, 변경시키지 않는 대신 공격자에게 시스템을 통제할 수 있는 권한을 부여하게 됨.

#### 2) 특징
- 데이터 파괴를 위해 주로 사용한다. 몰래 사용자의 파일을 삭제/변조할수도 있다.
- 원격 조정, 패스워드 가로채기, 키보드 입력 가로채기, 시스템 파일 파괴 형태 등 다양한 공격이 가능하다.
- 대표적인 프로그램으로 Back Orifice가 있다. 해커들이 백도어로 이용하기 적합하도록 개발됨.

#### 3) 대응책
- 첨부파일 함부로 열지 말고 사이트 함부로 들어가지 말고...
- 걍 조심하라고

#### 4) 스파이웨어
- 트로이목마랑 비슷하지만 주 목적은 정보 탈취.
- 정보를 탈취하여 신원 도용, 스패밍, 사기 등에 사용함. 또는 온라인 브라우징 습관에 대한 정보를 수집하여 스패머가 표적 광고를 보내는데 활용되기도 함.
- **+ 애드웨어**
	- 광고 뒤지게 띄우는 새끼들

### (5) 기타 악성 소프트웨어
#### 1) 기타 악성 소프트웨어 유형

| 이름            | 설명                                                    |
| ------------- | ----------------------------------------------------- |
| 기생 바이러스       | 프로그램에 기생하는거                                           |
| 웜             | 복제해서 다른 컴에 옮겨가고 반복...                                 |
| 논리폭탄          | 조건이 충족되면 트리거가 작동하는 유형                                 |
| 트로이목마         | 위장 프로그램                                               |
| 백도어(트랩 도어)    | 허가받지 않은 접근을 허용하는 프로그램의 변형                             |
| 모바일 코드        | 스크립트, 매크로나 다른 이동성 명령어 같은 소프트웨어.                       |
| Exploit       | 하나 또는 여러개의 취약점을 노리는 코드                                |
| Downloaders   | 공격을 받는 컴퓨터에 다른 아이템을 설치하는 프로그램. 보통 다운로더는 전자우편을 통해 전달됨. |
| Auto-rooter   | 시스템에 원격 칩입할 때 사용하는 툴                                  |
| Kit(바이러스 생성기) | 바이러스 생성 도구 모음                                         |
| 스패머           | 메일 스패밍할때 씀                                            |
| 플러더(Flooders) | 서비스 공격 거부(DoS) 공격 시 사용                                |
| 키로거           | 키 입력을 갈취                                              |
| 루트킷           | 루트 수준의 접근 허락을 얻기 위해 사용하는 도구 모음                        |
| 공격 킷          | 다양한 번식방법, 페이로드 기술을 사용하는 새로운 악성코드를 자동으로 만들어주는 툴 모음     |
| 좀비            | 감염된 컴퓨터에서 활성화되는 프로그램. 다른 컴퓨터에 대한 공격을 시작하는데 사용됨.       |
| 크라임웨어         | 불법적인 일 하는데 쓰는 악성코드                                    |
| 브라우저 하이재커     | 브라우저를 하이재킹하여 조작함                                      |
| 다이얼러          | 모뎀이 특정 번호로 연결되도록 하여 전화할 때마다 공격자가 수익을 얻도록 함            |
| 조크            | 실제 바이러스는 아니고 심리적 위협이나 불안함 조장                          |
| Hoax          | 속이거나 장난을 목적으로 퍼트리는 가짜 바이러스.                           |

## 2. 인터넷 활용 보안
#### (1) 하이퍼텍스트 전송 프로토콜(HTTP)
#### 1) 개요
- 웹에서 웹페이지를 가져오기 위해 어떻게 클라이언트-서버 프로그램이 작성될 수 있는지 정의하는데 사용됨
- 클라이언트는 요청, 서버는 응답을 함. 서버는 포트 80번을 사용하고 클라이언트는 임시 포트를 사용함.

#### 2) 영속성
- **(가) 개요**
	- HTTP 버전 1.0은 비영속적 연결을 사용하였으나 1.1은 영속적 연결을 기본값으로 함. 이는 사용자에 의해 변경 가능.
- **(나) 비영속적 연결**
	- 비영속적 연결(nonpersistent connection)에서는 각 요구, 응답에 대해 하나의 TCP 연결이 만들어짐. 동작은 아래와 같음.
		- 클라이언트가 TCP 연결을 열고 요청을 보냄.
		- 서버는 응답을 보내고 연결을 닫음.
		- 클라이언트는 end-of-file 표시가 나타날 때까지 데이터를 읽고 그 후 연결을 닫음.
	- 비영속적 연결은 서버에 큰 오버헤드를 부과한다. 서버가 연결을 열 때마다 다른 버퍼들을 필요로 하기 때문.
- **(다) 영속적 연결**
	- 영속적 연결에서 서버는 응답을 전송한 후 차후 요청에 의해 연결을 열어놓은 상태로 유지함. 서버는 클라이언트로부터 요청을 받거나 타임아웃이 되면 연결을 닫을 수 있음. 
	- HTTP/1.1 버전부터 커넥션 헤더에 Keep-Alive 옵션이 추가됨. TCP 연결 상태를 웹 서버 설정에 따라 일정시간 지속시키는 옵션. 한 번의 연결 이후에 요청/응답을 반복 가능.

#### 3) HTTP 트랜잭션
- **(가) 개요**
	- HTTP는 TCP 서비스를 이용하지만 HTTP 자체는 상태가 없는, stateless 프로토콜이다. 클라이언트에 대한 정보가 서버에 저장되어있지 않다는 의미.
	- 클라이언트는 요청 메시지를 보내어 트랜잭션을 초기화함. 서버는 응답을 보내어 대답함.
- **(나) 요청 메시지**
	- 요청 메시지의 첫 줄은 request line, 요청 라인이라고 부름.
	- 이 라인에는 문자 구분 기호에 의해 분리된 세 개의 필드가 존재함.
	- 이 필드들은 각각 메소드, URL, 버전이라 불림. 필드들은 공백 문자로 구분되어야 함.
		- 메소드 필드는 요청 유형(request type)을 정의한다.
	- **메소드**
		- **GET 방식**
			- GET 방식은 일반적인 HTTP Request 형태. 웹 브라우저에 요청 데이터에 대한 인수를 URL(Uniform Resource Locator)을 통해 전송한다.
			- GET 방식에서는 각 이름과 값을 &로 결합하며 글자수는 255자로 제한.
			- URL을 클릭하여 특정 웹 페이지를 똑같이 확인할 수 있는 경우가 GET 방식이 사용된 예.
			- GET 방식은 데이터가 주소란에 입력되기 때문에 보안이 매우 취약한 방식. 아이디나 패스워드가 인수로 전달되는 경우도 많음.
		- **POST 방식**
			- URL 요청에 데이터를 전달하지 않고 HTTP의 바디 영역에 소켓을 이용하여 데이터를 전송한다. 때문에 `?page=1&search=test` 같은 부분이 존재하지 않는다.
			- POST 방식에서는 인수 값을 URL을 통해 전송하지 않기 때문에 다른 이가 링크를 통해 페이지를 볼 수 없다.
			- 게시판 등에서 파일 업로드는 POST로만 할 수 있다. 보내는 데이터가 URL을 통해 노출되지 않기 때문에 최소한의 보안성은 갖춤.
	- 그 외 지시자들은 다음과 같다.
		- HEAD : 헤더부분만 응답해주는 메소드이다. 검색엔진에서 URL/링크의 유효성을 검증하기 위한 목적으로 주로 사용한다.
		- PUT : 클라에서 웹 서버로 데이터를 전송할 때 사용하는 방법으로 웹 서버가 처리할 수 있는 자료를 전달할 때 사용.
		- DELETE : 클라이언트가 권한이 있을 때 서버에서 웹 페이지를 제거하는 것을 허용.
		- TRACE : 디버깅에 사용됨. 클라이언트는 서버가 요청을 받고 있는지 여부를 확인하기 위해 에코 백(echo back)을 서버에 요청함.
		- OPTIONS : 시스템에서 지원되는 메소드 종류를 확인할 수 있음.
		- CONNECT : 서버에 프록시 기능을 요청할 때 사용.
	- **요청 헤더 라인**
		- 요청 라인 이후 0개 이상의 요청 헤더 라인(request header)을 가질 수 있다. 각 헤더라인은 추가 정보를 클라에서 서버로 보냄.
		- 클라이언트는 특별한 형태로 보내지는 문서를 요청할 수 있음.
			- 헤더 라인은 헤더 이름, 콜론, 스페이스, 헤더 값을 가진다. 주요 요청 헤더 정보는 아래와 같음.
				- Host : 요청의 대상이 되는 서버의 도메인명/호스트명과 포트 정보
				- User-Agent : 요청 클라이언트 애플리케이션/OS 정보
				- Referer : 현재 요청 URL 정보를 담고 있는 이전 문서의 URL 정보
	- **빈 라인**
		- 헤더의 끝을 의미하는 개행. 헤더의 수가 가변이기 때문에 빈 라인을 통해 끝을 식별한다.
	- **본체**
		- 메소드가 PUT이나 POST일 때 송신될 주석이나 웹사이트에 게시될 파일을 담고 있음. GET 방식의 경우 요청 데이터가 없기 때문에 메시지 바디가 없다.
- **(다) 응답 메시지**
	- **상태 라인**
		- 응답 메시지의 첫 줄은 상태 라인(status line)이라 부른다. 첫 필드는 HTTP 프로토콜의 버전을 의미하고 현재는 1.1.
	- **+ CR/LF과 공백**
		- CR은 캐리지 리턴으로 커서를 맨 앞으로 옮기는 Hex 문자. (OxOD)
		- LF는 라인 피드로 줄바꿈을 나타내는 Hex 문자. (Ox0A)
		- 실제로 모든 텍스트 에디터에서 엔터를 누르면 CR+LF를 입력하는 것.
		- 공백은 헥사값으로 0x20이다.
		- 상태 코드 필드는 요청의 상태를 정의한다. 이는 세 자리 숫자로 구성됨. 그지 같은거 뒤지게 많네
			- 100번대 : 조건부 응답
			- 200번대 : 성공
			- 300번대 : 리다이렉션
			- 400번대 : 요청오류
			- 500번대 : 서버오류
				- **100번대**
					- 100 : 컨티뉴
					- 101 : 프로토콜 변경
				- **200번대**
					- 200 : 요청 성공
					- 201 : PUT 메소드에 의해 파일이 생성됨
					- 202 : 요청 수락. 바로 실행되지 않음
					- 203 : Non-authoriative information
					- 204 : 헤더의 바디에 데이터 없음
					- 205 : Reset Content
					- 206 : Partial Content
				- **300번대**
					- 300 : 요청된 URL이 여러 개의 데이터를 명시.
					- 301 : Moved Permanently
					- 302 : Moved Temporary
					- 303 : See Other
					- 304 : Not Modified
					- 305 : Use Proxy
				- **400번대**
					- 400 : Bad Request (클라 문법 오류)
					- 401 : Unauthorized (권한이 없어 인증 실패)
					- 402 : Payment Required (결재 필요 요청)
					- 403 : Forbidden (리소스에 대한 권한이 없어 인가 실패)
					- 404 : Not Found (존재하지 않음)
					- 405 : Method Not Allowed (해당 방식으로 요청 불가)
					- 408 : 타임 아웃
				- **500번대** 
					- 500 : 메시지 손상과 같은 오류 발생
					- 501 : 요청된 메소드 수행 불가
					- 503 : 서비스 사용 불가
	- **응답 헤더 라인**
		- 상태 라인 이후 0개 이상의 응답 헤더 라인을 가질 수 있다.각 헤더 라인은 서버에서 클라이언트로 추가적인 정보를 보냄.
		- 예를 들어, 송신자는 문서에 대한 부가 정보를 보낼 수 있다. 각 헤더 라인은 헤더 이름과 콜론, 스페이스 그리고 헤더 값을 가지고 있다. 주요 응답 헤더 정보는 아래와 같음.
			- Content-Type : 메시지 바디의 데이터 형식
			- Content-Length : 메시지 바디의 전체 크기	
	- 빈 라인
		- 헤더의 끝을 빈 라인으로 식별.
	- 본체
		- 서버에서 클라이언트로 전송되는 문서를 포함함. 응답이 오류 메시지가 아니라면 본체가 존재함.

### (2) 쿠키(Cookie)
#### 1) 개요
- 쿠키는 사용자들이 웹을 편리하게 이용할 수 있도록 하기 위한 목적으로 만들어짐.
- 하지만 최근에는 쿠키를 이용하여 사용자의 정보를 수집하고 있다.
- 쿠키는 웹에 방문할 때 생기는 4KB 이하의 파일을 말함.
- 쿠키에는 사용자와 웹 사이트를 연결해주는 정보가 담겨있기 때문에 나중에 다시 접속하려 할 때 이 쿠키 내용을 이용하여 클라이언트의 신분을 알 수 있게 해줌.
- 쿠키와 세션은 클라이언트 상태정보 유지 기술이다.

#### 2) 쿠키를 이용한 통신
- **(가) 1단계**
	-  사용자가 웹 사이트에 방문하면 웹 사이트는 사용자의 컴퓨터에 쿠키를 만든다. 
	- 예를 들어 사용자가 사이트에 접속하면 사이트가 사용자의 브라우저를 화인하는 ID 번호를 쿠키 파일에 넣어서 사용자의 컴퓨터에 저장한다.
- **(나) 2단계**
	- 사용자가 웹 서버에 접속할 때 사용자 컴퓨터에 있는 쿠키를 웹 서버로 전송하는 단계.
	- 이전에 방문했던 사이트에 다시 접속하면 웹 사이트는 사용자의 컴퓨터에 저장된 쿠키를 통해 사용자의 여러 개인 정보를 알 수 있다.
	- 아이디와 비밀번호를 저장하여 사용한 경우 정보가 쿠키에 남아있으므로 다시 입력하지 않아도 로그인할 수 있다.

#### 3) 쿠키의 일반적 용도
- **(가) 사이트 개인화**
	- 쿠키를 통해 사용자의 성향을 파악할 수 있고, 쿠키에 심어놓은 정보를 통해 웹 사이트에 그대로 반영될 수 있다.
- **(나) 장바구니 시스템**
	- 전자상거래에 주로 사용되는 장바구니 시스템은 사용자가 물건을 고르면 그 내역이 쿠키게 저장된다.
- **(다) 웹 사이트 이용방식 추적**
	- 웹 사이트 사용 방식을 제대로 파악해 놓으면 그들이 자주 방문하는 사이트에 광고 배너를 달고 여러가지 관련 정보도 담아 놓을 수 있다.
	- 또 사용자가 많이 방문하지 않은 사이트는 폐쇄하거나 다른 방법으로 발전시킬 수도 있다.
- **(라) 타깃 마케팅**
	- 광고 대행 업체는 제3의 업체의 쿠키를 사용자 컴퓨터에 저장 후 사용자의 이용 정보를 수집한다.
	- 이렇게 수집한 사용자 정보를 광고업체에 판매 하여 그들의 광고를 얼마나 많이 보는지, 선호하는건 뭔지 알려준다.

#### 4) 쿠키의 구조
- **(가) 개요**
	- 쿠키는 4개의 속성과 하나의 데이터를 가지는 구조체.
	- 서버의 응답에 Set-Cookie 헤더를 포함시키는 방식으로 쿠키를 설정한다. 쿠키는 이름-값 쌍과 선택적인 애튜리뷰트로 구성된다. 
	- 값을 추가할 경우에는 세미콜론을 구분자로 추가한다.
	- 쿠키의 기본 구조는 다음과 같다.
	- `Set-Cookie: name=value; expires=[Date]; domain=[Domain]; path=[Path]; [secure]`
- **(나) 유효기간**
	- 쿠키가 생성되면 기본적으로 브라우저가 종료될 때까지는 쿠키의 데이터를 사용할 수 있다. 하지만 유효 기간을 지정하면 브라우저가 종료되어도 지정한 기간 동안은 쿠키 데이터를 읽고 쓸 수 있다.
	- 기간이 지나면 데이터가 소멸된다. 실제 파일이 지워지진 않아도 데이터를 읽을 수 없게 된다.
- **(다) 패스**
	- 쿠키는 쿠키 데이터를 생성한 웹 페이지에서만 그 데이터를 읽을 수 있다. 
	- 하지만 Path 항목을 지정해주면 해당 Path 이하에서는 그 쿠키 데이터를 공유할 수 있다.
- **(라) 도메인**
	- 도메인 속성은 패스 속성을 확장한 것.
	- 패스는 한 사이트에서, 도메인 항목은 도메인 단위에서 쿠키 데이터를 읽고 쓰는 권한을 설정함.

#### 5) 쿠키에 관한 오해
- **(가) 바이러스 전파**
	- 쿠키는 텍스트 파일이므로 실행되지 않는다.
