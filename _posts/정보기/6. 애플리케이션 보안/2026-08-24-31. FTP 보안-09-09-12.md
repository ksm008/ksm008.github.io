## 1. 파일 관련 프로토콜
### (1) FTP(File Transfer Protocol)
#### 1) 개요
- 한 호스트에서 다른 호스트로 파일을 복사하기 위해 TCP/IP에서 제공하는 표준 기능.
- FTP는 호스트 간에 두 연결을 설정하는 점에서 다른 클라이언트/서버 응용들과는 다름.
- 한 연결은 데이터 전송, 한 연결은 명령과 응답 등의 제어 정보를 위해 사용함.
- FTP는 두 개의 웰 논 포트, 즉 잘 알려진 포트를 사용한다. 포트 20번은 데이터 연결, 21번은 제어 연결을 위해 사용된다.
	- 데이터 연결 포트의 경우 서버가 20, 클라이언트는 1024번 이상을 사용한다.
- 제어 연결의 경우 FTP세션 동안 계속 연결 상태를 유지하고 데이터 연결의 경우 각 파일의 전송때마다 설정되며 전송 완료시 폐쇄된다.

#### 2) FTP 로그인 순서와 인증
- 인증 방식은 그냥 사용자명/비밀번호 방식으로 간단함.
- USER 명령을 통해 사용자명을 확인하고 PASS 명령으로 비밀번호를 전송함.

#### 3) FTP 연결
- **(가) FTP 능동 연결 (Active)**
	- 클라이언트에서 서버측 21번 포트로 접속하여 제어 체널을 생성하고 데이터는 서버에서 클라이언트로 접속하여 데이터를 보내는 방식.
	- 만약 클라이언트 PC에 방화벽이 설치되어 외부 접속을 허용하지 않는다면 FTP 접속은 되지만 파일을 받을 수 없는 문제가 발생한다.
	- 클라이언트가 임의 포트인 5000(예시, 1024번 이상인 포트)에서 서버의 21번 포트로 접속하여 제어 채널을 만든다.
	- 그리고 클라이언트가 이 채널을 통해 데이터 포트를 어디로 쓸 지 알려준다. 보통 제어 포트에 1을 더한 값을 쓴다.
	- 5001번을 쓴다고 보내고 나면, 서버에서는 자신의 20번 포트에서 클라이언트의 5001번 포트로 접속하여 데이터를 전송한다.
	- 데이터 전송이 끝나면 그 포트는 닫히고, 다른 번호의 포트로 전송하게 된다.
	- **Active/Passive 모드는 클라이언트가 결정한다.**
- **(나) FTP 수동 연결 (Passive)**
	- 클라이언트에서 서버측 21번 포트로 접속하고, 데이터 채널도 클라이언트에서 서버로 접속하여 데이터를 보내는 방식.
	- 클라이언트가 서버에 접속하고 PASV 명령을 보내 수동 모드로 연결할 것을 알려준다.
	- 그러면 서버는 데이터 연결을 위해 쓸 포트 번호 (1024번 이상)을 클라이언트에 알려준다.
	- 이후 클라이언트는 보통 자신이 사용했던 제어 연결 포트 + 1번을 사용하여 서버가 전해준 포트에 데이터 연결 채널을 생성한다.

>**포트 고갈 공격**
>- **TIME_WAIT 상태 악용**
>	- 데이터 채널이 한 번 전송하고 닫히는 구조를 악용함. 짧은 시간 안데 엄청나게 많은 데이터 전송을 요청하고 끊어버린다. 그러면 다 쓴 포트는 즉시 재사용되지 못하고 대기 상태에 머무르게 되는데, 요청속도를 높이면 서버가 사용할 수 있는 포트가 순식간에 동남.
>- **Passive 명령 연속 호출 악용**
>	- PASV 명령만 보낸 후 정작 데이터 포트로 접속하지는 않는 방식. 
>	- 그러면 서버는 클라이언트를 기다리며 포트를 열어둔 채 대기하고 가용포트가 모두 막힌다.

### (2) 익명 FTP
#### 1) 개요
- 계정이 없는 사용자가 서버 자원에 한정된 접근을 할 수 있는 권한을 제공함.
- 기술지원, 고객지원 등 단체에서 사용하는 경우가 많음.
- 사용자 이름을 anonymous로, 패스워드로 이메일 주소를 사용한다.
- 누가 접속중인지 서버가 로그에 기록하는 용도로 쓰임.

### (3) TFTP(Trivial File Transfer Protocol)
#### 1) 개요
- **(가) 기본 개념**
	- TFTP는 UDP 69번 포트를 사용한다.
	- FTP 기능을 전부 지원할 필요가 없거나 모두 지원하는게 비현실적인 경우를 위해 개발됨.
	- 소프트웨어 패키지를 읽기 전용 메모리나 디스크 없는 워크스테이션에 설치할 때 주로 쓰임.
- **(나) FTP와 TFTP의 차이점**
	- 전송 : TFTP는 다양한 기능을 지원하는 것이 중요하지 않을 때 사용. 부트 스트래핑을 할 때 사용하는 경우가 가장 많음.
	- 한정된 개수의 명령 : TFTP는 파일을 보내고 받는 기능만 지원함.
	- 한정된 데이터 표현 방식 : TFTP는 아스키와 바이너리만 지원한다.
	- 인증의 부족 : 삭제 기능이 없는 이유는 인증 기능이 없기 때문.

#### 2) 데이터 전송
- 데이터 전송은 연결 설정과 종료 사이에 수행됨.
- 파일은 데이터와 블록으로 나뉨. 마지막 블록을 제외한 각 블록은 정확히 512바이트의 크기를 갖는다. 마지막 블록은 0에서 511바이트의 크기를 가짐.
- 흐름 제어와 오류 제어를 위한 기능이 없으므로 흐름 제어와 오류 제어 매커니즘을 생성하여야 한다.

#### 3) 추가내용
- FTP로 파일을 전송하는 것은 안전하지 않음. 때문에 FTP 응용 계층과 TCP 응용 계층 사이에 SSL(보안 소켓 계층)을 추가하는 것. 또는 SSH 프로토콜 애플리케이션의 하나로서 SFTP라 불리는 완전히 독립된 파일 전송 애플리케이션을 사용하는 것.

### (4) NFS와 삼바
#### 1) NFS(Network File System)
- TCP/IP 프로토콜을 사용하여 네트워크 상에서 파일 시스템을 운영할 수 있도록 해주는 프로토콜.
- 데이터의 보안과 무결성을 보장하면서 인증된 네트워크 사용자가 공유된 네트워크 파일을 마치 자신의 저장장치에 있는 것처럼 사용할 수 있는 방법을 제공함.

#### 2) 삼바(Samba)
- SMB 프로토콜을 사용하여 유닉스 계열 시스템과 윈도우 시스템 간에 파일 및 프린터 자원을 공유할 수 있는 기능을 제공한다.
- 리눅스의 경우 최초 설치 과정에서 삼바 설치를 기본적으로 제공함.

## 2. FTP 보안 위협 및 대책
### 1) FTP 보안
- 비밀번호가 평문으로 되어있어 공격자가 가로채어 사용 가능하다.
- 데이터 전송 연결 또한 보호되지 않은 평문으로 데이터를 전송함. 보안을 위해서는 FTP 응용 계층과 TCP 계층 사이에 보안 소켓 계층을 추가 시킨 SSL-FTP를 사용할 수 있다.

#### 2) SFTP(Secure File Transfer Protocol)
- 보안 채널을 사용해 자료를 전송하는 다른 방법은 SFTP(보안 파일 전송 프로토콜)라 불리는 다른 독립된 프로토콜을 사용하는 것. SSH 프로토콜의 일부분인 SFTP라 불리는 유닉스의 프로그램이다.
- SSH에서 SSH 클라이언트와 서버 사이에 보안 연결이 성립되었을 때, 이 연결을 사용할 수 있는 응용 프로그램 중 하나거 SFTP.
- SSH 기반 파일 전송 프로토콜인 SFTP는 기본적으로 22번 포트를 사용함.
- FTPS는 SSL/TLS 기반의 파일 전송 프로토콜이며 기본적으로 990번 포트를 사용한다.
