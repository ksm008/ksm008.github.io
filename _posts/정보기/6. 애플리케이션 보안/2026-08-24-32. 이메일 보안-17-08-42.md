## 1. 이메일 관련 프로토콜
### (1) 전자우편의 구조
#### 1) 메일 서버 구조
- **(가) MUA(Mail User Agent, User Agent)**
	- 사용자가 메일을 송수신하기 위해 사용하는 메일 클라이언트 프로그램.
	- 대표적으로 아웃룩, 썬더버드 등이 있음.
- **(나) MTA(Mail/Message Transfer Agent)**
	- 메일 서버 프로그램으로 수신한 메일을 분석하여 수신자가 자신이 아닌 메일주소라면 해당 주소의 메일 서버로 전송하고 수신자가 자신의 메일주소라면 MDA를 통해 각 사용자 메일함에 저장하도록 한다.
	- 대표적으로 센드메일, 큐메일 등이 있음.
- **(다) MDA(Mail/Message Delivery Agent)**
	- 사용자 메일함에 메일을 저장해주는 프로그램으로 메일이 최종 수신 메일 서버에 도착했을 때 메일 서버는 MDA에 메일을 전달하고 MDA는 해당 사용자 메일함에 메일을 저장한다.
	- 대표적 MDA에는 프록메일 등이 있음.
- **(라) MRA(Mail Retrieval Agent, Message Access Agent)**
	- 메일 클라이언트가 확인을 요청하는 메일을 사용자 메일함에서 사용자로 전달해주는 프로그램으로 MUA와 MRA간 통신은 POP3 또는 IMAP 프로토콜을 기반으로 한다.

### (2)SMTP(Simple Mail Transfer Protocol)
#### 1) 개요
- **(가) 기본 개념**
	- 인터넷에서 MTA 클라이언트와 서버를 규정하는 공식적인 프로토콜은 단순 우편 전달 프로토콜(SMTP)이다.
	- SMTP는 송신자와 메일 서버 사이 그리고 두 메일 서버들 사이에서 총 두 번 사용된다. 메일 서버와 수신자 사이에는 또 다른 프로토콜이 필요하다.
	- 메일 서버는 SMTP를 가리킴. 유닉스에서 SMTP 서버 소프트웨어는 sendmail이며 마이크로소프트는 Exchange, 노벨은 GroupWise가 이에 해당함.
- **(나) 특징**
	- SMTP는 이메일을 암호화하여 이메일 전송을 보호하는 기능을 전혀 지원하고 있지 않음.
	- 사용자가 자신의 이메일 메시지를 남이 볼 수 없게 하려면 이메일 메시지를 보내기 전 별도로 메시지 본문을 암호화 해야 한다.
	- SMTP 초창기에는 인터넷을 통해 한 서버에서 다른 서버로 이메일을 중계하여 보내는 비교적 비효율적인 방법을 사용함.
	- 현대는 SMTP 서버가 사용자에게 이메일을 전달할 때 DNS를 통해 사용자의 메일 서버를 찾은 후 그 서버로 이메일을 직접 보냄.

#### 2) 명령과 응답
- **(가)개요**
	- SMTP는 명령과 응답을 사용하여 MTA 클라이언트와 서버 사이의 메시지를 전송한다.
- **(나) 명령**
	- 명령은 클라이언트에서 서버로 전송된다.
	- `Keyword:argument(s)`
	- 이는 키워드와 뒤에 따라오는 0, 또는 그 이상의 인수로 구성됨. SMTP는 14개의 명령을 규정하고 있다.
		- **HELO :** 인사 명령. SMTP 송신자가 세션을 초기화하기 위해 수신자에게 보내는 전통적인 명령.
		- **EHLO :** SMTP 확장 기능을 지원하는 송신자가 사용하는 인사 명령. 수신자에게 SMTP 확장의 목록을 보내달라고 요청하는 명령이다. 인자로 송신자의 도메인 이름을 사용함.
		- **MAIL :** 메일 전송 시작 명령. 이메일 전송 시작을 하기 위해 수신자에게 보내는 명령.
		- **RCPT :** 받는 사람 명령. 전송하고자 하는 메시지를 받는 사람의 주소를 하나 지정함.
		- **DATA :** 메시지의 데이터. 메시지를 송신하기 위해 사용함.
		- **RSET :** 리셋 명령. 송신자가 메일 전송 중에 중단을 시킨다. 
		- **VRFY :** 확인 명령. SMTP 수신자에게 편지함이 사용 가능한지 확인하도록 요청한다.
		- **EXPN :** 확장 명령. 인수로 보내진 메일링 리스트를 확장하여 그 목록을 이루는 수신자들의 주소를 되돌려 주도록 요구한다.
		- **HELP :** 도움말 명령. 인자를 명시하지 않으면 일반 도움말 정보를 요청하는 것을 의미. 인자를 사용하면 해당 명령 코드에 관한 정보를 요청한다.
		- **NOOP :** 무동작 명령(No Operation). 수신자와의 통신 상태를 확인하는 것 외 아무런 역할이 없음.
		- **QUIT :** 종료 명령. 세션을 종료한다.
- **(다) 응답**
	- 응답은 세 자리 숫자 코드로 뒤에 추가적인 문자 정보가 따라올 수 있음. HTTP 응답의 경우와 유사하다.

### (3) 메시지 엑세스 에이전트(POP와 IMAP)
#### 1) POP3(Post Office Protocol 버전 3)
- 간단하지만 기능상 제약이 존재함
- 클라이언트 POP3 소프트웨어는 수신자 컴퓨터에 설치, 서버 POP3는 메일 서버에 설치
- 전자우편 엑세스는 사용자가 메일 서버에 있는 편지함에서 전자우편을 내려받아야 할 때 클라이언트에서 시작함. 클라이언트에서 TCP 포트 110으로 서버에 연결을 한다.
- 대표적 클라이언트로 MS 아웃룩, 유도라 이메일 등이 있다.

#### 2) IMAP4(Internet Mail Access Protocol 버전 4)
- POP3보다 많은 기능을 가지고 복잡함.
- IMAP4(RFC 1730)는 데이터를 신뢰성 있게, 제대로 된 순서로 보내고 받을 수 있게 하기 위해 TCP 143번 포트에서 IMAP4 클라이언트의 연결 요청을 대기하고 있다.
- 다음과 같은 추가 기능을 제공한다.
	- 이메일 다운 전 헤더 검사
	- 이메일 다운 전 특정 문자열로 내용 검색 가능
	- 이메일 부분 다운 가능
	- 메일 서버에서 편지함을 생성, 삭제, 이름 변경 가능
	- 이메일 저장을 위해 폴더 내의 편지함들을 체계적으로 생성 가능.
