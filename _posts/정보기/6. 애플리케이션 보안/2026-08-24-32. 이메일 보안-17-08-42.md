## 1. 이메일 관련 프로토콜
### (1) 전자우편의 구조
#### 1) 메일 서버 구조
- **(가) MUA(Mail User Agent, User Agent)**
	- 사용자가 메일을 송수신하기 위해 사용하는 메일 클라이언트 프로그램.
	- 대표적으로 아웃룩, 썬더버드 등이 있음.
- **(나) MTA(Mail/Message Transfer Agent)**
	- 메일 서버 프로그램으로 수신한 메일을 분석하여 수신자가 자신이 아닌 메일주소라면 해당 주소의 메일 서버로 전송하고 수신자가 자신의 메일주소라면 MDA를 통해 각 사용자 메일함에 저장하도록 한다.
	- 대표적으로 센드메일, 큐메일 등이 있음.
- **(다) MDA(Mail/Message Delivery Agent)**
	- 사용자 메일함에 메일을 저장해주는 프로그램으로 메일이 최종 수신 메일 서버에 도착했을 때 메일 서버는 MDA에 메일을 전달하고 MDA는 해당 사용자 메일함에 메일을 저장한다.
	- 대표적 MDA에는 프록메일 등이 있음.
- **(라) MRA(Mail Retrieval Agent, Message Access Agent)**
	- 메일 클라이언트가 확인을 요청하는 메일을 사용자 메일함에서 사용자로 전달해주는 프로그램으로 MUA와 MRA간 통신은 POP3 또는 IMAP 프로토콜을 기반으로 한다.

### (2)SMTP(Simple Mail Transfer Protocol)
#### 1) 개요
- **(가) 기본 개념**
	- 인터넷에서 MTA 클라이언트와 서버를 규정하는 공식적인 프로토콜은 단순 우편 전달 프로토콜(SMTP)이다.
	- SMTP는 송신자와 메일 서버 사이 그리고 두 메일 서버들 사이에서 총 두 번 사용된다. 메일 서버와 수신자 사이에는 또 다른 프로토콜이 필요하다.
	- 메일 서버는 SMTP를 가리킴. 유닉스에서 SMTP 서버 소프트웨어는 sendmail이며 마이크로소프트는 Exchange, 노벨은 GroupWise가 이에 해당함.
- **(나) 특징**
	- SMTP는 이메일을 암호화하여 이메일 전송을 보호하는 기능을 전혀 지원하고 있지 않음.
	- 사용자가 자신의 이메일 메시지를 남이 볼 수 없게 하려면 이메일 메시지를 보내기 전 별도로 메시지 본문을 암호화 해야 한다.
	- SMTP 초창기에는 인터넷을 통해 한 서버에서 다른 서버로 이메일을 중계하여 보내는 비교적 비효율적인 방법을 사용함.
	- 현대는 SMTP 서버가 사용자에게 이메일을 전달할 때 DNS를 통해 사용자의 메일 서버를 찾은 후 그 서버로 이메일을 직접 보냄.

#### 2) 명령과 응답
- **(가)개요**
	- SMTP는 명령과 응답을 사용하여 MTA 클라이언트와 서버 사이의 메시지를 전송한다.
- **(나) 명령**
	- 명령은 클라이언트에서 서버로 전송된다.
	- `Keyword:argument(s)`
	- 이는 키워드와 뒤에 따라오는 0, 또는 그 이상의 인수로 구성됨. SMTP는 14개의 명령을 규정하고 있다.
		- **HELO :** 인사 명령. SMTP 송신자가 세션을 초기화하기 위해 수신자에게 보내는 전통적인 명령.
		- **EHLO :** SMTP 확장 기능을 지원하는 송신자가 사용하는 인사 명령. 수신자에게 SMTP 확장의 목록을 보내달라고 요청하는 명령이다. 인자로 송신자의 도메인 이름을 사용함.
		- **MAIL :** 메일 전송 시작 명령. 이메일 전송 시작을 하기 위해 수신자에게 보내는 명령.
		- **RCPT :** 받는 사람 명령. 전송하고자 하는 메시지를 받는 사람의 주소를 하나 지정함.
		- **DATA :** 메시지의 데이터. 메시지를 송신하기 위해 사용함.
		- **RSET :** 리셋 명령. 송신자가 메일 전송 중에 중단을 시킨다. 
		- **VRFY :** 확인 명령. SMTP 수신자에게 편지함이 사용 가능한지 확인하도록 요청한다.
		- **EXPN :** 확장 명령. 인수로 보내진 메일링 리스트를 확장하여 그 목록을 이루는 수신자들의 주소를 되돌려 주도록 요구한다.
		- **HELP :** 도움말 명령. 인자를 명시하지 않으면 일반 도움말 정보를 요청하는 것을 의미. 인자를 사용하면 해당 명령 코드에 관한 정보를 요청한다.
		- **NOOP :** 무동작 명령(No Operation). 수신자와의 통신 상태를 확인하는 것 외 아무런 역할이 없음.
		- **QUIT :** 종료 명령. 세션을 종료한다.
- **(다) 응답**
	- 응답은 세 자리 숫자 코드로 뒤에 추가적인 문자 정보가 따라올 수 있음. HTTP 응답의 경우와 유사하다.

### (3) 메시지 엑세스 에이전트(POP와 IMAP)
#### 1) POP3(Post Office Protocol 버전 3)
- 간단하지만 기능상 제약이 존재함
- 클라이언트 POP3 소프트웨어는 수신자 컴퓨터에 설치, 서버 POP3는 메일 서버에 설치
- 전자우편 엑세스는 사용자가 메일 서버에 있는 편지함에서 전자우편을 내려받아야 할 때 클라이언트에서 시작함. 클라이언트에서 TCP 포트 110으로 서버에 연결을 한다.
- 대표적 클라이언트로 MS 아웃룩, 유도라 이메일 등이 있다.

#### 2) IMAP4(Internet Mail Access Protocol 버전 4)
- POP3보다 많은 기능을 가지고 복잡함.
- IMAP4(RFC 1730)는 데이터를 신뢰성 있게, 제대로 된 순서로 보내고 받을 수 있게 하기 위해 TCP 143번 포트에서 IMAP4 클라이언트의 연결 요청을 대기하고 있다.
- 다음과 같은 추가 기능을 제공한다.
	- 이메일 다운 전 헤더 검사
	- 이메일 다운 전 특정 문자열로 내용 검색 가능
	- 이메일 부분 다운 가능
	- 메일 서버에서 편지함을 생성, 삭제, 이름 변경 가능
	- 이메일 저장을 위해 폴더 내의 편지함들을 체계적으로 생성 가능.

## 2. 이메일 콘텐츠 보안을 위한 보안 기술
### (1) PEM(Privacy Enhanced Mail)
#### 1) 개요
- IETF에서 인터넷 드래프트로 채택한 기밀성, 인증, 무결성, 부인방지를 지원하는 이메일 보안 기술. 
- 기존 전자우편 프로토콜을 이용하여 암호화된 정보, 전자서명, 암호화 방법 등의 내용을 본문에 텍스트 형식으로 전송한다.
- 하지만 이론 중심적, 사양이 방대하며 구현이 복잡하여 많이 사용되고 있지는 않다.

### (2) PGP(Pretty Good Privacy)
#### 1) 개요
- 1991년 Phil Zimmermann이 개발한 PGP는 대표적인 이메일과 파일 보호를 위해 암호화를 사용하는 암호시스템이다. PGP는 구현이 용이하여 가장 널리 사용되고 있다. 상업용 버전 뿐만 아니라 공개 소프트웨어로 제작된 것도 있으며, 다양한 플랫폼에서 활용할 수 있는 소프트웨어이다.
- PGP는 전자서명을 이용하여 인증을 제공하고, 대칭 블록암호를 이용해서 기밀성을 제공하고, ZIP 알고리즘을 이용해서 압축을 제공하고, 기수-64 부호화 시스템을 이용해 전자우편 호환성을 제공하며 길이가 긴 전자우편 데이터를 전송할 수 있도록 단편화 재조립을 제공한다.
- PGP는 폭발적으로 성장했고 현재는 아주 널리 사용되고 있음. 이렇게 된 이유로는 다음과 같은 여러 사항을 들 수 있다.
	- 윈도우, 유닉스, 맥킨토시 등을 포함한 다양한 플랫폼에서 동작되는 여러 버전을 전세계에서 무료로 제공했다.
	- 엄격하고 공개적인 검증을 거친 알고리즘을 기반으로 하고 있어서 매우 안전한 것으로 여겨진다.
	- 매우 다양한 영역에 응용할 수 있다.

#### 2) 키링
- PGP에서 사용하는 구조는 각 노드에서 한 쌍의 데이터 구조를 제공해야 한다. 하나는 노드가 소유한 공개키와 개인키 쌍을 저장하기 위한 것이고, 하나는 이 노드가 알고 있는 다른 사용자의 공개키를 저장하기 위한 것.
- 이 두 데이터 구조를 각 개인키 고리와 공개키 고리라고 한다.
- 다수의 사람들에게 메시지를 전송하고자 할 때 키링이 필요하다.

#### 3) PGP 보안 서비스
- PGP 서비스는 5가지로 구성된다. 인증, 기밀성, 압축, 전자메일 호환성, 단편화이다.
- 송신 부인 방지는 지원하지만, 수신 부인 방지는 지원하지 않는다.
	- **기밀성**
		- 알고리즘 : Triple-DES, IDEA, CAST, RSA
		- 송신자가 생성한 일회용 세션키로 CAST-128, IDEA, 3DES를 이용해서 메세지 암호화, 수신자의 공개키로 RSA를 이용해서 세션키를 암호화하고 메시지에 첨부한다.
	- **인증**
		- 알고리즘 : RSA, DSS, SHA-1, MD5, RIPEMD-160
		- 해시 알고리즘을 이용해서 메시지 다이제스트를 생성, 메시지 다이제스트는 송신자의 개인키로 DSS나 RSA를 이용 암호화, 그리고 메시지에 첨부.
	- **압축**
		- 알고리즘 : ZIP
	- **전자 우편 호환성**
		- 알고리즘 : RADIX-64 변환
		- Radix-64 변환을 이용해 아스키 부호로 변환한다.
	- **분할 및 재결합(단편화)**
		- 최대 메시지 사이즈 제한으로 인한 데이터의 분할 및 재결합

## 3. 스팸 메일 보안 대응 기술
### (1) 이메일 인증 기술
#### 1) 메일서버 등록제(SPF, Sender Policy Framework)
- **(가) 개요**
	- 발신 메일서버 정보를 사전에 발신 도메인 DNS 서버에 공개적으로 등록함으로써 수신자가 수신한 메일의 발신자 IP 주소가 발신자 메일주소 도메인(MAIL FROM 정보)의 실제 메일서버 정보(IP 주소)와 일치하는지 검사할 수 있도록 하는 이메일 인증 기술.
	- 스팸(해킹) 메일 발송자가 자신의 신원을 감추기 위해 발신자 메일주소를 조작하는 경우가 많으므로 이점에 착안하여 만든 인증 기술.
- **(나) 동작 절차**
	- 포털 업체들이 송신 측 메일 서버의 정보를 자신의 DNS에 등록함.
	- 메일 수신 후 발송 정보(IP)가 실제 메일을 발송한 서버 정보(IP)와 일치하는지 여부를 DNS에 질의함.
	- 발송자 정보의 위변조 여부를 파악한다.

#### 2) 도메인 키 인증파일(DKIM, DomainKeys Identified Mail)
- **(가) 개요**
	- 발신자가 발신 메일의 메시지 헤더와 바디에 대한 디저털 서명을 헤더에 삽입함. 
	- 이걸로 수신된 이메일이 위변조되지 않았는지 수신자 측에서 검증할 수 있다.
	- DKIM은 기업, 정부기관, 지메일, 야후 등 많은 ISP를 포함하여 다양한 전자우편 서비스 제공자에 의해 폭넓게 사용됨.
- **(나) DKIM 전략**
	- DKIM은 최종 사용자에게 투명한 전자우편 인증기술을 제공하도록 설계됨.
	- 사용자의 전자우편 메시지는 전자우편 발신지 관리 도메인의 개인키에 의해 서명된다.
	- 이 방법은 메시지의 내용을 서명하기 위해 발송자의 개인키를 사용하는 S/MIME과 PGP와는 다르다. DKIM은 아래 이유를 근거로 개발되었다.
		- S/MIME은 사용하는 송신, 수신 사용자 모드에 의존하고 거의 모든 사용자에게 수신되는 메시지의 대부분은 S/MIME을 사용하지 않음.  그리고 사용자가 전송하기 원하는 메시지의 대부분은 S/MIME을 사용하지 않는 수신자에게 전송한다.
		- S/MIME은 메시지 내용만 서명하기 때문에 출처와 관련된 RFC 5322 헤더 정보가 손상될 수 있다.
		- DKIM은 클라이언트 프로그램에 구현되지 않으므로 사용자에게 투명하며, 사용자는 추가적인 동작을 할 필요가 있다.
		- DKIM은 협력 도메인에서 온 모든 우편에게 적용된다.
		- DKIM은 착한 송신자가 특정 메시지를 전송하지 않았다는 것을 증명할 수 있게 하고, 위조범이 착한 송신자로 가장하는 것을 방지할 수 있게 한다.

#### 3) 도메인 기반 이메일 인증(DMARC, Domain-based Message Authentication Reporting And Conformance)


### (2) 스팸 메일 대응 방안
#### 1) 스팸 메일의 기술적 대응방안
- **메일 서버 수신 차단**
	- **콘텐츠 필터링**
		- 메일의 헤더 정보, 제목, 메시지 내용의 특정 단어나 문장 패턴을 검색하여 차단
		- 가장 많이 사용함
	- **송신자 필터링**
		- 송신자 아이피, 메일 주소, URL 등 정보를 포함한 블랙 리스트를 만들어 차단
		- 지속적으로 관리해야 함
	- **네트워크 레벨 필터링**
		- 패킷을 필터링 하거나 DNS를 변경
	- **발송량 기준 차단**
		- 기준 시간 동안 특정 용량 이상의 메일 수신 시 이후 수신 메일의 차단
		- 최대 수신 용량을 관리해야 함
	- **시간대별 차단**
		- 업무 시간에는 업무용 송신 메일 외 외부 메일 차단
		- 송신자 정보 기준이 필요함
- **메일 서버 보안**
	- **릴레이 스팸 방지**
		- 엑세스 DB를 통한 송신자별 릴레이 허용 여부 설정 기능
