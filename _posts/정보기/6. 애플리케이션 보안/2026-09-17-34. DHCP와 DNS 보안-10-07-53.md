## 1. 호스트 설정과 호스트 설정 프로토콜
#### 1) 호스트 설정의 개념
- TCP/IP에 접속하는 각 컴퓨터는 자신의 아이피를 알 필요가 있음. 클래스 없는 주소 체계 사용이나 서브넷 멤버라면 서브넷 마스크를 알 필요도 있음.
- 다른 망과 통신하기 위해선 아래 4가지 정보가 일반적으로 필요함.
	- **컴퓨터 아이피 주소**
	- **컴퓨터의 해당 서브넷 마스크**
	- **라우터 아이피 주소**
	- **네임서버의 아이피 주소**

#### 2) 호스트 설정 프로토콜 종류
- **(가) RARP**
	- 물리주소를 IP로 매핑.
	- ARP의 반대. ARP는 IP주소를 물리주소로 매핑한다.
	- 하지만 요즘은 거의 사용 안함
		- RARP는 데이터링크 계층의 브로드캐스트 서비스로 이용하는데 이는 ARP 서버가 각 망에 존재해야 함을 의미.
		- 컴퓨터는 위에서 언급한 4가지 모든 정보를 요구하는데 반해 RARP는 오로지 IP 주소만을 제공함.
- **(나) BOOTP(Bootstrap)**
	- DHCP 이전에 쓰던거. RARP의 약점을 보완하기 위한 정적 설정 프로토콜임.
	- 위 4가지 항목을 모두 제공하기 위해 RARP 프로토콜 관련 제약을 모두 제거함.
- **(다) DHCP**
	- BOOTP 프로토콜의 승계자. 역방향 호환성을 가짐.
	- 거의 BOOTP가 사라진 것 처럼 보이지만 호스트 설정을 위해 사용하는 시스템이 아직도 남아있음. DHCP의 동적인 측면을 제외하면 BOOTP에도 모두 적용이 가능함.

#### 3) DHCP(Dynamic Host Configuration Protocol, 동적 호스트 구성)
- **(가) 개요**
	- UDP 기반 프로토콜. 출발 68, 목적지 67번 포트를 사용함.
	- TCP/IP 네트워크 계층을 보조함.
	- 자동으로 사용가능한 아이피 주소를 확인하고 클라이언트에게 주소를 부여함.
	- 만약 DHCP를 정적 프로토콜로 사용하면 IP주소와 물리 주소를 매핑하는 테이블을 사용함.
	- **장점**
		- 네트워크 설계 변경이 자유로움
		- DHCP 서버에서만 네트워크 정보를 변경해주면 되므로 네트워크 구성변경이 용이
		- 실제로 호스트를 사용하는 경우에만 IP가 할당되기 때문에 IP 절약 가능
		- 사용자가 TCP/IP 설정을 따로 해주지 않아도 되므로 관리 용이
	- **단점**
		- DHCP 클아이언트는 부팅 시 브로드캐스트 방식으로 트래픽을 전송하므로 네트워크의 성능저하를 발생시킴.
		- 호스트의 전원만 켜 있어도 아이피가 할당되고, 전원을 꺼도 임대기간까지는 해당 아이피는 다른 단말에 할당될 수 없으므로 아이피 주소 낭비 발생 가능.
		- 호스트 수가 많아지면 서버의 과부하가 발생.
