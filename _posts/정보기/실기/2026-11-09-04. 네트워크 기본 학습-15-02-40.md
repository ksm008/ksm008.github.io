## 2. OSI 7 계층 모델
### (1) 개요
- ISO에서 제정한 네트워크 상호 연동을 위한 표준 참조 모델.

### (2) OSI 7 계층 모델과 TCP/IP 프로토콜 계층 비교
- **(가) OSI 모델의 각 계층은 크게 상위 계층과 하위 계층으로 구분할 수 있다.**
	- 
- **(나) TCP/IP 프로토콜 계층 구조는 4/5계층으로 구분할 수 있다.**
	- ㅁㄴㅇ

### (3) OSI 모델 계층별 기능 및 특징
- 응표세 전네데물

#### 1) 7계층 : 응용 계층
- **(가) 개요**
	- 사용자가 네트워크에 접근할 수 있는 인터페이스를 담당하는 계층.
	- 애플리케이션별로 프로토콜이 정의됨.
	- 데이터가 데이터 전송 단위.
	- 일반적으로 7,6,5계층의 전송 단위를 전부 데이터라고 한다.
	- **데이터 전송 단위(PDU, Protocol Data Unit)**
		- PCI, SDU로 구성됨.
			- PCI는 프로토콜 제어 정보를 나타냄.
			- SDU는 전송 데이터를 나타냄.
- **(나) 주요 프로토콜**
	- FTP, SSH, TELNET, SMTP, DNS, DHCP, TFTP, HTTP, POP3, IMAP, SNMP, HTTPS 등이 있다.
- **(다) 주요 장비**
	- L7 스위치 : 애플리케이션 수준에서 패킷을 교환해주는 네트워크 장비
	- 애플리케이션의 데이터의 콘텐츠 분석을 통한 탐지 및 차단, 애플리케이션 수준의 부하 분산 및 장애 조치, SSL 오프로드 기능을 제공함.

#### 2) 6계층 : 표현 계층
- 네트워크 애플리케이션 간 송수신 데이터 표현 방식의 변환을 담당함.
- 인코딩/디코딩, 암/복호화, 압축/압축해제를 한다.

#### 3) 5계층 : 세션 계층
- 네트워크 애플리케이션 간 송수신 데이터 동기화 및 논리적인 연결상태의 생성, 관리 및 종료를 담당한다.

#### 4) 4계층 : 전송 계층
- **(가) 개요**
	- 종단 노드 간 신뢰성 있는 데이터 전송을 담당하는 계층.
	- 프로세스간 통신을 담당하는 계층.
	- **포트** : 프로세스를 식별하기 위한 논리적인 식별자
	- **세그먼트**가 데이터 전송 단위.
	- 0~1023번 포트는 잘 알려진 서비스 들의 포트라 웰논포트라고 부름.
	- 1024번부터 49151번은 제조사가 관리 기관에서 용도를 등록해서 사용하는 포트다.
		- MySQL : 3306, Oracle 1521, SQL-Server 1433번이 그 예시.
	- 그 이후 65535번까지는 동적으로 할당하여 사용하는 임시 보트.
	- 0부터 1023번까지는 관리지만, 그 이후 포트는 일반 사용자도 사용이 가능하다.
- **(나) 주요 프로토콜**
	- TCP, UDP, SCTP 등이 있음.
- ****(다) 주요 네트워크 장비
	- L4 스위치 : 아이피와 포트번호를 기반으로 부하 분산 및 장애 조치 등의 기능을 제공하는 네트워크 장비

#### 5) 3계층 : 네트워크 계층
- **(가) 개요**
	- 종단 노드간 데이터 전송을 담당하는 계층.
	- 호스트 간 통신을 담당하는 계층,
	- 호스트를 구분하기 위한 논리적인 주소 : IP 주소.
	- **패킷**이 데이터 전송 단위.
- **(나) 주요 프로토콜**
	- IP, ICMP, IGMP, ARP, RARP
- **(다) 주요 네트워크 장비**
	- **라우터**
		- 서로 다른 네트워크를 연결하여 라우팅을 통해 아이피 패킷을 목적지로 전달(포워딩)해주는 네트워크 장비.
			- 데이터링크 계층의 브로드캐스트 및 멀티캐스트 프레임이 다른 네트워크로 전달되지 않도록 차단
			- 패킷 필터링 기능 제공
			- QoS 기능 제공. 서비스별로 전송 우선순위를 조절함.
	- **L3 스위치**
		- L2 스위치와 L3 라우터의 기능을 합친 네트워크 장비

#### 6) 2계층 : 데이터링크 계층
- **(가) 개요**
	- 인접한 노드 간에 신뢰성 있는 데이터 전송을 담당하는 계층.
	- **MAC 주소** : 인접한 노드를 식별하기 위한 물리적 주소
	- **프레임**이 데이터 전송 단위. 
	- 48비트 주소 체계로 네트워크 인터페이스 카드에 설정된 물리적인 주소. 변경이 불가능하다. 
	- 상위 24비트와 하위 24비트의 조합으로 구성된다. 상위 24비트는 제조사 식별 번호, 하위 24비트는 제조사에서 부여한 일련번호.
	- 콜론 또는 하이픈을 구분자로 1바이트 단위 16진수로 표현함.
- **(나) 주요 프로토콜**
	- LAN : 이더넷, 토큰링, FDDI 등
	- WAN : 프레임 릴레이, PPP, SLIP 등
- **(다) 주요 네트워크 장비**
	- **L2 스위치(스위칭 허브)**
		- MAC 주소 테이블을 검색하여 유입된 프레임의 목적지 MAC 주소 장치가 연결된 포트로 프레임을 전달하는 네트워크 장비.
- **(라) 스위칭 허브 주요 기능 및 동작 방식**
	- **학습** 기능 : 특정 포트로 유입된 프레임의 출발지 맥 주소를 기반으로 맥 주소 테이블을 갱신하는 기능
	- **포워드** 기능 : 맥 주소 테이블을 검색하여 유입된 프레임을 목적지 맥 주소 장치가 연결된 포트로 프레임을 전달하는 기능
	- **플러딩** 기능 : 프레임이 유입된 포트를 제외한 장치가 연결된 모든 포트로 프레임을 전달하는 기술. 플러딩이 발생하는 경우는 다음과 같음.
		- 목적지가 MAC 테이블에 없거나, 목적지 주소가 `FF:FF:FF:FF:FF:FF`인 브로드캐스트 주소일경우
	- **필터링** 기능
		- 목적지 포트 외에는 프레임을 전달하지 않는 기능.
		- 프레임이 유입된 포트로 다시 프레임을 전달하지 않는 기능
	- **에이징** 기능
		- 맥 주소 테이블에 있는 학습한 주소로 일정시간 프레임이 유입되지 않으면 맥 주소를 삭제하는 기능
- **(마) 스위칭 허브의 프레임 전달 방식(LAN 스위칭 방식)**
	- **Store-and-Forward 방식**
		- 프레임 전체를 모두 버퍼에 저장한 후 목적지로 전달한다.
		- 프레임 끝에 있는 FCS를 읽어 순환 중복 검사인 CRC를 수행함.
		- 손상된 프레임은 즉시 폐기하므로 신뢰성이 높지만 프레임 전체가 버퍼에 다 들어와야 하므로 지연 시간이 가장 길다.
	- **Fragment-Free 방식**
		- 컷 스루와 스토어 앤 포워드의 하이브리드 방식.
		- 이더넷 프레임의 최소 규격이자, 네트워크 충돌이 가장 빈번하게 일어나는 첫 64바이트까지만 읽어서 에러를 검사하고 포워딩을 한다.
	- **Cut-Thorugh 방식**
		- 유입된 목적지 MAC 주소인 6바이트만 읽자마자 포워딩을 시작한다.
		- 가장 빠르지만 에러 검사를 하지 않아 불량 프레임이 목적지까지 가서 대역폭을 낭비할 위험이 크다.

#### 7) 7계층 : 물리 계층
- ****(가) 개요
	- 디지털 데이터와 전기적인, 전자기적인, 광학적인 신호와의 변환 및 다양한 물리적 전송매체를 통한 신호의 전송을 담당하는 계층.
	- **비트**가 데이터 전송 단위.
- ****(나) 주요 장비
	- **더미 허브**
		- 그냥 허브라고도 함. 유입된 신호를 장치가 연결된 모든 포트로 플러딩 즉 전달해주는 네트워크 장비다.
		- 1계층 장비로 주소의 개념이 없으며 단순히 연결된 모든 장치로 신호의 전달만 담당함.
	- **리피터**
		- 전송 신호를 재생(증폭)시키는 장비다.

### (4) OSI 모델 계층 간 데이터 교환 방식
#### 1) 캡슐화와 역캡슐화
- **(가) 개요**
	- **캡슐화**
		- 상위 계층 프로토콜로부터 전달받은 데이터에 해당 계층 프로토콜의 기능 수행에 필요한 제어 정보를 추가해서 새롭게 데이터를 완성한 후 하위 계층으로 전달.
	- **역캡슐화**
		- 하위 계층 프로토콜로부터 전달받은 데이터에 해당 계층 프로토콜의 제어 정보(헤더 또는 헤더와 트레일러) 제거한 후 상위 계층으로 전달.

#### 2) 다중화와 역다중화
- **(가) 개요**
	- **다중화**
		- 여러 개의 데이터 흐름을 하나의 네트워크 경로로 합쳐서 내보냄.
		- 하나의 기능을 여러 영역에서 동시에 사용하는 기법. 상위 계층에 여러 프로토콜이 하위 계층에 있는 하나의 프로토콜을 이용하여 데이터를 전달함.
		- 수신측에서 상위 프로토콜을 식별할 수 있도록 프로토콜 식별자 정보를 헤더에 추가함.
	- **역다중화**
		- 하나의 회선으로 들어온 데이터를 원래 목적지로 분리해서 나누어 주는 과정.
		- 하위 계층 프로토콜이 여러 상위 계층 프로토콜 중 하나를 식별하여 데이터를 전달하는 방식. 프로토콜 식별자 정보를 이용함.

## 3. ARP/RARP 프로토콜
#### 1) 개요
- 아이피 주소를 MAC 주소로 변환하는게 ARP
- 그 역은 RARP.
- 프로토콜 요청 메시지와 응답 메시지로 나뉘어져 있음.
- **ARP**
	- 아이피 라우팅을 통해 선정된 경유(또는 최종 목적지) 노드의 아이피 주소에 대한 맥 주소를 알아내기 위해 사용함.
- **RARP**
	- 물리적인 MAC 주소를 논리적인 아이피 주소로 변환해주는 프로토콜.
	- 일반적으로 아이피 주소는 시스템의 하드디스크 설정 파일 내에 저장되어 있지만 하드디스크가 없는 터미널의 경우 초기 기동될 때 자신의 아이피 주소를 알아내기 위해 네트워크 인터페이스에 설정된 물리적인 MAC 주소 정보를 담은 RARP 요청 메시지를 보내고 RARP 서버로부터 IP 주소 정보를 담은 RARP 응답 메시지를 받는다.

#### 2) ARP 프로토콜 구조
- 나오면 자살함

#### 3) ARP 동작 방식
- 요청자는 응답자 호스트의 MAC 주소를 모르기 때문에 ARP 요청 메시지를 브로드캐스트 방식으로 전송한다.
- 요청 시 브로드캐스트 MAC 주소는 `FF:FF:FF:FF:FF:FF`이다. 또한 요청자의 아이피/MAC 주소가 들어가있고 응답자 호스트의 아이피와 0으로 이루어진 MAC 주소가 들어가있다.
- 응답자는 ARP 응답 메시지를 생성하여 요청 호스트에 전달한다. 이 때는 요청 호스트의 MAC 주소를 알고 있기 때문에 유니캐스트 방식으로 전송한다.
- 이후 요청/응답자 모두 각 호스트의 MAC 주소를 ARP 캐시 테이블에 저장하고 일정시간 유지, 참조함으로서 중복된 ARP 요청과 응답 통신 발생을 최소화 시킨다.

#### 4) ARP 캐시 테이블 관리
- **명령어**
	- **캐시 정보 확인**
		- `arp -a` : 윈도우/리눅스 공통. 
		- 윈도우에서 MAC 주소 바이트 구분자는 하이픈(`-`), 리눅스는 콜론(`:`)을 사용한다.
	- **캐시 정보 삭제**
		- `arp -d [아이피]` : 지정 삭제. 아이피를 안적으면 전체 삭제.
		- 리눅스의 경우 전체 삭제를 지원하지 않아서 아이피를 꼭 적어야 한다.
	- **캐시 정적 설정**
		- `arp -s [아이피] [MAC]`
		- 형식은 둘 다 똑같다. 
		- 정적 정보는 PERM으로 표시한다.

## 4. IP(IPv4) 프로토콜
#### 1) 개요
- 목적지 호스트를 식별하고 패킷을 전달하기 위한 라우팅을 담당하는 네트워크 계층 대표 프로토콜
- 비연결형 프로토콜이기 때문에 논리적인 연결 상태를 유지하지 않음. 때문에 패킷의 전송 순서를 보장하지 않는다.
- 비신뢰적 프로토콜이기 때문에 안전한 전송을 보장하지 않음.
	- 최선 노력형 프로토콜 : 목적지까지 전송하기 위해 최선을 다하지만 오류나 손실 없이 전송하는걸 보장하지는 못함.
	- 신뢰성 있는 전송을 위한 제어 동작을 수행하지 않음.

#### 2) IP 프로토콜 구조
- 나오면 자살함

#### 3) IP 단편화 및 재조합
- **(가) 개요**
	- IP 패킷은 하위 계층의 다양한 물리적 네트워크 프로토콜 프레임으로 캡슐화 되기위해 MTU에 따른 단편화가 발생함.
		- **MTU**
			- Maximum Transmission Unit
			- 물리적 네트워크 프로토콜 프레임의 데이터부 최대 크기를 말한다.
			- 물리적 네트워크 프로토콜은 각 물리적 특성에 맞게 정의된 MTU를 가지고 있으며 상위 계층에 있는 IP 프로토콜은 MTU의 크기에 맞게 적절하게 나누어 전달함.
			- 이더넷의 MTU는 1500바이트(옥텟)이다.
			- **옥텟 :** 데이터 통신의 통신량 단위. 8비트를 1옥텟이라 한다.
	- 단편화는 경유 구간의 MTU에 따라 추가로 발생할 수 있지만 재조합은 최종 목적지에서만 발생한다.
	- 일부 단편에 손실이나 오류가 발생하여 최정 목적지에서 일정 시간 이내에 IP 데이터그램 재조합에 실패하면 최종 목적지에서는 수신한 모든 단편을 폐기하고 ICMP Time Exceeded 오류 보고 메시지(타입 11)를 생성하여 출발지로 보냄.
- **(나) 단편화 동작 방식**
	- 단편화 중 각 단편의 크기는 무조건 8로 나누어 떨어져야 한다. 
	- **첫 단편**
		- 이더넷 MTU 크기는 1500바이트임. 데이터부는 1480이다. 왜냐? IP 헤더가 20바이트임.
		- 추가 단편이 있으므로 MF, 즉 More Fragment 플래그가 1로 설정되었고 첫번째이므로 오프셋이 0이다.
		- 모든 단편이 동일한 원본의 IP 데이터그램의 단편이므로 아이디는 이후 전부 똑같다.
	- **두 번째 단편**
		- 역시 추가 단편 있으니까 MF 값은 1
		- 얘는 오프셋이 1480임. 두번째 데이터부니까. 실제 오프셋 헤더 필드에서는 8바이트 단위로 설정하기 때문에 185로 설정됨.
	- **마지막 단편**
		- 추가 단편이 없으면 MF 0.
- **(다) 단편화의 단점과 PMTUD(Path MTU Discovery)**
	- 단편화는 라우터에 부하를 일으킴.
	- 경유 구간에서 추가 단편화가 발생하면 라우터는 수행하느라 전체적인 처리 성능이 떨어진다.

- 네트워크 및 호스트의 상태를 알려주는 대표 메시지는 2가지가 있다.
	- 오류 보고 메시지
	- 진단 메시지
- 나머지는 마지막에 추가로 해봅시다

## 6. TCP 프로토콜
#### 1) 개요
- **(가) 연결 지향**
	- 논리적인 연결 통로를 생성하여 통신하는 방식.
	- 종단 간에 연결 세션을 생성하고 종료하기 위해 연결 설정 과정과 연결 종료 과정을 수행한다.
	- 순서제어 : 
	- 스트림 기반의 전송 방식.

#### 2) TCP 프로토콜 구조
- **플래그**
	- URG : 긴급 데이터 전송을 알리는 제어 플래그
	- ACK : 상대방이 보낸 데이터가 정상 수신되었음을 알리는 제어 플래그
	- PSH : 송수신 데이터의 즉시 처리를 요청하는 제어 플래그
	- RST : 연결 중단, 강제 종료를 요청하는 제어 플래그
	- SYN : 연결 설정 플래그
	- FIN : 연결 종료 플래그
	- 총 6비트로 이루어짐. 위에서부터 아래가 순서다. 첫 비트가 URG.
	- `100000`이라면 이건 URG. `000001`이 FIN.

#### 3) TCP 분할과 재조합
- MSS : TCP 세그먼트의 데이터부의 최대 크기. 이더넷 환경에서 1460. 왜냐... IP헤더 20바이트랑 TCP 헤더 20바이트를 이더넷 MTU 1500에서 뺀 값.

#### 4) 연결 설정 과정
- 처음 보내는 Seq 번호는 랜덤. 보안을 위해서 0이나 1로 시작하지 않음.
- 상대방의 SYN을 받고 응답할 때 보내는 ACK 번호는 받은 SEQ번호에 +1을 한다.
- 첨에 클라이언트가 SYN, 그 다음에는 서버가 SYN+ACK, 그 다음 클라이언트가 마지막으로 ACK.
- 이렇게 연결 설정이 완료되면 TCP 상태는 ESTABLISHED가 된다.

#### 6) 연결 종료 과정 
- 얘는 4way handshake.	
- 맨 처음 클라이언트가 FIN + ACK
- 그 다음 서버가 ACK, FIN + ACK를 보냄.
- 마지막으로 클라가 ACK를 보냄.
- Seq, Ack Num은 연결 설정과 같음.
- 능동 연결 종료를 Active Close, 수동 연결 종료를 Passive Close 라고 함.
- 마지막 단계에서 서버의 연결 종료를 수신한 클라이언트는 즉시 연결을 종료하지 않고 서버에 마지막 ACK 패킷을 보내고 Time Wait 타이머가 동작하여 2MSL 동안 대기함.(Maximum Segment Lifetime)
- 2MSL은 통상 1분에서 4분. ACK 패킷이 안전하게 상대방에게 전송됨을 보장해주기 위한 것. 서버가 마지막 ACK 패킷을 수신하지 못했다면 FIN + ACK 패킷 재전송이 발생하기 때문에 일정시간 대기함.
	- FIN_WAIT 1은 클라이언트가 보낸 FIN에 대한 서버의 ACK 응답을 대기
	- FIN_WAIT 2는 그 이후 다시 서버의 FIN + ACK 응답 대기
	- TIME_WAIT은 마지막 ACK 전송 이후 2MSL 동안 대기하는 상태. 
	- CLOSE_WAIT은 서버가 FIN + ACK 수신에 대한 ACK를 보내고 FIN + ACK를 보내기 전까지의 상태.
	- LAST_ACK는 서버가 FIN + ACK 패킷 보내고 마지막 ACK 응답을 대기하는 상태
	- CLOSED : 종료된 상태

#### 8) 세선 하이재킹 공격
- **(가) 개요**
	- 인증이 완료된 정상적인 사용자 세션을 중간에 공격자가 가로채서 인증 작업 없이 사용자로 위장하여 가로챈 세션으로 통신하는 행위를 말한다.
	- OTP나 시도/응답 기법을 사용해도 이미 인증된 세션을 가로채기 때문에 세션 하이재킹이 이를 무력화할 수 있다.
- **(나) TCP 세션 하이재킹**
	- 케빈 미트닉이 사용했던 방법 중 하나
	- TCP는 연결 설정 과정을 통해 상호 간에 세션을 생성한 후 다음 식별자를 통해 상호간에 인식하게 된다.
		- 출발지 아이피, 포트와 목적지 아이피와 포트
		- 순서번호와 수신확인응답번호(Seq num, Ack num)
	- 공격자는 출발지 주소와 포트번호를 위조하고 순서번호를 예측하여 세션을 탈취한다.
	- 받은 seq + len = ack 번호가 된다...
	- 중간에서 len을 조작해서 ack 번호를 틀리게 만듬. 그러면 서로 서버와 클라이언트는 교정 메시지를 계속해서 반복한다. 이걸 ACK Storm이라고 한다.
	- 공격자는 이 ACK Storm을 막기 위해 다시 서버의 아이피를 스푸핑하여 강제 종료 RST 패킷을 날려버린다.

## 8. 네트워크 관련 기술
### (1) VLAN 기술
#### 1) 개요
- 하나의 L2 스위치 즉 스위칭 허브는 하나의 LAN을 구성하는 장치들을 연결하기 위해 2개 이상의 가상의 LAN을 구성할 수 있다.
- 브로드캐스트 도메인을 나누기 위해 사용하는 기술. 물리적인 네트워크 구조 변경 없이 스위치에서 제공하는 기능을 통해 논리적 LAN을 구성할 수 있다.
	- 같은 VLAN에 속한 호스트 간에만 사용 가능.
	- VLAN 내의 브로드캐스트 트래픽은 다른 VLAN으로 전달되지 않고 만약 다른 VLAN간 통신하려면 라우터 경유가 필수임.
- 브로드캐스트 도메인을 생성함으로써 해당 트래픽을 제한하여 전체 네트워크 서비스의 성능 향상을 기대할 수 있음.
- 서로 다른 L2 스위치 2개를 사용하고 각각 VLAN을 2개로 구성하여 나눴을 때, 랜선 하나를 꽂아 트렁크 포트로 사용한다.
	- 트렁크 프로토콜(IEEE 802.1Q)을 통해 프레임에 VLAN 태그를 달아 보내서 스위치가 분류하여 프레임을 소속된 VLAN 포트로 뿌려줌.
- VLAN별로 다른 보안 정책을 적용할 수 있으므로 보안성을 높일 수 있음.

#### 2) VLAN 종류
- 포트 기반, 맥 주소 기반, 네트워크 주소 기반, 프로토콜 기반으로 나뉨.
- 포트 기반이 가장 일반적이고 많이 사용됨. 맥 주소는 일일이 주소를 등록하고 관리해야해서 귀찮고 어려움.
- 포트 기반은 포트에 각 VLAN을 할당함. 맥 주소 기반은 맥 주소를 VLAN에 등록하는 방식. 네워크 기반도 주소별로 VLAN을 구성한다. 프로토콜은 사용하는 통신 프로토콜끼리 구성함.

#### 3) 정적/동적 VLAN
- 정적 VLAN은 관리자가 직접 스위치 모든 포트에 VLAN 정보를 할당한다. VLAN 프레임을 처리해야 하는 모든 스위치에 이를 할당해야 함. 중소규모 네트워크에서 사용함.
- 동적 VLAN은 별도 관리 장비를 사용하여 VLAN 정보를 자동으로 할당하는 방식이다.
- 스위치 포트에 접속하는 MAC 주소에 따라 자동으로 VLAN을 할당함.
- 관리 장비를 통해 MAC 주소와 VLAN ID간 매핑 테이블 관리가 필요함.
- 대형 네트워크 규모에서 사용함.

### (2) NAT 기술
#### 1) 공인 주소와 사설 주소
- 공인 주소는 인터넷에서 사용할 수 있는 호스트를 식별하기 위한 고유 주소임.
- 사설 주소는 인터넷에서 사용이 불가능하고 사설망에서만 자유롭게 사용할 수 있는 주소임.
- 인터넷에 접속하기 위해서는 NAT 기술을 통해 공인 주소로 변환해야 함.
- 사설 주소로 예약된 클래스는 다음과 같음.
	- A 클래스 : 10.0.0.0/8 (10.0.0.0 ~ 10.255.255.255)
	- B : 172.16.0.0/12(172.16.0.0 ~ 172.31.255.255)
	- C : 192.168.0.0/16(192.168.0.0 ~ 192.168.255.255)

#### 2) NAT 개요
- 사설 아이피와 공인 아이피 변환 기술을 말함.
- 부족한 공인 아이피 주소를 절약할 수 있음.
- 내부 시스템이 사설 아이피를 적용하면 그 아이피로는 내부 시스템에 접속할 수 없으므로 안전한 내트워크 환경 구축이 가능함.

#### 3) NAT 유형
- **정적 NAT**
	- 하나의 사설 주소와 하나의 공인 주소를 1대1로 매핑함.
- **동적 NAT**
	- 다수의 사설 아이피와 소수의 공인 주소를 M:N으로 동적으로 변환함.
	- 소수의 공인 아이피로 변환하므로 모두 할당 되었을 때는 더 할당이 불가능하며 일정 시간 통신하지 않는 연결은 NAT 테이블에서 삭제된다.
	- 그래서 동적 NAT을 사용할 때는 PAT을 사용하는게 더 효율적.
- **PAT(NAPT)**
	- 다수의 사설 이이피 주소를 포트 번호를 이용하여 하나의 공인 아이피 주소로 변환함.
	- 다수의 사설 아이피를 하나의 공인 아이피로 변환할 수 있으므로 내부 사용자 망에 있는 다수 사용자 호스트의 인터넷 접속에 주로 적용되는 NAT 기술.

## 10. 스니핑(Sniffing) 공격
### (1) 개요
- 공격 기법은 더미 허브 환경이냐, 스위치 환경이냐에 따라서 나뉨. 
- **스니핑에 대한 대응 방안**
	- 암호화 프로토콜 또는 프로그램을 이용한 데이터 암호화.
	- 더미 허브에 비해 안전한 스위칭 허브를 사용한다.
	- 스니핑 탐지 도구를 이용하여 지속적인 점검을 한다.

### (2) 더미 허브에서의 스니핑 기법
#### 1) 개요
- 허브는 유입된 신호를 장치에 연결된 모든 포트로 전부 플러딩해버린다. 주소 개념이 없어 모든 포트로 보내버리기 때문에 네트워크 스니핑 공격에 매우 취약함.
- 네트워크 이터페이스 카드의 동작 모드를 'Promiscuous Mode(무차별 모드)'로 설정하면 허브를 통해 전달되는 모든 프레임을 스니핑할 수 있다.

#### 2) 네트워크 인터페이스 카드 동작 모드
- **Non-promiscuous**
	- 비무차별 모드, 기본 동작 모드
	- 유입된 프레임의 목적지 MAC 주소가 자신이 해당하는 경우에만 수신하고 나머지는 모두 폐기하는 동작 모드.
	- 자신이 해당하는 경우란 목적지 MAC 주소가 자신의 주소와 일치하거나 브로드캐스트 또는 멀티캐스트 프레임인 경우를 말함.
- **Promiscuous**
	- 유입된 프레임의 목적지 맥 주소와 무관하게 모든 프레임을 수신하는 동작 모드. 따라서 이게 설정되어있으면 스니핑 공격을 하는걸로 의심할 수 있음.

#### 3) 실습
- **리눅스에서 설정하는 방법**
	- `ifconfig eth0 promisc` : Promiscuous 모드 설정
	- `ifconfig eth0`으로 확인했을때 PROMISC이 떠있으면 무차별 모드.
	- 또한 로그 파일인 `/var/log/message`에도 네트워크 인터페이스 설정이 바뀌었다는걸 기록한다.
	- 만약 해제하고 싶으면 `-promisc`을 쓰면 된다. 

### (3) 스위치 환경에서의 스니핑 기법
#### 1) 개요
- 스위치 장비는 기본적으로 MAC 주소 테이블을 검색하여 목적지 MAC 주소의 장치가 연결된 포트로 패킷을 전달하기 대문에 장치가 연결된 모든 포트로 패킷을 전달하는 더미허브에 비해 스니핑에 안전함.
- 그렇다고 안일어나는건 아님.

#### 2) 스위치 재밍 공격을 이용한 스니핑 기법
- **(가) 개요**
	- MAC Flooding 공격이라고도 함.
	- 다수의 출발지 MAC으로 위조한 프레임을 생성하여 스위치의 MAC 주소 테이블을 오버플로우시켜 더미 허브처럼 플러딩하게 함으로써 스위치를 통해 전달되는 모든 프레임을 공격자 쪽으로 전달되도록 하는 스니핑 기법이다.
	- 스위치는 장애시 Fail Safe(Open) 정책을 따르는 장비기 때문에 장애가 발생하면 더미 허브처럼 연결된 모든 장치로 프레임을 전달함.
	- Fail Safe(Open)은 장애 발생 시 모든 트래픽을 허용한다.
	- Fail Secure(Close)는 장애 발생 시 모든 트래픽을 차단한다.

#### 3) ARP 스푸핑을 이용한 공격
- ARP Cache Poisoning 공격이라고도 함.
- 공격자가 특정 호스트의 MAC 주소를 자신의 MAC 주소로 위조한 ARP Reply 메시지를 희생자 호스트에 지속적으로 전송하면 희생자 호스트의 ARP 캐시 테이블에 특정 호스트의 맥 주소가 공격자의 맥 주소로 조작됨.
- ARP 프로토콜의 구조적 취약점을 이용했다.
	- 상대방이 보낸 인증이 미흡하다. 수신한 ARP Reply를 보낸 상대방이 올바른 상대방이 보냈는지 확인하지도 않고, 심지어 자신이 요청하지 않은 ARP Reply를 수신해도 ARP 캐시 테이블을 갱신한다.
- ARP 메시지는 로컬 네트워크에서 동작하므로 공격자와 희생자는 같은 네트워크에 있어야 한다.
- **대응 방안**
	- ARP 캐시 테이블에 대해 주소를 MAC 주소를 정적으로 설정하여 ARP Reply 메시지를 수신해도 캐시 정보가 갱신되지 않도록 한다.
		- `arp -s [IP주소] [MAC주소]`
		- 단 재부팅하면 모두 삭제되므로 매번 다시 재등록해줘야 한다.
	- 네트워크 상의 ARP 트래픽을 실시간으로 모니터링하는 Arpwatch 등을 이용하여 IP 주소에 대한 MAC 주소의 변경 여부를 확인한다.

## 11. 포트 스캔 기법
### (1) 개요
- 주로 Nmap을 사용하여 포트스캔을 한다.

### (2) Nmap 포트 스캐너 사용 방법
- **NMAP(Network Mapper)**
	- 모든 운영체제에서 사용 가능한 스캔 도구. 
	- 운영체제의 종류, 사용 서비스에 대한 정보, FTP 서버의 취약점을 이용한 bounce 공격을 수행할 수 있는 스캔 도구.
	- 프로그램 소스를 공개하여 많은 사용자들이 직접 소스를 업그레이드도 가능. 최근에는 윈도우용 GUI도 지원.
	- **사용법**
		- `nmap [scan type] [options] <target>`
		- **Scan Type**
			- `-sS` : TCP SYN Scan (하프 오픈)
			- `-sT` : TCP Connection Scan (오픈)
			- 대충 `-s` 다음 유추할 수 있는 것들이 들어감.
			- UDP면 `-sU`, Xmas면 `-sX`...
			- `-sN, -sA, -sP(-sn), -D, -b` : 각각 null, ACK, Ping, Decoy, FTP Bounce이다.
		- **Port Option**
			- `-p`로 포트를 지정하여 스캔이 가능하다.
			- `-p <service>` 로 service 자리에 서비스명으로도 스캔이 가능하다. ssh 같은거.
			- 여러 포트를 20,25,80 처럼 콤마로 구분하여 스캔도 가능
			- 1-1023처럼 범위로도 가능
			- `-p T:21,23,110,U:53`처럼 TCP, UDP별로 구분도 가능
		- **Output Option**
			- `-v` : 상세 내역 출력. 
			- `-d` : 디버깅
			- `-oN <file>` : 결과를 일반 파일 형식으로 출력
			- `-oX <file>` : 결과를 XML 파일 형식으로 출력
			- `-oG <file>` : 결과를 Grepable 파일 형식으로 출력
			- `-oA <Directory>` : 위 3파일을 경로에 전부 출력
		- **기타 옵션**
			- `-O` : 영대문자 O. 호스트 운영체제 출력
			- `-F` : 빠른 네트워크 스캐닝
			- `-T0 ~ T5` 아주 빠르게부터 아주 느리게. 이게 뭔 개소리냐

### (3) TCP Connect(Open) 스캔
- 대상 호스트의 지정한 포트에 SYN 패킷을 전송한다.
- 포트 오픈 여부에 따라 응답 패킷이 다름.
	- 열려있다면 SYN+ACK 응답을 수신하고 ACK 패킷을 송신자가 전송하여 TCP 연결을 마무리한다. 이 때 연결을 끊기 위해 RST + ACK 응답을 추가로 송신한다.
	- 닫혀있다면 RST + ACK 응답을 수신한다.
- TCP 연결 설정이 이루어지기 때문에 대상 호스트의 시스템 로그에 접속 기록이 남아있다.

### (4) TCP SYN(Half-Open) 스캔
- 열려있다면 SYN + ACK를 수신하고, 닫혀있다면 RST + ACK를 수신한다.
- 여기까지는 TCP 오픈 스캔과 똑같지만... 열려있다면 ACK 패킷을 송신하지 않고 바로 RST 패킷을 송신하여 패킷 조작을 즉시 중단한다. 따라서 TCP 연결이 완료되지 않는다.
- TCP 3-way handshake를 완전하게 수행하지 않기 때문에 half open이라 부른다.
- 대표적인 스텔스 스캔 중 하나이다. 연결 로그가 남지 않는다.

### (5) TCP FIN, NULL, Xmas 스캔
#### 1) 개요
- 여기 애들은 전부 스텔스 스캔이다. 관리자 권한으로 TCP 패킷 자체를 조작하여 오픈 여부를 판단하는 스캔 방식들.
- 아래 스캔들은 전부 열려있을땐 응답이 없고, 닫혀있을 땐 RST + ACK 응답을 받는다.

#### 2) 스캔 방식
- **(가) TCP FIN 스캔**
	- 송신자는 FIN 제어 플래그만 설정된 조작 패킷을 보낸다.
- **(나) TCP NULL SCAN**
	- 아예 플래그가 없는 TCP 패킷을 보낸다.
- **(다) Xmas 스캔**
	- URG+PSH+FIN 제어 플래그가 설정된 패킷을 보낸다.

### (6) TCP ACK 스캔
#### 1) 개요
- 얘는 포트 오픈 여부가 아니라 방화벽 룰셋을 파악하기 위한 스캔이다.
- ACK 제어 플래그가 설정된 패킷을 보낸다.
- 방화벽에 의해 차단되면 응답이 없거나 ICMP 오류 메세지 응답을 받는다.
- 만약 차단되지 않았다면 포트 오픈 여부와는 상관없이 항상 RST 응답을 받는다.

### (7) UDP Scan
#### 1) 개요
- 닫힌 UDP 포트로 패킷을 보내면 ICMP 오류 메시지로 응답하는 특성을 이용한다.
- 하지만 UDP는 세션을 맺지 않는 비연결형 프로토콜이므로 빈 패킷을 보내면 서버는 이를 무시하고 응답을 보내지 않는 경우도 많으며 일부 서비스는 단방향으로 응답 자체가 없다. 때문에 응답이 없을 경우 포트가 열린 상태인지, 아니면 차단된 상태인지 신뢰성이 떨어진다.
- 열려 있으면 응답이 없고, 닫혀있으면 ICMP Port 또는 Destination Unreachable 응답을 받는다.

### (8) Decoy 스캔
#### 1) 개요
- 실제 스캐너의 주소 외 여러 개의 가짜 IP 주소를 함께 사용하여 스캔하는 방식.
- Decoy 스캔은 다른 스캔에 옵션을 추가하는 방식이므로...
- `nmap -sS -p 22,80 -D RND:5 172.30.3.100`
	- `-D RND:5` : 무작위 가짜 출발지 IP 5개를 섞으라는 뜻

## 12. 서비스 거부(DoS) 공격
### (1) 개요
- 서비스의 가용성을 저하시켜 정상 사용자 요청을 처리하지 못하게 하는 공격이다.
- 파괴, 시스템 자원 고갈, 네트워크 대역폭 소진 공격이 대표적이다.
- 만약 공격자가 단일 컴퓨터로 공격하면 DoS, 공격자가 다수의 컴퓨터로 이루어진 봇넷을 사용하여 동시에 공격하면 DDoS.

### (2) Ping of death
- 핑 명령으로 뒤지게 큰 ICMP Echo Request 패킷을 전송하여 대상에게 과부하나 오류를 유발하는 공격.
- 너무 큰 ICMP 패킷은 MTU(Maximum Transmission Unit)을 초과하므로 네트워크 전송 과정에서 IP 단편화가 발생해 여러개의 단편으로 분할되어 대상 시스템으로 전달된다.
- 대상 시스템이 다수의 IP 단편을 재조합하는 과정에서 과부하나 재조합 버퍼 오류에 의한 서비스 거부가 발생 가능함.
- 정상적인 ICMP 패킷은 단편화가 거의 없으므로, IP 단편화가 발생한 ICMP 패킷을 탐지하여 차단한다.
- 또는 최신 시스템은 비정상적으로 큰 ICMP 패킷을 무시하거나 안전하게 처리하도록 설정되어있어 여전히 취약점을 가지고 있는 시스템이라면 최신 보안 패치를 적용해야 한다.
- 와이어샤크에서 **ID**가 똑같고 Info에 **Fragmented IP protocol**이라고 뜨면 단편화가 발생한 것.

### (3) Land Attack
- 출발지 아이피를 희생자의 아이피로 위조한 패킷을 전송하는 IP 스푸핑 공격 방법이다.
- 자기 자신에게 응답을 보내는 비정상 동작을 유발함으로 무한 루프 상태 또는 과도한 자원 소모를 일으킨다.
- 이거도 역시 최신 패치를 하거나 출발지와 목적지 IP 주소가 동일한 패킷을 탐지하고 차단하면 된다.
- `hping3 --icmp --spoof 172.30.1.100 172.30.1.100 -c 5`
- 와이어샤크에서 출발/목적지가 같은 패킷을 확인하면 된다.

### (4) Smurf
- 에브리원 핑 찍고 이 새끼가 그랬어요 하는거
- 출발지 주소를 희생자로 스푸핑 하고 증폭/반사 네트워크의 다이렉티드 브로드캐스트 주소로 ICMP Echo Request 패킷을 전송한다. 그러면 해당 네트워크의 모든 호스트가 ICMP Echo Reply 패킷을 희생자에게 보내도록 만들어 네트워크 대역폭을 소진시키는 서비스 거부 공격.
- ==🔴아이피 스푸핑==과 ==🔴다이렉티드 브로드캐스트==, ==🔴증폭/반사 네트워크==를 사용하는 것이 주요 특징이다.
- 증폭/반사 네트워크 관점에서는 다이렉티드 브로드캐스트 패킷이랑 해당 패킷에 대한 ICMP 응답 비활성화를 하면 된다.
- 희생자 관점에서는 비정상적으로 많은 ICMP Echo Reply 패킷을 탐지하고 차단하면 된다.
- 와이어샤크에서는...
	- 희생자 입장에서는 같은 증폭 네트워크의 호스트로부터 왔는지 확인한다. 
		- 192.168.1.X 같이...
	- 증폭자 관점에서는 네트워크의 모든 호스트들이 하나의 호스트에게 Echo Reply를 전송하는지 살펴본다.

### (5) Teardrop 공격
- IP 단편의 오프셋 값을 비정상적으로 조작한 패킷을 전송하여 대상 시스템이 IP 단편을 재조합하는 과정에서 오류가 발생하도록 만드는 서비스 거부 공격.
- 정상 IP 단편화에서는 각 단편화의 오프셋이 정확하게 설정되어 재조합되지만, 이 공격은 중첩 또는 비연속적인 오프셋 값을 가진 단편화를 전송하여 재조합 모듈에서 버퍼 오버플로우 등 시스템 오류를 발생시킨다.
- 정상 범위를 벗어난 오프셋을 가진 IP 단편을 탐지하고 차단한다.
- 역시나 시스템 패치 적용.

### (6) IP 단편화 취약점을 이용한 우회 공격
#### 1) 개요
- IP 단편화 과정에서 발생할 수 있는 취약점을 악용하여 패킷 필터링 장비를 우회하기 위함.
- 작은 단편 공격과 단편 중첩 공격이 대표적이다.

#### 2) 작은 단편 공격(Tiny Fragment 공격)
- TCP/UDP 헤더가 2개의 IP 단편으로 나눠질 정도로 첫 단편을 아주 작은 크기로 생성한다.
- 첫 단편에는 목적지 포트가 없도록 하고, 두 번째에는 있도록 한다.
- 그럼 첫 단편에는 검사해야 할 목적지 포트가 없으므로 허용하고, 두번째 단편은 이전 단편이 허용되었다는 이유로 통과시킨다.
- 통과된 두 단편은 대상 시스템에서 재조합되어 공격자가 의도한 포트로 연결이 이루어지게 된다.

#### 3) 단편 중첩 공격(Fragment overlap)
- IP 오프셋 값을 조작하여 두 번째 단편이 첫 단편을 덮어쓰도록 하는 것.
- 첫 단편에는 패킷 필터링 장비가 허용하는 포트 정보를 포함시키고, 두 번째 단편은 접근을 차단하는 포트 번호를 포함시킨다.
- 첫 단편이 허용되었으므로 두 번째 단편도 허용된다. 이때 두번째 단편의 오프셋은 첫 번째 단편의 목적지 필드를 덮어쓰도록 조작되어있다.
- 그 이후 다시 재조합하는 과정에서 두 번째 단편의 목적지 포트 번호가 덮어씌워져 공격자가 의도한 포트로 연결이 이루어진다.
- 패킷 필터링 장비 즉 방화벽이나 IDS, IPS가 단편을 재조합하여 검사할 수 있도록 한다. 또는 비정상 단편화 패킷을 탐지, 차단 가능한 패킷 필터링 장비를 적용한다.

## 13. 분산 서비스 거부(DDoS) 공격
#### 1) 정의
- 봇에 감염된 다수의 좀비PC나 디바이스가 동시에 공격 대상에게 비정상적인 트래픽을 전송하여 서비스 장애를 유발하는 공격.

#### 2) 공격 구조(구성 요소)
- 공격자, C&C 서버(명령 제어, Command and Control, C2 서버), 좀비 PC/디바이스, 공격 대상 총 4가지로 나뉨.
- 좀비 피씨같이 감염된 기기를 봇이라고 하며 이러한 봇의 집합을 봇넷이라 한다.
- 명령 제어 서버는 이런 다수의 봇들에게 명령을 내리는 커맨드 센터.

#### 3) 절차
- 먼저 감염시킨 봇들을 통제하기 위한 C2 서버를 구축한다.
- 공격자는 악성 웹사이트, 스팸 메일, 취약한 IoT 기기 등을 통해 다수의 PC나 디바이스를 감염시켜 봇으로 만든다.
- 봇은 감염 이후 스스로 C2 서버에 접속해 봇넷의 일원이 된다.
- 공격자는 C2 서버로 공격 명령을 전달하면 봇넷을 통해 다른 봇들에게 전파된다. 
- 봇은 명령을 따라 공격을 수행하며 필요시 다른 PC나 디바이스로 봇의 전파도 시도한다.

### (2) 봇넷의 구조 및 제어 방식
- 봇넷은 사용하는 프로토콜에 따라 IRC, HTTP, P2P 등으로 분류된다.
- 네트워크의 구조에 따라서 중앙집중형(IRC, HTTP), 분산형(P2P)으로 구분한다.
- **중앙집중형**
	- 초기에는 단순한 Internet Relay Chat 기반인 IRC 기반 구조가 주를 이루었으나 이후 탐지, 차단을 어렵게 하기 위해 HTTP 기반 C2로 진화하였다.
	- 여러 도메인을 확보하여 C2 서버로 운영하고 다수의 좀비 피씨는 이에 연결되어 명령을 수행한다.
	- 구조가 단순하지만 C2 서버가 차단되면 봇넷이 마비될 위험이 있다.
	- IRC 봇넷인 Rbot, HTTP 봇넷인 Robax가 이에 해당한다.
- **분산형**
	- C2 서버가 존재하지 않고 봇들이 서로 공격자의 명령을 전파한다.
	- 탐지 및 차단이 매우 어려워짐. 
	- P2P 봇넷인 Storm, Peacomm 등이 이에 해당한다.

#### 3) DNS 싱크홀 서비스
- 감염된 피씨가 C2 서버로 접속을 시도할 때 싱크홀 서버로 연결시켜 공격자의 명령을 받지 못하도록 하는 서비스.
- 감염된 피씨가 싱크홀 서비스가 적용된 DNS 서버에 C2 서버의 도메인에 대한 질의를 수행하면 싱크홀 서버 IP 주소를 응답으로 주는 식으로 서비스된다.
- 공격자의 명령 전달도 차단하고 추후 감염 분석, 대응도 가능해진다.
- 싱크홀이 적용된 DNS 서버는 알려진 C2 서버 도메인을 KISA 배포받고 해당 목록을 주기적으로 업데이트 해야 한다.

### (3) 디도스 공격 유형 분류
#### 1) 개요
- 네트워크 대역폭 소진 공격, 시스템 자원 소진 공격, 웹/DB 서버 부하 공격. 주로 3가지로 나뉜다.
- 웹/DB 서버 부하 공격의 경우 고대역폭, 저대역폭으로 다시 나뉨.

#### 2) 네트워크 대역폭 소진 공격
- 대량의 트래픽을 발생시켜 대상 시스템이 사용하는 네트워크 대역폭을 소진시키는 형태의 공격.
- 역추적을 어렵게 하기 위해 출발지 IP 주소를 위조하는 스푸핑 후 공격하는 것이 일반적이다.
- 주요 공격 기법으로 UDP 플러딩, ICMP 플러딩, UDP DRDoS가 있다.
- 공격 대상 시스템이 연결된 네트워크 회선, 또는 동일 네트워크 대역을 공유하는 모든 시스템에 접속 장애가 일어난다.

#### 3) 시스템 자원 소진 공격
- CPU, 메모리, 스토리지, 네트워크 연결 등 다양한 시스템 자원을 소진시키는 공격이다.
- 얘도 아이피 스푸핑을 위조하여 공격하는게 일반적.
- 주요 공격 기법으로 TCP SYN/ACK 플러딩이 있다.
- 공격 대상 서버, 네트워크 장비 등의 과부하로 인해 접속 장애가 발생한다.

#### 4) 웹/DB 서버 부하 공격
- **고대역폭 기반 공격**
	- 다수의 TCP 연결을 설정한 후 대량의 HTTP 요청 트래픽을 발생시켜 웹/DB 서버에 과부하를 유발하는 공격.
	- 연결 설정을 해야 하기 때문에 스푸핑이 불가능하다.
	- HTTP GET/POST 플러딩이 이에 해당한다.
- **저대역폭 기반 공격**
	- 웹 서버의 TCP 연결 자원을 장시간 점유하여 소진시키는 방식이다.
	- 소량의 HTTP 요청 트래픽만 발생시키면서 점유함.
	- 얘도 TCP 연결이 필수이므로 스푸핑 불가.
	- Slow HTTP Header(Slowloris), Slow HTTP Post(RUDY), Slow HTTP Read 공격이 해당한다.

### (4) 네트워크 대역폭 소진 공격
#### 1) UDP/ICMP 플러딩 공격
- 둘 다 UDP/ICMP 패킷을 대상 시스템에 전송하여 네트워크 대역폭을 소진시키는 공격이다.
- 와이어샤크를 보면 Time 필드의 시간 간격이 좁고 출발지가 다수의 봇으로 이루어져있는걸 확인해야 한다.
- 대응책으로는 네트워크 보안 장비에 임계치 기반 차단 정책을 적용한다. 출발지 아이피 별 시간 당 UDP/ICMP 패킷 수에 대한 임계치를 설정하고 이를 초과하는 경우 비정상으로 판단하여 차단한다.
- 근데 해당 공격은 출발지 주소를 무작위로 위조하기 때문에 효과가 제한적일 수 있으므로 목적지를 기준으로 임계치를 설정하여 과도하게 유입되는 트래픽을 폐기하거나 속도를 제한하는 방식의 정책을 적용할 수 있다.

### (5) 시스템 자원 소진 공격
#### 1) TCP SYN Flooding 공격
- 출발지가 위조된 다수의 SYN 패킷을 대상 시스템에 전송하여 TCP 연결 자원을 모두 소진시키는 서비스 거부 공격.
- 공격자가 의도적으로 TCP 연결 설정을 완료하지 않아 다수의 Half Open 연결 상태를 발생시켜 Backlog Queue를 소모하게 만드는 공격. 이를 위해 공격자는 출발지 아이피 위조, 서버 응답 SYN/ACK에 대한 ACK 응답이 이루어지지 않도록 함.
- TCP 연결 과정인 3-way handshake의 구조적 취약점을 이용한 공격임. 연결 과정에서 클라이언트를 인증하지 않는 취약점을 이용하여 출발지가 위조된 SYN 패킷을 보낼 수 있음.
- **대응책**
	- **TCP SYN Cookie 기능 활성화**
		- 클라이언트의 유효성을 검증하기 위한 기술로 정상 클라이언트로 확인될 때까지 서버의 Backlog Queue에 연결 요청 정보를 저장하지 않는다.
		- `sysctl -w net.ipv4.tcp_syncookies=1`로 설정한다.
	- **임계치 기반 차단 정책 적용**
		- 출발지 또는 목적지 IP별 단위 시간당 SYN 패킷 발생량을 기준으로 임계치를 설정하고 이를 초과하는 SYN 트래픽을 탐지하면 차단하도록 정책을 적용한다.
		- 이건 iptables로 하면 된다.
			- limit 모듈을 사용하여 초당 10개의 요청만 허용하기
			- `iptables -A INPUT -p tcp --syn --dport 443 -m limit --limit 10/s -j ACCEPT`
			- `iptables -A INPUT -p tcp --syn --dport -j DROP`
	- **First SYN Drop 기능 활성화** 
		- 출발지 별로 초로 수신되는 SYN 패킷을 의도적으로 폐기하고 동일 출발지에서 재전송 될 경우 이를 정상 요청으로 판단하여 허용하는 방식의 기법.
		- 만약 정상 클라이언트라면 SYN/ACK 응답이 도착하지 않았을 경우 네트워크 오류로 판단하여 SYN 패킷을 재전송한다. 반면 다수의 공격 도구는 조작된 SYN 패킷만 대량으로 전송하고 재전송을 수행하지 않는 경우가 많아 SYN Flooding 공격에 효과적으로 대응할 수 있음.
	- **Backlog Queue 확장**
		- 임시적인 대응책이다. 
		- `sysctl -w net.ipv4.tcp_max_syn_backlog=1024`

### (6) 웹/DB 서버 부하 공격 : 고대역폭 공격
#### 1) HTTP GET Flooding 공격
- 동일한 동적 컨텐츠(URL)에 대한 HTTP GET 요청을 대량으로 발생시켜 대상 웹 서버가 이를 처리하기 위한 CPU, 메모리, 프로세스/스레드, DB Query 등의 자원을 과도하게 사용하도록 유도하고 그 결과 정상 요청을 처리하지 못하게 만드는 서비스 거부 공격.
- 실제 HTTP 요청을 전달해야 하므로 스푸핑이 불가능하다. 정상적인 TCP 3-way handshake를 완료한 후 특정 동적 자원에 대한 GET 요청을 대량으로 전송한다.
- 요청을 처리하기 위해 CPU, 메모리, 프로세스, DB Query 등 자원을 과도하게 소비하여 정상 사용자가 웹 서비스에 접속할 수 없게 된다.
- 대충 시간 간격 좁은데 Info에 GET으로 도배되어 있으면 GET Flooding임
- **대응책**
	- **임계치 기반 차단 정책 적용**
		- 얘는 스푸핑이 안되니까 임계치 차단 정책이 효과적으로 작동함.
	- **HTTP 쿠키 기반 검증 적용**
		- 다수의 공격 도구에는 HTTP 쿠키 저장 및 재전송 기능이 없는걸 이용함.
		- 응용계층의 보안장비를 이용하여 클라이언트의 첫 요청에 검증용 HTTP 쿠키를 설정해 응답하고 이후 요청에서 동일 쿠키를 포함하지 않을 경우 비정상 사용자로 판단하여 차단함.
- 웹 서버의 access 로그를 분석하여 GET 방식의 특정 파일을 요청한 클라이언트의 아이피와 요청 건수를 파악한다. (access_log)
	- 나오면 KCA 욕하고 자살함
- **ngrep 도구를 이용한 패킷 분석**
	- 나오면 KCA 욕하고 자살함

### (7) 웹 서버 부하 공격 : 저대역폭 공격
#### 1) Slow HTTP Header 공격(Slowloris 공격)
- 다수의 HTTP 요청을 전송하면서도 요청 헤더의 끝을 의미하는 CR LF를 연속 2번 보내지 않고 의미 없는 헤더만 매우 느린 속도로 지속적으로 연결하여 웹 서버와의 연결을 장시간 유지시키는 공격.
- 요청 헤더의 끝은 CR(캐리지 리턴)과 LF(라인 피드) 2개로 구분된다.
- 그래서 의미 없는 헤더만 계속 매우 느린 속도로 전송하여 연결을 유지함. 웹 서버는 요청 헤더 수신이 완료될 때까지 연결을 유지한 채 대기하게 된다.

#### 2) Slow HTTP Post 공격(RUDY 공격)
- **(가) 개요**
	- 얘는 다수의 POST 요청을 전송하면서 Content-Length 헤더 값을 실제 데이터보다 매우 크게 설정한 후 매우 작은 데이터를 천천히 지속적으로 전송하여 웹 서버와 연결을 장시간 유지시키는 공격.
- **(나) 공격 원리**
	- POST를 사용할 때 전송 데이터 유형과 크기 정보를 전달하기 위해 Content-Type과 Content-Length 헤더를 사용함.
	- 타입을 통해 유형을 파악하고 Length를 통해 데이터의 길이를 확인하여 길이만큼 데이터를 읽어들이는 작업을 수행한다.
	- 큰 크기로 설정하고 매우 소량의 데이터를 지속적으로 천천히 보내면 전부 다 받을대까지 연결을 유지한채 대기함. 그러면 동시 연결 자원 소진으로 더는 정상적 요청을 처리할 수 없는 상태가 된다.

#### 3) Slow HTTP Read 공격
- 다수의 HTTP 요청에 대한 웹 서버 응답 과정에서 클라이언트가 TCP 윈도우 크기를 0으로 설정한 Zero Window 패킷을 지속적으로 전송하여 HTTP 응답 데이터의 수신을 지연시키는 공격.
- 자신이 더 이상 수신할 공간이 없다고 조작된 Window size를 가지는 패킷을 전송하여 웹 서버가 응답 메시지를 전송하지 못하게 막으며 연결을 유지한다.
- Zero Window를 통보하여 서버 연결 자원을 고갈시킨다...

#### 4) Slow 계열 공격 대응책
- **(가) 3가지 Slow 계열 공격에 모두 적용되는 대응책**
	- **동시 연결 수에 대한 임계치 설정을 통한 차단**
		- Slow 공격 계열은 동일 클라이언트에서 대상 시스템과 다수의 TCP 연결을 설정한 후 장시간 연결하는 특징이 있음.
		- 출발지 IP별 동시 연결 수에 대한 임계치를 설정하고 초과하는 경우 비정상 트래픽으판단하여 출발지를 차단하도록 정책.
		- iptables를 이용하면 된다.
			- `iptables -A INPUT -tcp --syn --dport 443 -m connlimit --connlimit-above 30 -j DROP`
	- **연결 타임아웃 설정을 통한 차단**
		- 아무런 데이터 송수신 없이 연결을 유지할 수 있는 시간에 대해 연결 타임아웃을 설정하고, 이를 초과할 경우 TCP 연결을 종료하도록.
		- 아파치 컨픽인 httpd.conf에 `Timeout 5`처럼 추가한다. 5초동안 아무런 데이터 송수신이 없으면 연결을 종료한다.
		- 하지만 공격자가 데이터 송수신 주기를 짧게 조정하면 막기 힘들고 타임아웃 값을 너무 짧게 설정하면 정상적인 서비스에도 영향을 미치기 때문에 적절한 설정이 필요함.
- **(나) Slow HTTP Reader와 slow HTTP POST 공격 대책**
	- 읽기 타임아웃 설정을 통한 차단
	- HTTP Header는 헤더를 느리게, POST는 요청 메시지 바디를 느리게 전송한다.
	- 요청 헤더 또는 요청 메시지 바디를 모두 수신할 때까지 허용되는 시간에 대해 읽기 타임아웃을 설정하고 이를 초과할 경우 연결을 종료하도록 한다.
	```
	<IfModule reqtimeout_module>
		RequestRealTimeout header=5 body=10
	</IfModule>
	```
	- httpd.conf를 수정하면 된다.
	- header값은 header 공격 방어, body는 post 공격 방어.

## 14. DRDoS(Distributed Reflection DoS) 공격
### (1) 개요
- 출발지 아이피 주소를 공격 대상의 아이피 주소로 위조하여 대수의 증폭/반사 서버로 서비스 요청하여 증폭된 대량의 응답 트래픽을 수신하도록 만드는 서비스 거부 공격 유형이다.
- 특징으로는 증폭/반사서버에 작은 서비스 요청을 할 때 크기가 큰 응답을 주도록 하여 공격 대상 시스템에게 이를 응답하게 하는 방식. 
- TCP/UDP/ICMP 기반이 있다.
	- TCP는 TCP SYN 방식을 쓸 수 있다.
	- UDP도 비슷. 
	- ICMP는 스머프 공격이 대표적.
- 실제로는 UDP 기반 DRDoS 공격이 많이 쓰임. DNS, NTP, SNMP 등의 서비스를 이용한다.
- 공격은 크게 증폭, 반사 형태로 나뉨.
- UDP를 사용하는 이유는 비연결형 프로토콜이므로 출발지 위조가 수월하고 요청 응답 대비 증폭을 크게 얻을 수 있어 주로 활용된다.

### (2) UDP 기반 DRDoS 유형
#### 1) DNS 증폭 DRDoS 공격
- 53번 UDP/TCP를 사용한다.
- 취약한 공개 DNS 서버에 큰 응답 데이터를 요청하는 ANY나 TXT 타입의 DNS 질의를 공격 대상 아이피로 스푸핑하여 위조하고 전송한다.
- ANY 타입 질의는 도메인에 대한 모든 리소스 레코드 정보를 요청하는 타입.
- TXT 타입 질의는 도메인에 대한 텍스트 정보를 저장하고 있는 TXT 리소스 레코드에 대한 질의 타입. 
- 위 요청은 둘 다 요청 대비 응답이 크다.

#### 2) NTP 증폭
- NTP는 네트워크상에 연결된 장비들의 시간을 동기화하기 위한 서비스 프로토콜. 
- 123/UDP를 사용한다.
- 상대적으로 큰 응답을 요청하는 monlist 명령을 사용한다. 최근 NTP 서버에 접속한 클라이언트 목록을 요청하는 명령이다.

#### 3) 그 외 증폭 공격들
- **SNMP 증폭**
	- 네트워크에 연결된 장치의 상태 정보를 관리하는 서비스 프로토콜. 
	- 161/UDP
	- 큰 응답 데이터를 요청하는 GetBulkRequest 메시지를 주로 사용함. 
		- 해당 요청은 장치의 다양한 상태 정보를 한번의 요청으로 대량 조회하는 메시지.
- **SSDP 증폭**
	- 네트워크상의 서비스나 정보를 검색하는 프로토콜. 프린터, 스캐너, IP 카메라 등 다양한 IoT 기기의 정보 검색 용도로 사용된다. 
	- 1900/UDP
	- 취약한 공개 IoT에 큰 응답 데이터를 요청...
- **Memcached 증폭**
	- 11211/UDP or TCP
	- 데이터베이스의 부하를 줄이기 위해 데이터를 메모리에 캐싱하여 응답 속도를 높이는 분산 메모리 캐싱 서비스 프로토콜.
	- 이론상 최대 5만배의 응답 패킷이 전달되도록 함.
- **CLDAP 증폭**
	- 네트워크상에서 디렉터리 정보를 조회하기 위한 서비스. 기업 내 자원 식별 및 인증 정보를 관리하는 LDAP의 비연결형 버전.
	- 389/UDP

### (3) DNS 증폭 DRDoS 공격
- ANY, TXT 레코드를 주로 이용함.
- **대응책**
	- **DNS 질의(재귀적 질의) 제한**
		- 주로 공개된 Recursive/Cache DNS 서버를 대상으로 ANY 또는 TXT 타입의 재귀적 질의를 수행하는 방식으로 이루어짐.
		- Authoritative DNS 서버의 경우 재귀적 질의가 불필요하므로 이를 허용하지 않도록 함.
		- 내부 사용자 전용 재귀/캐시 DNS 서버는 내부 사용자를 대상으로만 재귀적 질의를 허용한다.
	- **임계치 기반 차단 정책 적용**
		- ANY, TXT DNS 건수에 대한 임계치를 설정하여 이를 초과하는 경우 비정상 트래픽으로 판단하여 차단시킴.
		- 근데 문제는 아이피가 스푸핑되었으므로 희생자의 주소를 차단할 수도 있다.

### (4) 일반적인 DDoS, DRDoS 공격 비교
- DDoS는 공격자가 직접 봇을 사용하여 명령을 내려 공격한다. 하지만 DRDoS는 출발지 아이피 스푸핑 후 요청에 대한 응답으로 공격한다.
- DDoS는 출발지 스푸핑이 필수가 아니지만 DRDoS는 필수이다. 스머프 형태니까.
- 근원지 추적에 있어 DRDoS는 여러 증폭/반사 서버를 경유하기 때문에 어렵다.
- DDoS는 직접 공격자가 희생자에게 공격을 가하지만 DRDoS는 증폭/반사 서버를 한번 경유하여 희생자에게 공격이 가해진다.
- DDoS의 공격 트래픽의 크기는 공격자가 설정한 크기에 비례하지만 DRDoS는 요청에 비해 응답의 크기가 증폭되어 매우 크다.

### (5) IP 스푸핑 공격 대응을 위한 패킷 필터링 방법
#### 1) 개요
- 라우터에 있는 Ingress, Egress, Unicast RPF 기법을 사용한다.

#### 2) Ingress 기법
- 내외부 경계 라우터에서 안으로 들어오는. 즉 외부에서 내부로 유입되는 패킷에 대해 출발지 주소를 검사한다.
- 신뢰할 수 없는 아이피 주소를 가진 패킷을 차단.
	- 내부망 IP 주소
	- 사설 아이피 주소.
	- 호스트에게 할당이 불가능한 아이피(루프백, 멀티캐스트, 브로드캐스트, 기본 경로 주소 등)

#### 3) Egress 기법
- 내부에서 외부로 나가는 패킷에 대해 출발지 아이피 주소를 검사하여 신뢰할 수 없는 아이피인지 확인한다.
	- 내부에서 사용하지 않는 주소
	- 공인 IP로 변환되지 않은(NAT) 사설 아이피 주소
	- 할당 불가 주소

#### 4) Unicast RPF(Reverse Path Forwarding)
- 외부에서 내부로 유입되는 패킷에 대해 라우팅 테이블에 역경로가 존재하는지 검사하여 존재하지 않거나 비정상 인터페이스로 유입되는 패킷을 차단함.
	- 역경로란 유입된 패킷의 출발지 주소를 역으로 목적지로 간주했을 때 해당 주소로 패킷을 보낼 수 있는 라우팅 경로가 존재하는지, 도는 유입된 인터페이스로 다시 전송 가능한지를 확인하는 것.
- 역경로가 없거나 실제 경로와 패킷이 유입된 인터페이스가 일치하지 않으면 차단됨.
