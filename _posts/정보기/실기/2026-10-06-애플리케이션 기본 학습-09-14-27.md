## 1. DNS(Domain Name System)
### (1) DNS 구조
- 사용자 호스트는 DNS 서버에 질의를 하기 전, 로컬 DNS 캐시와 hosts 파일을 검색한다. 만약 여기에도 정보가 없다면 DNS 서버에 질의를 한다. `www.algisa.com`에 접속하는 과정은 아래와 같다.
	- 사용자가 Recursive DNS 서버에 질의한다.
	- Recursive 서버에도 자신의 캐시에 해당 도메인이 없기 때문에 도메인 체계의 가장 최상위인 root DNS에 질의를 한다.
	- root DNS는 해당 도메인의 최종 IP는 모르지만 `.com`을 관리하는 도메인 서버를 알고 있어서 `<com DNS>` 를 Recursive DNS에게 알려준다. 그러면 Recursive DNS 서버는 다시 com DNS 서버에 질의를 하게 된다.
	- com DNS 서버 역시 최종 IP는 모르지만 `algisa.com` 도메인을 담당하는 서버를 알고 있어서 `<algisa.com DNS>` 를 응답한다. 그럼 그 정보를 바탕으로 다시 algisa.com DNS 서버에 질의를 한다.
	- 이번에 질의를 한 algisa.com DNS 서버는 실제 아이피 주소를 관리하고 있는 서버이기 때문에 Recursive DNS 서버에게 정확한 아이피를 응답해준다.

#### 1) 용어정리
- **Recursive/Cache 네임서버/DNS서버**
	- 관리하거나 위임받은 도메인이 없다. 호스트로부터 질의가 들어오면 캐시에 저장된 정보나 반복적 질의를 통해 결과를 사용자 호스트에게 응답해 주는 네임서버다.
	- ISP 업체가 제공 해주는 DNS 서버가 해당한다.
- **Authoritative 네임서버/DNS서버**
	- 특정 도메인에 대한 정보를 관리하면서 해당 도메인에 대한 질의에만 응답해 주는 네임서버.
	- 네임서버가 관리하는 도메인 영역을 Zone/존이라고 하고 관리 도메인에 대한 정보를 담고 있는 파일은 Zone File/존 파일이라고 한다.
	- 네임서버는 존 파일을 읽어 존 데이터를 구성하고 이를 이용하여 질의에 응답한다.
	- 각 회사별로 자신의 도메인을 관리하는 DNS 서버가 해당한다.
- **재귀적 질의(Recursive Query)**
	- 사용자 호스트가 Recursive 네임서버로 질의할 떄 사용하는 방식. 대상 도메인의 리소스 레코드 정보를 조회해서 응답해달라는 질의를 의미함.
	- 그럼 네임서버는 자신의 캐시 데이터를 조회한 후 있으면 그 데이터를 반환하고, 없으면 최상위 Root 네임서버부터 질의 대상 도메인 네임서버까지 반복적 질의를 수행한 후 그 결과를 호스트에게 반환.
- **반복적 질의(Iterative Query)**
	- Recursive 네임서버가 도메인을 관리하는 각 네임서버로 질의할 때 사용하는 방식. 
	- 최상의 루트 네임서버부터 계층구조에 따라 대상 도메인 네임서버까지 각 네임서버가 응답하는 위임된 네임서버 정보에 따라 순차적으로 반복하여 진행하는 질의를 의미.

#### 2) 동작방식 잡것
- **윈도우**
	- 윈도우의 경우 로컬 DNS 캐시, hosts.ics, hosts 파일 순으로 검색하고 없으면 시스템에 설정된 네임서버로 요청한다. 중요한 점은 hosts 파일보다 DNS 질의에 대한 검색 우선순위가 높으므로 질의 시 먼저 참조되는 특성이 있음. 악성코드에 의해 조작된 hosts.ics 파일을 생성하여 파밍 사이트로 접속을 유도하는 보안 사고가 발생한 사례가 있으니 주의해야 한다.
- **리눅스/유닉스**
	- /etc/resolv.conf 파일은 시스템 기본 네임서버 설정 정보를 담고 있음. 내 호스팅 서버의 경우 아래와 같다.
		- `nameserver 127.0.0.53`은 리눅스 운영체제 내부의 로컬 DNS 캐시 데몬인 systemd-resolved를 일차적으로 바라보고 있다는 뜻.
		- `search vcn09260939.oraclevcn.com`은 `ping db-server`처럼 짧은 호스트 이름만 질의하면 운영체제는 자동으로 해당 주소를 붙여서 `db-server.vcn09260939.oraclevcn.com`으로 변환하여 질의한다. 오라클 클라우드 내부망에 있는 다른 인스턴스와 통신하기 편하도록 세팅된 것.
		- `options edns0 trust-ad`는 아래와 같다.
			- `edns0` : DNS 기본 UDP 패킷의 크기는 512바이트로 매우 작음. 이를 확장하여 더 큰 패킷을 주고 받을 수 있게 해주는 옵션. 주로 IPv6나 DNSSEC 암호화 키를 전송할 때 필요함.
			- `trust-ad` : DNS 응답이 중간에 위조되지 않았음을 검증하는 보안 기술인 DNSSEC와 관련된 설정. 응답 패킷 헤더에 있는 AD 플래그를 신뢰하겠다는 뜻. DNS Spoofing(캐시 포이즈닝)의 대표적인 방어 대책이 DNSSEC.
	```
	nameserver 127.0.0.53
	options edns0 trust-ad
	search vcn09260939.oraclevcn.com
	```
	- /etc/hosts 파일은 도메인/호스트명과 아이피 주소 매핑 정보를 담고 있는 파일. 네임서버에 질의하기 전 먼저 참조되는 파일. 파밍 등의 공격을 통해 파밍 사이트로 접속하도록 hosts 파일을 변조하는 사례가 많음. 
	- /etc/host.conf 파일은 DBS 질의 순서를 지정하는 파일로 order 절에 명시된 순서로 질의를 수행한다.
