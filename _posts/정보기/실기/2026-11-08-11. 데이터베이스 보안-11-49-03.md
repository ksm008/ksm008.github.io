## 1. 데이터베이스 보안 위협과 통제
### (1) 데이터베이스 보안 위협
- **(가) 집성**
	- 낮은 등급 보안 여러 개를 조합해서 높은 보안 등급의 정보를 알아내는 것.
	- 만들어진 정보의 보안 등급이 더 높을 경우 심각한 기밀 유출 문제 발생 가능.
- **(나) 추론**
	- 일반 사용자가 보안으로 분류되지 않은 정보를 가지고 기밀 정보를 유추해내는 것.
	- 주로 통계 정보로부터 발생하기 때문에 개개의 개체에 대한 정보를 추적하지 못하게 해야 함.

### (2) 데이터베이스 보안 통제(제어)
- **(가) 접근 통제(제어)**
	- 사용자가 가진 접근 권한 범위 내에서 데이터 접근을 허용하는 기술적인 방법.
	- 데이터베이스 관리자(DBA)는 사용자나 역할, 그룹별로 접근 통제 사항을 결정한다.
		- 접근 가능한 데이터
		- 데이터의 접근 수준
		- 데이터에 허용할 작업(읽기, 변경, 삽입, 추가 등)
- **(나) 추론 통제(제어**)
	- 추론 방지를 위한 방법은 다음과 같음.
		- 허용 가능한 질의 제한
		- 질의의 응답으로 제공되는 데이터를 한정
		- 데이터가 숫자인 경우 반올림하거나 일관성이 없는 질의 결과를 제공하기
- **(다) 흐름 통제(제어)**
	- 객체 간의 정보의 흐름을 조정하는 것을 말함.
	- A 테이블의 데이터가 B 테이블에 기록되면 A에서 B로 흐름이 발생했다는 것을 말함.
	- 높은 객체에서 낮은 객체로 정보 흐름을 제어해야함.

## 2. DBMS 보안 통제
### (1) SQL 분류
- **(가) DML**
	- 데이터 조작어. 원하는 데이터를 조작하는데 사용.
	- SELECT, UPDATE, DELETE, INSERT
- **(나) DDL**
	- 데이터 정의어. 객체를 생성하거나 사제.
	- CREATE, DROP, ALTER
- **(다) DCL**
	- 데이터 제어어. 권한을 부여하거나 제거.
	- GRANT, REVOKE
- **(라) TCL**
	- 트랜잭션 제어어.
	- COMMIT, ROLLBACK

### (2) 뷰 기반의 접근 통제
#### 1) 개요
- 뷰는 가상 테이블. 하나 이상의 기본 테이블에 의해 유도되어 만들어지는것.
- 실행간에 구체화 되는 특성이 있음.
- 뷰는 그 정의 자체를 권한 부여 기법으로 사용 가능함.
- 기본 테이블에 직접 접근하는 것을 차단하고 일부 데이터만 뷰로 제공하면 민감한 데이터 은닉이 가능함.

### (3) SQL 기반의 접근 통제 기법
#### 1) 개요
- 뷰는 데이터베이스 객체에 수행하는 작업(DDL, DML)에 대해 제한할 수 있는 방법은 아님.
- 이를 DCL 문을 사용해서 작업 권한을 제어 가능.

#### 2) GRANT 문을 이용한 사용자 권한 부여
- MySQL을 기준으로 함.
- `GRANT [권한] ON [데이터베이스 객체(테이블 등)] TO [사용자] [WITH GRANT OPTION]`
	- WITH GRANT OPTION : 사용자가 부여받은 권한을 다른 사용자에게 다시 부여할 수 있는 권한.
- 주요 권한 종류는 다음과 같다.
	- CREATE, ALTER, DROP
	- SELECT, INSERT, UPDATE, DELETE
	- ALL 
	- USAGE : 계정만 생성된 상태로 권한 없음
- **사용 예시**
	- `grant select on kiwi_99_db.member to algisa@localhost;`
	- `show grants for algisa@localhost;`
	- `grant select,update,insert,delete on kiwi_99_db.member to algisa@localhost with grant option;`

#### 2) REVOKE 문을 이용한 사용자 권한 해제
- `REVOKE [해제할 권한] ON [데이터베이스 객체] FROM [사용자]`
- `revoke select on kiwi_99_db.member from algisa@localhost`

## 3. 데이터베이스 암호화 기술
### (1) 개요
- 컬럼 암호화, 블록 암호화 2개로 나뉨.
	- 컬럼 암호화는 테이블의 컬럼 단위로 데이터를 암호화하여 저장하는 방식이다.
	- 블록 암호화는 DBMS 블록 또는 파일 블록 단위로 암호화하여 저장하는 방식임.
- 컬럼 암호화 방식은 암/복호화 모듈의 위치와 요청 위치의 조합에 따라...
	- API
	- Plug-In
	- Hybrid 방식 등이 있고...
- 블록 암호화 방식은
	- TDE
	- 파일 암호화 방식이 있다.

### (2) 컬럼 암호화 방식
#### 1) API 방식 : 응용 프로그램 자체 암호화 방식 
- 암/복호화 모듈이 API 라이브러리 형태로 각 애플리케이션 서버에 설치되어 응용 프로그램에서 해당 암/복호화 모듈을 호출하는 방식.
- 애플리케이션 서버와 DB 서버 간의 통신에서 암호화된 데이터 전송을 보장할 수 있음.
- DB 서버에 영향을 주지 않아 DB 서버의 성능 저하가 적은 편
- 구축 시 응용 프로그램 전체 또는 일부의 수정이 필요함.
- 기존 운영하는 프로그램 적용보다 차세대 시스템 개발 등 기존 애플리케이션에 대한 전면적인 수정이 가능한 경우 적용하면 효과적.

#### 2) 플러그인 방식 : DB서버 암호화 방식
- 암/복호화 모듈이 DB에 설치되고 DB 서버에서 플러그인으로 연결된 암/복호화 모듈을 호출하는 방식.
- 구축 시 응용 프로그램의 수정을 최소화 할 수 있으나 기존 DB 스키마와 대응하는 뷰를 생성하고 암호화할 테이블을 추가하는 등의 작업이 필요함.
- DB 서버에서 암/복호화 모듈을 플러그인으로 호출할 때 추가적인 부하가 발생하여 성능이 저하될 수 있으므로 트랜잭션 처리량이 많지 않아 성능에 대한 민감성이 낮은 시스템에 적용하기 적합한 방식.

#### 3) 하이브리드 방식 : API와 플러그인의 방식 혼용
- 대용량 트랜잭션 처리에는 플러그인 방식을, 성능 저하가 발생할 수 있는 부분은 API를 사용하여 성능을 보장하고, 나머지는 플러그인을 사용하여 애플리케이션의 수정을 최소한으로 하는 방식.

### (3) 블록 암호화 방식
#### 1) TDE(Transparent Data Encryption) : DBMS 자체 암호화 방식
- DBMS에 내장된 암호화 방식을 이용하여 DB 내부에서 데이터 파일 저장 시 암호화하고 파일에 저장된 내용을 메모리 영역으로 가져올 때 DBMS에 의해 자동으로 복호화되는 방식.
- 기존 응용 프로그램의 수정이나 DB 스키마의 수정이 거의 필요하지 않고 최적화된 성능을 제공할 수 있음.

#### 2) 파일 암호화 방식 : 운영체제 암호화 방식
- 운영체제에서 암호화하는 방식. 
- DB 파일 뿌만 아니라 로구, 이미지, 음성/영상 등 다양한 비정형 데이터도 암호화 적용이 가능함.
- 거의 모든 DBMS에 적용할 수 있다는 장점이 있지만 파일을 전체 암호화하는데 DB 서버에 추가적인 부하가 발생할 수 있음.

## 4. 데이터베이스 취약점 점검
### (1) 개요
- mysql은 설치 시 `mysql` 이라는 데이터베이스를 생성함. 주요 테이블은 다음과 같다.
	- user : 전체 데이터베이스에 적용되는 사용자 정보와 권한 정보를 가짐.
	- host : 호스트 전체에 대한 데이터베이스 접근 권한 정보
	- db : 각각의 데이터베이스에 대한 접근 권한 정보.
	- table_priv : 테이블에 대한 접근 권한 정보
	- columns_priv : 테이블의 컬럼에 대한 접근 권한 정보를 가짐.
