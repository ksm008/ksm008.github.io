## 1. 윈도우 기본 학습
### (1) 윈도우 인증과정
1. 사용자가 로그인 화면에서 아이디, 비번을 입력하면 Winlogon이 정보를 받아 LSA 서브 시스템 내부의 LSA 서버 서비스로 전달한다.
2. LSA 서버 서비스는 모든 계정의 로그인에 대한 검증을 총괄하고 시스템에 대한 자원 접근 권한을 확인하는 핵심 서비스다. 이 서비스는 로컬 로그인인지, 도메인 로그인인지를 구분하여 NTLM 또는 커버로스로 인증 요청을 넘긴다.
3. 만약 네트워크나 도메인 환경을 통한 인증이라면 Netlogon 서비스를 거쳐 도메인 컨트롤러와 통신하게 된다.
4. 로컬 인증의 경우 인증 프로토콜(NTLM)을 거친 요청이 SAM으로 전달된다. SAM은 사용자 및 그룹 계정의 암호화된 해시 정보를 관리하는 모듈로 내부 데이터베이스인 사용자 인증 정보에 저장된 값과 사용자가 입력한 정보를 대조해 일치 여부를 확인한다.
5. 인증이 성공하면 커널 모드 아래에 있는 SRM과 통신한다. SRM은 인증된 사용자에게 SID를 부여하고 해당 계정의 권한 정보가 담긴 접근 토큰을 생성한다. 이후 사용자가 파일이나 프로세스에 접근할 때 이 토큰을 기반으로 권한을 검사함.
6. 이 모든 로그인 인증 시도와 관련된 결과는 이벤트 로거로 전달되어 보안 로그 데이터 베이스에 기록된다. 이는 윈도우 이벤트 뷰어의 보안 탭에서 확인할 수 있다.

#### 1) 윈도우 인증 구성요소
- 주요 구성요소는 LSA, SAM, SRM으로 나뉜다.
- **LSA 서비스 기능**
	- 가장 대빵
	- 모든 계정의 로그인에 대한 검증 및 시스템 자원에 대한 접근 권한 검사.
	- 계정명과 SID를 매칭하며 SRM이 생성한 감사로그를 기록한다.
- **SAM 서비스 기능**
	- 사용자/그룹 계정 정보에 대한 데이터베이스를 관리한다.
	- 사용자 로그인 정보와 SAM 파일에 저장된 사용자 패스워드 정보를 비교하여 인증 여부를 결정
	- SAM 파일은 사용자, 그룹 계정 및 암호화된 패스워드 정보를 저장하는 데이터베이스.
	- 주로 윈도우 설치 디렉터리에 있다. `C:\Windows\System32\config\SAM`
- **SRM 서비스 기능**
	- 인증된 사용자에게 SID를 부여한다
	- SID를 기반으로 하여 디렉터리에 대한 접근을 허용할지 여부를 결정하고 이에 대한 감사 메시지를 생성.

#### 2) 로컬 인증
- 윈도우 로그인 창 - LSA 서브 시스템 - NTLM - SAM - 접근토큰을 Winlogon에게 전달

#### 3) 원격 도메인 인증
- 윈도우 로그인 창 - LSA 서브 시스템 - 커버로스 프로토콜을 이용해 도메인 컨트롤러에 인증을 요청 - 인증 정보 확인 - 접근 토큰 부여

#### 4) SAM 파일 접근통제 설정
- SAM 파일은 사용자와 그룹 계정의 패스워드를 관리하고 LSA를 통한 인증을 제공하는 중요한 파일이므로 적절한 접근통제가 필요하다.
- Administrator / System 그룹 외에는 파일에 대한 접근을 제한하고 권한을 제거함.

### (2) 윈도우 보안 식별자(SID:Security Identifier)
#### 1) 개요
- 윈도우의 각 사용자나 그룹에게 부여되는 고유 식별 번호이다.
- SAM 파일에 SID 정보가 저장되어 있다.
- 사용자가 로그인을 수행하면 생기는 접근 토큰에 로그인 사용자/그룹에 대한 SID 정보가 담겨있음.

#### 2) SID 구조
- 예시 : `S-1-5-21-4243233100-3174512425-4165118588-500`
- S-1 : 윈도우 시스템을 의미
- 5-21 : 시스템이 도메인 컨트롤러 이거나 단독 시스템임을 의미
- 4243233100-3174512425-4165118588 : 해당 시스템만의 고유한 식별자. 동일한 컴퓨터에서 다시 윈도우를 설치해도 동일한 값을 가지지 않음.
- 500 : 관리자 식별자. 501번은 게스트, 1000번 이상은 일반 사용자 식별자이다.
- 윈도우 관리명령 콘솔 WMIC에서 `useraccount list brief`로 볼 수 있다는데...안되네
- 자기 꺼 보는건 cmd에서 `whoami -user`

### (3) 윈도우 인증 구조
#### 1) 개요
- 윈도우는 Challenge & Response 방식을 사용함.
	- 사용자가 인증하고자 하는 윈도우 시스템에 인증 요청을 한다.
	- 인증 요청을 받은 서버는 Challenge 값을 생성하여 사용자에게 보낸다.
	- 사용자는 전달받은 Challenge 값과 자신의 패스워드 값을 이용해 Response 값을 생성하여 서버에 전달한다.
	- 서버는 사용자가 전달한 값을 확인하여 인증 성공 여부를 전달한다.

#### 2) 인증 암호 알고리즘
- LM(Lan Manager) 해시 : 윈도우 2000, XP의 기본 알고리즘으로 구조적으로 취약한 알고리즘. 윈도우 비스타 이후 버전부터 사용을 못함.
- NTLM 해시 : LM 해시에 MD4 해시가 추가된 형태이다.
- NTLMv2 해시 : 기존 인증과 전혀 다른 알고리즘. 현재까지 복잡도가 충분해 크래킹이 어려움.

#### 3) Lan Manager 인증 수준
- Lan Manager는 네트워크를 통한 파일 및 프린터 공유 등과 같은 작업 시 인증을 담당하는 서비스이다.

### (4) 패스워드 크래킹
- 사전공격(딕셔너리 어택), 무차별 공격(브루트 포스), 혼합 공격, 레인보우 테이블 공격 등이 있음.

## 2. UNIX/Linux 기본 학습
### (1) 시스템 기본
#### 1) 사용자 정보
- **(가) passwd 파일**
	- 사용자 계정 정보를 저장하는 파일. 콜론을 사용해 7개의 필드로 구분함.
	- `/etc/passwd`에 있음.
	- `사용자 계정명 : 사용자 패스워드 : 사용자 ID : 사용자 그룹 ID : 설명 : 홈 디렉터리 : 로그인 쉘`
	- 만약 암호화된 패스워드를 사용하면 사용자 패스워드 쪽이 x임.
	- 암호화된 패스워드는 shadow 파일을 따로 쓴다. 그룹은 gshadow로 따로 있음.
	- 사용자 ID 즉 UID는 사용자를 고유하게 식별하기 위해 사용함.
	- UID는 다른 사용자가 같은 값을 사용할 수 있음. 시스템은 계정명만 다른 같은 사용자로 인식하게 된다.
	- root 계정의 UID는 0 고정. 일반 사용자의 UID가 0이 되면 루트 권한을 가지게 됨.
	- 모든 사용자는 하나의 기본 그룹에 필수적으로 속한다.
		- `id` 명령을 통해 사용자 ID나 사용자 그룹 ID를 확인할 수 있다.
	- 로그인 셸의 경우 별도 실행파일을 설정하여 로그인 후 실행파일이 동작할 수도 있으니 주기적으로 점검해야한다.

#### 2) 그룹 정보
- **(가) group 파일**
	- `/etc/group`
	- root 그룹 역시 0으로 예약되어 있다.
- **(나) UID, GID 확인**
	- `id 아이디`하면 된다.
- **(다) 사용자 패스워드 변경**
	- `passwd 아이디`하면 된다.
	- 자기 자신 아이디만 변경 가능하며 루트는 전부 변경 가능하다.

#### 3) 입출력 재지정 기능
- 얘랑 파이프가 유닉스의 중요한 특성.
- 프로세스가 커널에 의해 생성되면 기본적인 입출력을 위한 3개의 파일(통신 채널)을 오픈한다.
	- **표준 입력(STDIN, FD:0)**
		- 키보드로부터 입력을 받기 위한 파일
	- **표준 출력(STDOUT, FD:1)**
		- 수행 중에 발생한 정상 메시지를 모니터(터미널 화면)으로 출력하기 위한 파일
	- **표준 에러(STDERR, FD:2)**
		- 수행 중에 발생한 에러 메시지를 모니터로 출력하기 위한 파일
- 입출력 재지정 기능은 프로세스의 표준 입출력/에러를 키보드나 모니터가 아닌 파일로 재지정하는 기능을 말함.
- 입력 재지정 : 표준 입력을 키보드가 아닌 파일에서 읽도록 하는 것.
- 출력 재지정 : 표준 출력이나 에러를 모니터가 아닌 파일로 저장하도록 재지정하는 것.
	- 출력 재지정의 경우 `>>` 이렇게 2개를 쓸 수 있는데, 2개를 쓰면 기존 파일에 추가해서 작성한다. `>` 이렇게 1개면 아예 결과를 덮어씀.

#### 4) 파이프 또는 파이프라인 기능
- 파이프는 프로세스 간 통신을 위한 기법 중 하나.
- 프로세스의 출력을 다른 프로세스의 입력으로 전달해주는 기능.
- 기호로 `|`를 사용.

#### 5) 특수 문자(메타 문자, Meta Character)
- 정의된 특별한 기능이 있는 문자들.

| 문자   | 사전 정의                   |
| ---- | ----------------------- |
| `~`  | 홈 디렉터리                  |
| `.`  | 현재 디렉터리                 |
| `..` | 상위 디렉터리                 |
| `#`  | 주석                      |
| `$`  | 셸 변수(`$셸변수명`)           |
| `&`  | 백 그라운드 모드로 실행. `명령어 &`  |
| `*`  | 임의의 0개 이상 문자 대체(와일드카드)  |
| `?`  | 임의의 1개 문자 대체(와일드카드)     |
| `;`  | 셸 명령 구분자(명령어를 순차적으로 실행) |
| `\|` | 파이프                     |
| `<`  | 입력 재지정                  |
| `>`  | 출력 재지정                  |

### (2) 파일시스템 응용
#### 1) 파일시스템 개요
- **(가) 개요**
	- 물리 저장장치에 파일을 생성, 저장, 관리하기 위한 논리 자료구조를 뜻함.
	- 물리 저장장치는 논리적인 파티션으로 나뉘고 파티션별로 고유한 파일 시스템을 생성함.
- **(나) 파일시스템 구성**
	- **부트 블록**
		- 운영체제를 부팅하거나 초기화하기 위한 부트스트랩 코드를 담고 있는 블록
	- **슈퍼 블록**
		- 파일시스템을 관리하기 위한 정보를 담고 있는 블록
	- **아이노드 목록**
		- 아이노드 숫자
		- 파일타입
		- 접근권한
		- 링크 카운트
		- 소유자
		- 소유그룹
		- 파일크기
		- MAC Time
			- 마지막 수정, 접근, 변경 시간을 뜻함.
			- 각각 mtime, atime, ctime.
		- 블록 인덱스
			- 데이터 블록에 저장된 파일 데이터에 대한 인덱스 위치 정보
		- 아이노드에는 파일명이 없다! 파일명은 디렉터리를 통해 관리된다.
		- 침해사고가 발생하면 시스템 파일에 대한 무결성 확인을 위해 타임라인 분석을 ㅎ는데, 이때 파일시스템에 있는 inode 구조체의 MAC Time을 점검한다.
		- 특정 파일의 아이노드 정보는 stat 명령을 통해 확인이 가능하다.
	- **데이터 블록**
		- 실제 파일의 내용이 저장되는 블록. 고정 크기 블록임.

#### 2) 파일시스템과 링크 파일
- **(가) 개요**
	- 하드. 심볼릭으로 나뉨.
	- 명령어는 `ln`. 기본은 하드 링크이다.
	- `-s` 옵션을 붙이면 심볼릭.
	- `ln [-s] 원본파일 생성할파일`
- **(나) 하드링크**
	- 기존 파일과 동일한 아이노드 숫자를 가지는 파일을 생성하여 접근함.
	- 아이노드 숫자는 파일시스템별로 고유한 값이기 때문에 동일 파일 시스템 내에서만 하드 링크가 가능하고 디렉터리는 하드 링크가 불가능.
	- 하드 링크가 생성되면 링크 카운트가 1 증가한다. 기본은 1이다.
	- 파일 삭제시 링크 카운트를 1 감소시키고 그 값이 0이 되면 해당 파일의 아이노드 정보와 데이터가 삭제됨. 만약 아이노드를 참조하는 파일이 있으면 삭제하지 않음.
- **(다) 심볼릭 링크**
	- 원본 파일에 대한 경로를 파일 내용으로 하는 새로운 파일을 생성하여 접근함.
	- 파일 경로를 기반으로 하기 때문에 파일 시스템에 제한이 없고 디렉터리도 가능함
	- 원본 파일이 삭제되거나 이동하면 경로가 바뀌어 심볼릭 링크는 링크가 끊어진다.
	- 한 파일에 대해 여러 심볼릭 링크를 생성하면 해당 아이노드는 전부 다르다. 같은 경로를 가리켜도 개별 파일로 취급.

#### 3) 디렉터리 관리
- **(가) 파일의 종류**
	- **일반 파일**
	- **디렉터리**
	- **특수 파일**
- **(나) 디렉터리 내용 출력(ls 명령어)**
	- 디렉터리와 파일 목록, 정보를 보여준다.
	- 디렉터리에는 파일명과 해당 파일들의 아이노드 넘버 정보만 가지고 있다.
	- **입력 문법**
		- `-l` : 자세하게 표시
		- `-a` : 디렉터리에 있는 모든 디렉터리/숨김 파일까지 전부 보여줌
		- `-R` : 하위 디렉터리에 있는 내용까지 보여줌
		- `-F` : 파일명 끝에 파일 종류를 기호로 보여준다. 디렉터리의 경우 `\.`, 실행파일일 경우 `*`
		- `-i` : 디렉터리/파일에 지정된 아이노드 넘버를 보여준다.
	- **파일 종류**
		- `-` : 일반 파일
		- d : 디렉터리
		- b : 블록 장치 파일
		- c : 문자 장치 파일
		- l : 심볼릭 링크 파일
		- p : 이름 있는 파이프
		- s : 유닉스 도메인 소켓
	- **접근권한**
		- 소유자, 소유그룹, 기타 사용자로 나뉨.
		- 아니 다 아는거잖아
	- 그 외는 아는거라 안적음 귀찮다

여기서부터는 아는건 대충 적음

- **(다) cd 나옴**
- **(라) mkdir**
	- `-p` 옵션으로 계층 구조를 갖는 디렉터리를 모두 생성함
	- `mkdir -p AA/BB/CC` 같이 씀
- **(마) rmdir**
	- `-p` 옵션으로 계층 구조 디렉터리 전부 삭제

#### 4) 파일 권한 관리
- **(가) chmod**
	- `-R` 옵션으로 하위 디렉터리 파일 권한까지 변경.
	- +로도 가능하고... =로도 가능하고... 숫자로도 가능하고...
- **(나) chown, chgrp**
	- -R : 하위 디렉터리/파일 소유자나 그룹 변경
	- -h : 심볼릭 링크 파일 자체의 소유자나 그룹을 변경
- **(다) umask**
	- 파일 디렉터리 생성시 접근권한 설정하는거
	- 파일은 기본 666, 디렉터리는 777에서 해당 값을 제거

#### 5) find
- `find [경로] [조건] [액션]`
- 경로는 절대/상대 둘 다 가능함.
- 검색 조건은 여러가지가 있음.
	- name : 메타문자 사용가능
	- type : f는 정규 파일, d는 디렉터리, l은 심볼릭 등 문자 사용 가능
	- user
	- group
	- `size [+-]num[단위]`
	- perm mode : 검색할 접근권한을 8진수로 지정
	- atime
	- ctime
	- mtime
	- exec
- 검색 조건은 하나 이상 명시가 가능하며 논리 연산도 가능.
	- -a, -o, ! / -and, -or, -not
- **예시**
	- `find . -type f -user root`
		- 조건 2갠데 논리연산 언급 안하면 기본은 and
	- `find . -type f \( -user root -o group dev \) -print`
		- 연산 결과를 하나의 단위로 평가하기 위해 소괄호를 사용함. 이때 소괄호 앞에 백슬래시를 써야 한다.
		- -print 옵션은 명시하지 않아도 화면 출력함. 그럼 왜 쓰는거임?;
	- `find . -name "*.dat" -user algisa -exec ls -al {} \;`
		- exec 명령을 통해 검색 결과 파일에 대한 추가 명령을 수행한다.
		- `{}`는 검색 결과 파일들을 `ls -al` 명령의 인수로 전달하기 위한 기호.
		- `\;`는 명령의 끝을 의미함.
	- `find / . \( -nouser -o -nogroup \) -exec ls -al {} \;`
	- `find . -type f -mtime -10 -exec ls -al {} \;`
		- `-mtime/atime/ctime [+-] n` 같은 방식으로 사용. 단위 n은 일이 기준.
		- 최상위 루트 티렉터리 이하 모든 정규 파일에 대하여 최근 10일 이내에 변경된(수정된, 새롭게 생성된) 파일을 검색한 후 `ls -al`  명령을 수행한 결과를 출력한다.
	- `find / -type f -mtime -10  > /tmp/result.out`
		- 결과를 /tmp/result.out에 저장.
	- `find . -type f -perm 600`
		- 권한 앞에 하이픈이 없으면 정확히 일치하는 파일, 있으면 해당 권한을 포함하는 파일을 찾는다.
	- `find . -type f -perm 2`
		- 숫자를 하나만 쓰면 기타 사용자, 2개 쓰면 소유그룹과 기타 사용자에 대해 검색한다.
	- `find / -type f -perm 2 -exec ls -al {} \;`
		- 최상위 루트 디렉터리 이하 모든 일반 파일에 대하여 소유자나 소유자 그룹에 속자히 않는 모든 사용자에게 쓰기 권한이 있는 파일을 검색한 후 결과 파일에 대해 각각 `ls -al` 명령을 수행한 결과를 출력함.
		- Others에게 쓰기가 허용된 파일은 위험하기 때문에 이를 확인하고 rm을 통해 삭제하거나 chmod로 권한을 제거한다.
	- `find . -type f -size 6M -exec ls -al \;`
		- `-size` 옵션은 +- 뒤에 단위를 작성하여 쓴다. 만약 +-가 없으면 정확히 일치하는걸 찾음.
		- 크기의 단위는 block (b, 기본값임), c(bytes), k, M, G (킬로, 메가, 기가 순서)

### (3) 프로세스 응용
#### 1) 프로세스 개요
- 프로세스가 생성되면 커널(운영체제)는 프로세스별로 관리정보를 담고 있는 PCB(Process Control Block)을 생성한다. 프로세스 제어 블록을 통해 관리되는 주요 정보는 아래와 같음.
	- PID, PPID
		- PID로 각 프로세스를 식별하며 PPID는 해당 프로세스의 부모 프로세스 PID다.
	- 프로그램 카운터, PC
		- Context change(문맥 교환) 발생 시 다음에 실행할 명령어의 위치값 저장
		- ==🔴문맥 교환(Context Change)==
			- CPU에서 실행 중인 프로세스가 새로운 프로세스로 교환될 때 현재 실행 중인 프로세스의 상태정보(PC 등 레지스터 정보)를 저장하고 새로운 프로세스의 상태 정보를 복원하는 과정을 말한다.
	- 레지스터 저장 영역
		- Context change(문맥 교환) 발생 시 현재 프로세스의 실행 상태정보(레지스터 정보) 저장
	- 프로세스 상태, Process State
		- 프로세스의 현재 상태, 즉 Ready, Running, Blocked 등을 저장.
	- 메모리 정보, Memory limits
		- 프로세스가 사용하는 메모리(세그먼트 또는 페이지 테이블) 정보
- 프로세스가 생성되면 프로세스 별로 오픈한 파일을 관리하기 위한 파일 디스크립터 테이블(FDT, File Descripter Table)이 생성됨.
	- 기본적으로 3개의 파일이 자동으로 오픈됨. STDIN, STDOUT, STDERR
	- 프로세스 내에서 오픈한 각 파일을 식별하기 위한 양의 정수값을 파일 디스크립터라고 함.
- **System Open-file table(시스템 오픈 파일 테이블)**
	- 커널이 시스템 내에서 여러 프로세스에 의해 오픈된 파일들을 관리하기 위한 자료구조. 
	- open_mode : 파일의 읽기, 쓰기 모드
	- offset : 파일 I/O를 수행하기 위한 현재 위치값
	- reference_count : 해당 파일의 참조 개수를 의미함. 파일 복제가 발생하게 되면 refernce_count가 증가한다.
- **Active vnode table**
	- inode 정보를 가지고 잇는 일종의 캐시 역할을 함. 다양한 파일시스템의 inode 정보를 관리하기 위한 중계자 역할.
