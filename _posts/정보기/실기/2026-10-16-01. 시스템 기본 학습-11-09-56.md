## 1. 윈도우 기본 학습
### (1) 윈도우 인증과정
1. 사용자가 로그인 화면에서 아이디, 비번을 입력하면 Winlogon이 정보를 받아 LSA 서브 시스템 내부의 LSA 서버 서비스로 전달한다.
2. LSA 서버 서비스는 모든 계정의 로그인에 대한 검증을 총괄하고 시스템에 대한 자원 접근 권한을 확인하는 핵심 서비스다. 이 서비스는 로컬 로그인인지, 도메인 로그인인지를 구분하여 NTLM 또는 커버로스로 인증 요청을 넘긴다.
3. 만약 네트워크나 도메인 환경을 통한 인증이라면 Netlogon 서비스를 거쳐 도메인 컨트롤러와 통신하게 된다.
4. 로컬 인증의 경우 인증 프로토콜(NTLM)을 거친 요청이 SAM으로 전달된다. SAM은 사용자 및 그룹 계정의 암호화된 해시 정보를 관리하는 모듈로 내부 데이터베이스인 사용자 인증 정보에 저장된 값과 사용자가 입력한 정보를 대조해 일치 여부를 확인한다.
5. 인증이 성공하면 커널 모드 아래에 있는 SRM과 통신한다. SRM은 인증된 사용자에게 SID를 부여하고 해당 계정의 권한 정보가 담긴 접근 토큰을 생성한다. 이후 사용자가 파일이나 프로세스에 접근할 때 이 토큰을 기반으로 권한을 검사함.
6. 이 모든 로그인 인증 시도와 관련된 결과는 이벤트 로거로 전달되어 보안 로그 데이터 베이스에 기록된다. 이는 윈도우 이벤트 뷰어의 보안 탭에서 확인할 수 있다.

#### 1) 윈도우 인증 구성요소
- 주요 구성요소는 LSA, SAM, SRM으로 나뉜다.
- **LSA 서비스 기능**
	- 가장 대빵
	- 모든 계정의 로그인에 대한 검증 및 시스템 자원에 대한 접근 권한 검사.
	- 계정명과 SID를 매칭하며 SRM이 생성한 감사로그를 기록한다.
- **SAM 서비스 기능**
	- 사용자/그룹 계정 정보에 대한 데이터베이스를 관리한다.
	- 사용자 로그인 정보와 SAM 파일에 저장된 사용자 패스워드 정보를 비교하여 인증 여부를 결정
	- SAM 파일은 사용자, 그룹 계정 및 암호화된 패스워드 정보를 저장하는 데이터베이스.
	- 주로 윈도우 설치 디렉터리에 있다. `C:\Windows\System32\config\SAM`
- **SRM 서비스 기능**
	- 인증된 사용자에게 SID를 부여한다
	- SID를 기반으로 하여 디렉터리에 대한 접근을 허용할지 여부를 결정하고 이에 대한 감사 메시지를 생성.

#### 2) 로컬 인증
- 윈도우 로그인 창 - LSA 서브 시스템 - NTLM - SAM - 접근토큰을 Winlogon에게 전달

#### 3) 원격 도메인 인증
- 윈도우 로그인 창 - LSA 서브 시스템 - 커버로스 프로토콜을 이용해 도메인 컨트롤러에 인증을 요청 - 인증 정보 확인 - 접근 토큰 부여

#### 4) SAM 파일 접근통제 설정
- SAM 파일은 사용자와 그룹 계정의 패스워드를 관리하고 LSA를 통한 인증을 제공하는 중요한 파일이므로 적절한 접근통제가 필요하다.
- Administrator / System 그룹 외에는 파일에 대한 접근을 제한하고 권한을 제거함.

### (2) 윈도우 보안 식별자(SID:Security Identifier)
#### 1) 개요
- 윈도우의 각 사용자나 그룹에게 부여되는 고유 식별 번호이다.
- SAM 파일에 SID 정보가 저장되어 있다.
- 사용자가 로그인을 수행하면 생기는 접근 토큰에 로그인 사용자/그룹에 대한 SID 정보가 담겨있음.

#### 2) SID 구조
- 예시 : `S-1-5-21-4243233100-3174512425-4165118588-500`
- S-1 : 윈도우 시스템을 의미
- 5-21 : 시스템이 도메인 컨트롤러 이거나 단독 시스템임을 의미
- 4243233100-3174512425-4165118588 : 해당 시스템만의 고유한 식별자. 동일한 컴퓨터에서 다시 윈도우를 설치해도 동일한 값을 가지지 않음.
- 500 : 관리자 식별자. 501번은 게스트, 1000번 이상은 일반 사용자 식별자이다.
- 윈도우 관리명령 콘솔 WMIC에서 `useraccount list brief`로 볼 수 있다는데...안되네
- 자기 꺼 보는건 cmd에서 `whoami -user`

### (3) 윈도우 인증 구조
#### 1) 개요
- 윈도우는 Challenge & Response 방식을 사용함.
	- 사용자가 인증하고자 하는 윈도우 시스템에 인증 요청을 한다.
	- 인증 요청을 받은 서버는 Challenge 값을 생성하여 사용자에게 보낸다.
	- 사용자는 전달받은 Challenge 값과 자신의 패스워드 값을 이용해 Response 값을 생성하여 서버에 전달한다.
	- 서버는 사용자가 전달한 값을 확인하여 인증 성공 여부를 전달한다.

#### 2) 인증 암호 알고리즘
- LM(Lan Manager) 해시 : 윈도우 2000, XP의 기본 알고리즘으로 구조적으로 취약한 알고리즘. 윈도우 비스타 이후 버전부터 사용을 못함.
- NTLM 해시 : LM 해시에 MD4 해시가 추가된 형태이다.
- NTLMv2 해시 : 기존 인증과 전혀 다른 알고리즘. 현재까지 복잡도가 충분해 크래킹이 어려움.

#### 3) Lan Manager 인증 수준
- Lan Manager는 네트워크를 통한 파일 및 프린터 공유 등과 같은 작업 시 인증을 담당하는 서비스이다.

### (4) 패스워드 크래킹
- 사전공격(딕셔너리 어택), 무차별 공격(브루트 포스), 혼합 공격, 레인보우 테이블 공격 등이 있음.

## 2. UNIX/Linux 기본 학습
### (1) 시스템 기본
#### 1) 사용자 정보
- **(가) passwd 파일**
	- 사용자 계정 정보를 저장하는 파일. 콜론을 사용해 7개의 필드로 구분함.
	- `/etc/passwd`에 있음.
	- `사용자 계정명 : 사용자 패스워드 : 사용자 ID : 사용자 그룹 ID : 설명 : 홈 디렉터리 : 로그인 쉘`
	- 만약 암호화된 패스워드를 사용하면 사용자 패스워드 쪽이 x임.
	- 암호화된 패스워드는 shadow 파일을 따로 쓴다. 그룹은 gshadow로 따로 있음.
	- 사용자 ID 즉 UID는 사용자를 고유하게 식별하기 위해 사용함.
	- UID는 다른 사용자가 같은 값을 사용할 수 있음. 시스템은 계정명만 다른 같은 사용자로 인식하게 된다.
	- root 계정의 UID는 0 고정. 일반 사용자의 UID가 0이 되면 루트 권한을 가지게 됨.
	- 모든 사용자는 하나의 기본 그룹에 필수적으로 속한다.
		- `id` 명령을 통해 사용자 ID나 사용자 그룹 ID를 확인할 수 있다.
	- 로그인 셸의 경우 별도 실행파일을 설정하여 로그인 후 실행파일이 동작할 수도 있으니 주기적으로 점검해야한다.

#### 2) 그룹 정보
- **(가) group 파일**
	- `/etc/group`
	- root 그룹 역시 0으로 예약되어 있다.
- **(나) UID, GID 확인**
	- `id 아이디`하면 된다.
- **(다) 사용자 패스워드 변경**
	- `passwd 아이디`하면 된다.
	- 자기 자신 아이디만 변경 가능하며 루트는 전부 변경 가능하다.

#### 3) 입출력 재지정 기능
- 얘랑 파이프가 유닉스의 중요한 특성.
- 프로세스가 커널에 의해 생성되면 기본적인 입출력을 위한 3개의 파일(통신 채널)을 오픈한다.
	- **표준 입력(STDIN, FD:0)**
		- 키보드로부터 입력을 받기 위한 파일
	- **표준 출력(STDOUT, FD:1)**
		- 수행 중에 발생한 정상 메시지를 모니터(터미널 화면)으로 출력하기 위한 파일
	- **표준 에러(STDERR, FD:2)**
		- 수행 중에 발생한 에러 메시지를 모니터로 출력하기 위한 파일
- 입출력 재지정 기능은 프로세스의 표준 입출력/에러를 키보드나 모니터가 아닌 파일로 재지정하는 기능을 말함.
- 입력 재지정 : 표준 입력을 키보드가 아닌 파일에서 읽도록 하는 것.
- 출력 재지정 : 표준 출력이나 에러를 모니터가 아닌 파일로 저장하도록 재지정하는 것.
	- 출력 재지정의 경우 `>>` 이렇게 2개를 쓸 수 있는데, 2개를 쓰면 기존 파일에 추가해서 작성한다. `>` 이렇게 1개면 아예 결과를 덮어씀.

#### 4) 파이프 또는 파이프라인 기능
- 파이프는 프로세스 간 통신을 위한 기법 중 하나.
- 프로세스의 출력을 다른 프로세스의 입력으로 전달해주는 기능.
- 기호로 `|`를 사용.

#### 5) 특수 문자(메타 문자, Meta Character)
- 정의된 특별한 기능이 있는 문자들.

| 문자   | 사전 정의                   |
| ---- | ----------------------- |
| `~`  | 홈 디렉터리                  |
| `.`  | 현재 디렉터리                 |
| `..` | 상위 디렉터리                 |
| `#`  | 주석                      |
| `$`  | 셸 변수(`$셸변수명`)           |
| `&`  | 백 그라운드 모드로 실행. `명령어 &`  |
| `*`  | 임의의 0개 이상 문자 대체(와일드카드)  |
| `?`  | 임의의 1개 문자 대체(와일드카드)     |
| `;`  | 셸 명령 구분자(명령어를 순차적으로 실행) |
| `\|` | 파이프                     |
| `<`  | 입력 재지정                  |
| `>`  | 출력 재지정                  |

### (2) 파일시스템 응용
#### 1) 파일시스템 개요
- **(가) 개요**
	- 물리 저장장치에 파일을 생성, 저장, 관리하기 위한 논리 자료구조를 뜻함.
	- 물리 저장장치는 논리적인 파티션으로 나뉘고 파티션별로 고유한 파일 시스템을 생성함.
- **(나) 파일시스템 구성**
	- **부트 블록**
		- 운영체제를 부팅하거나 초기화하기 위한 부트스트랩 코드를 담고 있는 블록
	- **슈퍼 블록**
		- 파일시스템을 관리하기 위한 정보를 담고 있는 블록
	- **아이노드 목록**
		- 아이노드 숫자
		- 파일타입
		- 접근권한
		- 링크 카운트
		- 소유자
		- 소유그룹
		- 파일크기
		- MAC Time
			- 마지막 수정, 접근, 변경 시간을 뜻함.
			- 각각 mtime, atime, ctime.
		- 블록 인덱스
			- 데이터 블록에 저장된 파일 데이터에 대한 인덱스 위치 정보
		- 아이노드에는 파일명이 없다! 파일명은 디렉터리를 통해 관리된다.
		- 침해사고가 발생하면 시스템 파일에 대한 무결성 확인을 위해 타임라인 분석을 ㅎ는데, 이때 파일시스템에 있는 inode 구조체의 MAC Time을 점검한다.
		- 특정 파일의 아이노드 정보는 stat 명령을 통해 확인이 가능하다.
	- **데이터 블록**
		- 실제 파일의 내용이 저장되는 블록. 고정 크기 블록임.

#### 2) 파일시스템과 링크 파일
- **(가) 개요**
	- 하드. 심볼릭으로 나뉨.
	- 명령어는 `ln`. 기본은 하드 링크이다.
	- `-s` 옵션을 붙이면 심볼릭.
	- `ln [-s] 원본파일 생성할파일`
- **(나) 하드링크**
	- 기존 파일과 동일한 아이노드 숫자를 가지는 파일을 생성하여 접근함.
	- 아이노드 숫자는 파일시스템별로 고유한 값이기 때문에 동일 파일 시스템 내에서만 하드 링크가 가능하고 디렉터리는 하드 링크가 불가능.
	- 하드 링크가 생성되면 링크 카운트가 1 증가한다. 기본은 1이다.
	- 파일 삭제시 링크 카운트를 1 감소시키고 그 값이 0이 되면 해당 파일의 아이노드 정보와 데이터가 삭제됨. 만약 아이노드를 참조하는 파일이 있으면 삭제하지 않음.
- **(다) 심볼릭 링크**
	- 원본 파일에 대한 경로를 파일 내용으로 하는 새로운 파일을 생성하여 접근함.
	- 파일 경로를 기반으로 하기 때문에 파일 시스템에 제한이 없고 디렉터리도 가능함
	- 원본 파일이 삭제되거나 이동하면 경로가 바뀌어 심볼릭 링크는 링크가 끊어진다.
	- 한 파일에 대해 여러 심볼릭 링크를 생성하면 해당 아이노드는 전부 다르다. 같은 경로를 가리켜도 개별 파일로 취급.

#### 3) 디렉터리 관리
- **(가) 파일의 종류**
	- **일반 파일**
	- **디렉터리**
	- **특수 파일**
- **(나) 디렉터리 내용 출력(ls 명령어)**
	- 디렉터리와 파일 목록, 정보를 보여준다.
	- 디렉터리에는 파일명과 해당 파일들의 아이노드 넘버 정보만 가지고 있다.
	- **입력 문법**
		- `-l` : 자세하게 표시
		- `-a` : 디렉터리에 있는 모든 디렉터리/숨김 파일까지 전부 보여줌
		- `-R` : 하위 디렉터리에 있는 내용까지 보여줌
		- `-F` : 파일명 끝에 파일 종류를 기호로 보여준다. 디렉터리의 경우 `\.`, 실행파일일 경우 `*`
		- `-i` : 디렉터리/파일에 지정된 아이노드 넘버를 보여준다.
	- **파일 종류**
		- `-` : 일반 파일
		- d : 디렉터리
		- b : 블록 장치 파일
		- c : 문자 장치 파일
		- l : 심볼릭 링크 파일
		- p : 이름 있는 파이프
		- s : 유닉스 도메인 소켓
	- **접근권한**
		- 소유자, 소유그룹, 기타 사용자로 나뉨.
		- 아니 다 아는거잖아
	- 그 외는 아는거라 안적음 귀찮다

여기서부터는 아는건 대충 적음

- **(다) cd 나옴**
- **(라) mkdir**
	- `-p` 옵션으로 계층 구조를 갖는 디렉터리를 모두 생성함
	- `mkdir -p AA/BB/CC` 같이 씀
- **(마) rmdir**
	- `-p` 옵션으로 계층 구조 디렉터리 전부 삭제

#### 4) 파일 권한 관리
- **(가) chmod**
	- `-R` 옵션으로 하위 디렉터리 파일 권한까지 변경.
	- +로도 가능하고... =로도 가능하고... 숫자로도 가능하고...
- **(나) chown, chgrp**
	- -R : 하위 디렉터리/파일 소유자나 그룹 변경
	- -h : 심볼릭 링크 파일 자체의 소유자나 그룹을 변경
- **(다) umask**
	- 파일 디렉터리 생성시 접근권한 설정하는거
	- 파일은 기본 666, 디렉터리는 777에서 해당 값을 제거

#### 5) find
- `find [경로] [조건] [액션]`
- 경로는 절대/상대 둘 다 가능함.
- 검색 조건은 여러가지가 있음.
	- name : 메타문자 사용가능
	- type : f는 정규 파일, d는 디렉터리, l은 심볼릭 등 문자 사용 가능
	- user
	- group
	- `size [+-]num[단위]`
	- perm mode : 검색할 접근권한을 8진수로 지정
	- atime
	- ctime
	- mtime
	- exec
- 검색 조건은 하나 이상 명시가 가능하며 논리 연산도 가능.
	- -a, -o, ! / -and, -or, -not
- **예시**
	- `find . -type f -user root`
		- 조건 2갠데 논리연산 언급 안하면 기본은 and
	- `find . -type f \( -user root -o group dev \) -print`
		- 연산 결과를 하나의 단위로 평가하기 위해 소괄호를 사용함. 이때 소괄호 앞에 백슬래시를 써야 한다.
		- -print 옵션은 명시하지 않아도 화면 출력함. 그럼 왜 쓰는거임?;
	- `find . -name "*.dat" -user algisa -exec ls -al {} \;`
		- exec 명령을 통해 검색 결과 파일에 대한 추가 명령을 수행한다.
		- `{}`는 검색 결과 파일들을 `ls -al` 명령의 인수로 전달하기 위한 기호.
		- `\;`는 명령의 끝을 의미함.
	- `find / . \( -nouser -o -nogroup \) -exec ls -al {} \;`
	- `find . -type f -mtime -10 -exec ls -al {} \;`
		- `-mtime/atime/ctime [+-] n` 같은 방식으로 사용. 단위 n은 일이 기준.
		- 최상위 루트 티렉터리 이하 모든 정규 파일에 대하여 최근 10일 이내에 변경된(수정된, 새롭게 생성된) 파일을 검색한 후 `ls -al`  명령을 수행한 결과를 출력한다.
	- `find / -type f -mtime -10  > /tmp/result.out`
		- 결과를 /tmp/result.out에 저장.
	- `find . -type f -perm 600`
		- 권한 앞에 하이픈이 없으면 정확히 일치하는 파일, 있으면 해당 권한을 포함하는 파일을 찾는다.
	- `find . -type f -perm 2`
		- 숫자를 하나만 쓰면 기타 사용자, 2개 쓰면 소유그룹과 기타 사용자에 대해 검색한다.
	- `find / -type f -perm 2 -exec ls -al {} \;`
		- 최상위 루트 디렉터리 이하 모든 일반 파일에 대하여 소유자나 소유자 그룹에 속자히 않는 모든 사용자에게 쓰기 권한이 있는 파일을 검색한 후 결과 파일에 대해 각각 `ls -al` 명령을 수행한 결과를 출력함.
		- Others에게 쓰기가 허용된 파일은 위험하기 때문에 이를 확인하고 rm을 통해 삭제하거나 chmod로 권한을 제거한다.
	- `find . -type f -size 6M -exec ls -al \;`
		- `-size` 옵션은 +- 뒤에 단위를 작성하여 쓴다. 만약 +-가 없으면 정확히 일치하는걸 찾음.
		- 크기의 단위는 block (b, 기본값임), c(bytes), k, M, G (킬로, 메가, 기가 순서)

### (3) 프로세스 응용
#### 1) 프로세스 개요
- **(가) 개요**
	- 프로세스가 생성되면 커널(운영체제)는 프로세스별로 관리정보를 담고 있는 PCB(Process Control Block)을 생성한다. 프로세스 제어 블록을 통해 관리되는 주요 정보는 아래와 같음.
		- PID, PPID
			- PID로 각 프로세스를 식별하며 PPID는 해당 프로세스의 부모 프로세스 PID다.
		- 프로그램 카운터, PC
			- Context change(문맥 교환) 발생 시 다음에 실행할 명령어의 위치값 저장
			- ==🔴문맥 교환(Context Change)==
				- CPU에서 실행 중인 프로세스가 새로운 프로세스로 교환될 때 현재 실행 중인 프로세스의 상태정보(PC 등 레지스터 정보)를 저장하고 새로운 프로세스의 상태 정보를 복원하는 과정을 말한다.
		- 레지스터 저장 영역
			- Context change(문맥 교환) 발생 시 현재 프로세스의 실행 상태정보(레지스터 정보) 저장
		- 프로세스 상태, Process State
			- 프로세스의 현재 상태, 즉 Ready, Running, Blocked 등을 저장.
		- 메모리 정보, Memory limits
			- 프로세스가 사용하는 메모리(세그먼트 또는 페이지 테이블) 정보
	- 프로세스가 생성되면 프로세스 별로 오픈한 파일을 관리하기 위한 파일 디스크립터 테이블(FDT, File Descripter Table)이 생성됨.
		- 기본적으로 3개의 파일이 자동으로 오픈됨. STDIN, STDOUT, STDERR
		- 프로세스 내에서 오픈한 각 파일을 식별하기 위한 양의 정수값을 파일 디스크립터라고 함.
	- **System Open-file table(시스템 오픈 파일 테이블)**
		- 커널이 시스템 내에서 여러 프로세스에 의해 오픈된 파일들을 관리하기 위한 자료구조. 
		- open_mode : 파일의 읽기, 쓰기 모드
		- offset : 파일 I/O를 수행하기 위한 현재 위치값
		- reference_count : 해당 파일의 참조 개수를 의미함. 파일 복제가 발생하게 되면 refernce_count가 증가한다.
	- **Active node table**
		- inode 정보를 가지고 잇는 일종의 캐시 역할을 함. 다양한 파일시스템의 inode 정보를 관리하기 위한 중계자 역할.
- **(나) 프로세스 기본 조건**
	- 시스템 부팅을 담당하는 boot 프로세스 (0번)을 제외한 모든 프로세스는 부모 프로세스를 가짐.
	- PID 1번인 init process가 기본 부모 프로세스.
	- **고아 프로세스**
		- 자식 프로세스가 살아있는 상태에서 부모 프로세스가 종료하게 되면 자식 프로세스는 고아 프로세스가 된다. 이 때 init process가 대리모 프로세스 역할을 한다.
	- **좀비 프로세스**
		- 원래는 자식 프로세스가 자신의 종료 상태정보를 부모에게 반환해야 정상적으로 소멸할 수 있음. 
		- 종료 상태정보는 자신의 PID, 종료 코드, CPU 사용 시간 등을 담고 있다. 하지만 커널 오류나 부모 프로세스의 자식 프로세스에 대한 처리 오류 등으로 소멸하지 않으면 좀비 프로세스가 됨.
		- 좀비 프로세스가 많아지면 더는 프로세스를 생성할 수 없기에 시스템 장애가 발생할 수 있음.
	- `ps -l`로 결과를 살펴보면 상태 정보가 Z인 애들은 좀비 프로세스이다. 명령어 이름 필드에 `<defunct>` 표시가 추가됨.
	- `ps -l` **명령으로 확인 가능한 주요 필드 정보들**
		- **F**
			- 프로세스 플래그 정보
			- 1 : fork()를 통해서 생성되었으며 exec() 되지 않음.
			- 4 : 슈퍼유저 권한을 통해 실행됨
		- **S**
			- 프로세스의 현재 상태 정보.
				- Z : Zombie
				- R : CPU 점유를 대기중이거나 실행중인 상태
				- S : 인터럽트가 가능한 Sleep 상태
				- D : 인터럽트가 불가능한 Sleep 상태
				- T : 정지된 상태(Stopped)
		- **PRI**
			- 프로세스의 우선순위. 낮을수록 순위가 높음.
		- **NI**
			- 우선순위 계산 시 사용하는 값. Nice Value
		- **ADDR**
			- 프로세스의 메모리 주소
		- **SZ**
			- 프로세스가 차지하는 크기
		- **WCHAN**
			- Sleep 상태의 프로세스가 기다리는 커널 함수명
	- 좀비프로세스는 kill 시그널을 통해서도 소멸하지 않음. 좀비 프로세스를 제거하려면 좀비 프로세스의 부모 프로세스를 종료시키거나 시스템을 재기동하여 커널 정보를 초기화해야 한다.
	- 모든 프로세스는 종료 후 일시적으로 좀비 상태를 거친 후 소멸한다. 유닉/리눅스 시스템의 모든 프로세스는 작업을 종료하면 커널을 통해 부모 프로세스에게 알림. 이때 부모 프로세스가 종료 사실을 확인할 때까지 자식 프로세스는 일시적으로 좀비상태가 되는데 이는 눈으로 식별 불가능할 정도로 순식간에 이루어진다. 따라서 지속적으로 좀비 상태가 나타난다면 대부분 부모 프로세스 오류로 시그널 처리가 이루어지지 않았거나 커널 오류 등으로 인한 비정상 상태일 확률이 높음.
- **(다) 프로그램 실행 과정**
	- **프로세스 생성과 동시에 프로세스 그룹도 생성된다.**
		- 프로세스 그룹은 커널이 터미널 제어권을 관리하기 위한 목적으로 사용하는 프로세스들의 집함. 셸에서 실행된 프로세스와 그 자식 프로세스들이 하나의 프로세스 그룹으로 관리됨.
		- 터미널 제어권이란 터미널로부터 입력되는 데이터와 터미널로부터 발생하는 시그널에 대한 제어권으로 프로세스 그룹 단위로 제어권이 부여됨.
		- 커널이 프로세스 그룹을 식별하기 위한 PGID를 부여하며 PGID는 별도로 부여하는 식별자가 아니고 해당 그룹의 리더 프로세스의 PID를 PGID로 설정한다.
	- **포/백그라운드**
		- 터미널에 대한 제어권을 가지고 동작하는 모드를 포그라운드, 제어권 없이 동작하는 모드를 백그라운드라 한다.
		- 터미널과 연결되어 세션이 생성되면 해당 세션 내에서는 하나의 포그라운드 프로세스 그룹과 하나 이상의 백그라운드 프로세스 그룹이 생성된다.
- **(라) 프로세스 관련 식별자**

#### 2) 프로세스 정보 확인(ps)
- `ps` 명령어로 시스템에서 동작하는 프로세스 정보를 확인할 때 씀.
	- `-f, -l, -e` 3개를 주로 쓴다.
	- e는 everthing. 시스템에서 동작중인 프로세스를 전부 출력하는것. 안쓰면 현재 셸에서 동작중인 프로세스 정보만 출력한다.
	- f를 사용하면 좀 간략하게 출력한다. 프로세스의 상태 현재 상태 정보를 볼 수 있는 S 필드나 우선순위를 나타내는 PRI 필드... 차지하는 메모리 크기인 SZ 필드 등등 빠지는게 많다.
- 주요 필드들은 아래와 같다.
	- **-f 사용시 나오는 필드**
		- UID, PID, PPID, STIME, TTY, TIME, CMD
			- UID : 여기서 UID는 EUID를 나타낸다.
			- STIME : 프로세스가 시작된 시간.
			- TTY : 프로세스와 연결된 터미널 타입. ?는 제어 터미널에 연결되어있지 않음을 나타냄.
			- TIME : CPU 사용시간
	- **-l 사용시 추가되는 필드**
		- S, PRI, SZ, WCHAN, CMD
			- S : 프로세스의 현재 상태 정보.
				- Z : 좀비
				- R : CPU 점유를 위해 대기중이거나 실행중인 상태
				- S : 인터럽트가 가능한 Sleep 상태
				- D : 인터럽트가 불가능한 Sleep 상태. 일반적으로 IO 대기 중 상태.
				- T : 정지된 상태
			- PRI : 프로세스 우선순위
			- SZ : 프로세스가 차지하는 메모리 크기
			- WCHAN : Sleep 상태의 프로세스가 기다리는 커널 함수명

#### 3) 프로세스 간 통신(시그널)
- 시그널은 유닉스/리눅스 시스템에서 지원하는 프로세스 간 통신 기법 중 하나로 커널 또는 프로세스가 다른 프로세스에 약속된 신호를 전달하여 통신하는 목적으로 사용한다.
- 시그널 발생 상황은 에러 상황, 외부 상황, 이벤트 발생, 인위적 발생 등이 있음.
	- 에러는 주로 커널
	- 외부 상황은 주로 키보드 입력
	- 이벤트 발생은 주로 alarm() 함수나 프로세스 종료
	- 인위적 발생은 kill() 시스템 콜이나 kill 명령어 등으로 발생함.
- **kill 입력문법**
	- -l을 사용하면 지원하는 시그널 목록을 출력한다.
	- 시그널은 번호나 이름으로 지정할 수 있다.
	- `kill -9 1000` : PID가 1000번인 프로세스에 9번 시그널(SIGKILL)을 전달한다.
- **시그널 목록**
	- **SIGINT**
		- 2번. Ctrl + C 조합키를 누르면 포그라운드 프로세스 그룹 내 모든 프로세스에 이 시그널이 전달됨. 이 시그널을 받은 프로세스는 디폴트로 종료.
	- **SIGKILL**
		- 9번. 무시하거나 임의 처리 불가. 무조건 종료.
	- **SIGSTOP**

## 4. UNIX/Linux 서버 보안
### (1) 시스템 보안
#### 1) 사용자 패스워드 관리
- **(가) 개요**
	- passwd / shadow 알고 있음.
- **(나) passwd 파일**

	- `[사용자 계정명]:[비밀번호]:[UID]:[GID]:[설명]:[홈디렉터리]:[로그인 셸]`
	- 비밀번호의 경우 shadow를 사용하면 x로 표시됨.
	-  UID가 0일 경우 root. 때문에 다른 계정의 uid가 0이면 루트 탈취 행위 의심해야됨.
	- GID도 똑같다.
	- 로그인 셀의 경우 로그인이 불필요한 계정은 `/bin/false`나 `/sbin/nologin`으로 설정하여 로긴을 막아야 한다. 기본값은 `/bin/bash`.
- **(다) shadow 파일**
	- 구조는 다음과 같다.
	- `[이름] : [암호화된 해시값] : [마지막 변경일] : [패스워드 최소 사용일] : [최대 사용일] : [만료 경고일] : [유예기간]: [만료일] : [예약필드]`
		- 패스워드의 경우 `$id$salt$hashed` 형태. id는 암호화 알고리즘, salt는 소금값, hashed는 사용자 패스워드에 솔트를 조합한 값의 해시값.
			- 암호화 알고리즘의 경우 `$1`은 MD5, `$2a, $2y`는 Blowfish, `$5, $6` : SHA-256 / 512. MD5의 경우 안전하지 않기 때문에 5 즉 SHA-256 이상의 알고리즘을 사용해야 함.
			- 솔트 즉 소금값은 레인보우 테이블 공격에 효과적으로 대응이 가능함. 암호화된 패스워드의 평문을 알아낸다고 하더라도 솔트와 조합된 패스워드 해시값에 대한 평문 패스워드로 실제 패스워드가 아니기 때문.
		- 만약 패스워드에 값이 없으면 비어있는거라 누구든지 로그인이 가능하다.
		- 패스워드에 아래 기호가 있으면 의미는 다음과 같다.
			- `*` : 패스워드가 잠긴 상태. 로그인은 불가능하지만 SSH 인증키 등의 방법으로 로그인이 가능함.
			- `!!` : 패스워드가 잠긴 상태로 모든 로그인이 불가능함. 기본적으로 사용자 생성 후 패스워드를 설정하지 않으면 !! 상태가 된다.
		- 변경일, 만료일의 경우 1970년 1월 1일을 기준으로 계산한다. 왜 그런거지?
		- 패스워드 최대 사용일이 99999면 변경하지 않아도 된다.
		- 실제로는 예약필드까지 필드는 총 9개. 그래서 콜론의 개수가 8개이다.
	- 패스워드를 잠그는건 `passwd -l`, 푸는건 `-u`.
	- 유닉스는 리눅스랑 살짝 다르다.
		- NP : 로그인을 할 수 없는 계정. 시스템이나 애플리케이션 계정 용도.
		- `*LK*` : 비밀번호가 잠긴 상태로 로그인 불가.
		- 빈값 : 패스워드가 없으며 설정되어있지 않으면 로그인 시 패스워드 설정 과정이 진행된다.
	- **패스워드 저장 정책 변경**
		- `pwconv`는 shadow 사용, `pwunconv`는 shadow 비활성화.

#### 2) 프로세스 실행권한(SUID, SGID)
- setuid, setgid에 관한 내용.
- Real ID와 Effective ID에 관한 내용이다.
- 리얼 쪽은 프로세스를 실행시킨 사용자의 아이디를 뜻하고...
- 이펙티브 쪽은 실행 중인 동안에만 부여되는 임시 아이디를 뜻한다.
- SetUID/GID로 실행시 이펙티브에 속한다.
- 즉 SetUID/GID가 설정된 파일을 실행하면...
	- RSID/GID는 파일을 실행시킨 사람이 뜬다.
	- 하지만 ESID/GID의 경우 파일의 소유자가 뜬다. 이 사람의 권한으로 실행중이라는 것.
- SetUID는 s나 숫자로 표기한다. 4의 경우 suid, 2는 sgid, 6은 둘 다 설정이다. 4755같이 앞에다가 써주면 된다.
	- `chmod u+s a.out / chmod ug+s a.out`
	- `chmod 6755 a.out`
- 만약 루트 소유의 자원에 대해 사용자의 직접 접근을 차단하고 기능상 필요한 부분만 접근하도록 허용할 필요가 있는 경우 보안 측면과 운영 측면에 매우 효율적이긴 하다.
- 하지만 루트 권한이 필요 없는데도 소유주가 루트면서 Setuid가 설정된 경우 보안상 매우 취약함.
	- `find -perm /6000` 같은 방식으로 setuid, setgid가 있는 명령어들을 검색할 수 있다.
	- `find / -user root -type f \( -perm -4000 -o -perm 2000 \) -exec ls -al {} \;`
		- 소유주가 root이고 일반 실행파일이면서 SUID, GID가 설정된 파일의 정보를 출력
- 제거는 `chmod -s`로 하면 된다. setuid/gid를 둘 다 제거함.

#### 3) 디렉터리 접근권한(스티키 비트)
- 일반적으로 공유 디렉터리(`/tmp, /var/tmp`)는 모든 사용자가 사용할 수 있도록 모든 권한을 부여한다. 하지만 다른 사용자가 만든 파일을 누구나 삭제 또는 변경이 가능하기 때문에 파일의 삭제나 이름 변경 등은 소유자만 할 수 있도록 설정해야 한다.
- 이 권한을 스티키 비트라고 한다.
- 스티키 비트는 숫자 1 또는 t로 표현한다.
	- `chmod 1777 /tmp`
	- `chmod o+t /tmp`
	- 유닉스의 경우 o가 아니라 u이기 때문에 `u+t`로 해야한다.

#### 1) 버퍼 오버플로우 공격
- **(가) 개요**
	- 연속된 메모리 공간에 사용하는 프로그램에서 메모리의 범위를 넘어선 위치에 자료를 읽거나 쓰려고 할 때 발생함.
	- 오작동을 유발하거나 악의적 코드를 실행하여 공격자 프로그램을 통제할 수 있는 권한을 획득하게 됨.
	- 스택과 힙 오버플로우가 있다.
		- 스택은 함수 처리를 지역변수 및 매개변수가 위치하는 메모리 영역. 주로 복귀 주소를 변경하고 공격자가 원하는 코드를 실행하도록 한다.
		- 힙은 사용자가 동적으로 할당하는 메모리 영역. 힙의 메모리 사이즈를 초과하여 문자열이 저장되는 경우 데이터와 함수 주소 등을 변경하여 공격자가 원하는 임의 코드를 실행함.
- **(나) 버퍼 오버플로우 이해를 위한 C언어 함수**
	- **주요 C언어 함수**
		- `strcpy(char *dst, const char *src)` : src 문자열을 dst 버퍼에 저장한다. src의 문자열 크기를 체크하지 않으므로 dst 버퍼를 초과하는 결과가 발생 가능.
		- `strncpy(char *dst, const char *src, size_t len)` : 얘는 src의 문자열의 len 만큼을 버퍼에 저장함. 때문에 안전함.
		- `size_t strlen(const char *str)` : 문자열의 널 문자를 제외한 바이트 수를 반환한다.
		- `sizeof(피연산자)` : 피연산자의 크기를 반환한다.
	- **C언어에서의 문자열 처리 방식**
		- C언어에서 문자열은 널문자로 문자열의 끝을 표현한다.
		- 널 문자는 0x00으로 표기함.
		- ABCD라는 문자열을 정의한다면 실제로는 ABCD\0, \0은 널 문자를 의미하므로 5개의 문자로 저장된다.
- **(다) 스택 버퍼 오버플로우 공격 실습**
	- 나중에..!
- **(라) 스택 버퍼 오버플로우 대응방안(안전한 코드)**
	- **1. 안전한 함수를 사용하여 방지**
		- `strncpy()` 함수를 사용한다.
		- len만큼 저장하기 때문에 오버플로우가 발생하지 않음.
		- len크기를 `sizeof(buffer) - 1`로 설정하여 마지막 널문자를 포함시킨다.
	- **2. 입력값 사전 검증을 통한 방지**
		- 입력 문자열이 버퍼와 같거나 크면 프로그램을 종료하도록 한다.
		- 직접 버퍼의 크기를 명시할 수도 있지만 버퍼의 크기 변경시 유연하지 않으므로 주의가 필요하다.
- **(마) 스택 버퍼 오버플로우 대응 기술**
	- **스택 가드** 
		- 메모리 상의 복귀 주소와 변수 사이에 특정 값을 저장했다가 값 변경시 오버플로우로 간주하여 중단을 시키는 방법. 여기서 그 특정 값을 카나리 단어라고 부른다.
	- **스택 쉴드** 
		- 복귀 주소를 Global RET라는 특수 스택에 저장했다가 종료시 Global RET 값을 스택의 RET 값과 비교하여 다르면 오버플로우로 간주하고 중단시킨다.
	- **ASLR**
		- 주소 공간 배치를 난수화하는 기법. 실행시마다 메모리 주소를 변경시켜 악성코드에 의한 특정주소 호출을 방지한다.

#### 3) 포맷 스트링 공격(Format String Attack)
- ****(가) 개요
	- C 언어에서 `printf()` 등 함수에서 사용되는 문자열의 입/출력 형태를 정의하는 문자열로 서식 문자열이라 표현함.
	- 외부에서 들어온 값을 검증하지 않고 함수의 포맷 스트링을 그대로 사용하는 경우 발생할 수 있는 취약점.
- **(나) 공격 원리 실습**
	- `printf(), fprintf(), sprintf()`가 주요 함수에 해당한다.
		- printf는 표준 출력, fprintf는 파일 출력, sprintf는 버퍼 출력에 해당함.
	- **포맷 스트링 식별자**
		- `%d / %f / %c / %s / %x / %n`
		- 각각...
		- `10진수 / 실수 / 문자 / 문자열 / 16진수 정수` 출력이고..
		- `%n`은 이전까지 출력한 총 바이트수를 지정한 변수(4 바이트 단위)에 저장한다.
			- `%hn`은 2바이트 단위로 저장한다.
- **(다) 대응 방안**
	- 간단하게 함수 사용 시 포맷 스트링을 지정하여 간접적으로 참고하게 한다.
	- `printf(argv[1]);` 처럼 직접 넣지 말고...
	- `printf("%s", argv[1]);` 처럼 간접적으로 넣으면 형식 지정자를 넣어도 단순 문자열 텍스트 처리가 되어 안전하다.
