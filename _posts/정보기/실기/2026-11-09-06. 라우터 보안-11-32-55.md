## 1. 라우터 자체 보안
#### 1) 개요
- 처음 접속하면 사용자 모드. 암것도 못함. 라우터 정보만 볼 수 있음.
- enable로 privileged 모드로 레벨을 변경하여 조회 말고도 설정 변경 등을 할 수 있음.
	- User EXEC 모드 : `>`로 보이는 모드. 간단한 상태 조회만 됨.
	- privileged 모드 : `#`으로 보이는 모드. 모든 명령어에 대해 수행이 가능함.
	- Global Configuration 모드 : `(config)` 모드로 보임. 라우터의 전반적인 설정을 변경하고자 할 때 씀.
	- Other configuration 모드 : `(config-mode)`로 보이게 됨. 좀 더 복잡하고 세부적인 설정을 함. 설정이 끝나면 exit나 Ctrl + z로 빠져나오기.
- privileged 모드로 변경할 때 사용하는 enable 패스워드를 설정하기 위해서는 enable password와 enable secret을 사용할 수 있는데, 안전한 운영을 위하여 secret 설정을 추천한다.
- **enable password**
	- type 0(평문 저장)
	- `service password-encryption` 명령을 실행하면 역함수가 존재하는 type 7 방식으로 암호화한다.
- **enable secret**
	- type 5(일방향 해시/MD5)
	- enable password와 같이 설정된 경우 시크릿이 적용됨.

## 2. 라우터와 접근제어(ACL)
#### 1) 개요
- 라우터에서는 access-list를 이용하여 특정 패킷에 대한 접근제어를 설정할 수 있다.
- 표준과 확장 두 가지로 나뉨.

#### 2) standard access-list
- 패킷의 소스 아이피(출발지)만으로 허용하거나 차단한다.
- acl(access-list) number로 1~99까지만 사용함.
- **형식 :** `access-list acl번호 [permit or deny] [소스주소 와일드카드 or any]`
	- `access-list 5 permit host 192.168.159.131`
	- 소스 아이피가 192.168.159.131일 경우 패킷을 허용한다.
	- 만약 특정 아이피를 지정할 경우 host를 아이피 앞에 붙여야 한다.
	- ip 대역을 지정하는 경우 와일드마스크를 명시한다. 서브넷 마스크의 비트를 반전시킨 것과 같다.

#### 3) extend access-list
- 패킷의 소스 아이피 뿐 아니라 목적지 아이피, 포트, 프로토콜 등을 이용하여 차단할 수 있다.
- acl number로 100~199까지 사용한다.
- **형식 :** `access-list acl번호 [permit or deny] [protocol] [source] [source-wildcard] [dest] [dest-wildcard] [프로토콜 지정 또는 범위]`
	- `access-list 120 deny ip host 192.168.159.131 100.100.100.0 0.0.0.255`
		- 출발지가 192.168.159.131이면서 목적지가 100.100.100.0/24 대역인 패킷은 모두 거부.
	- `access-list 140 dent udp host 192.168.2.5 100.100.100.0 0.0.0.255 range 100 200`
		- 단일 포트 지정은 eq, 범위 포트 지정은 range이다.

#### 4) Filtering 유형
- **(가) Ingress**
	- standard 또는 extended access-list를 활용하여 라우터 내부로 즉 사내 네트워크로 유입되는 패킷의 소스 아이피나 목적지 포트 등을 체크하여 허용, 거부하는 필터링.
	- 실제로 존재하지 않는 아이피를 위조된 주소를 소스로 하여 공격을 많이 하기 때문에 실제 사용하지 않는 대역만 차단해도 사전에 차단하는 효과가 있음.
- **(나) Egress**
	- 반대로 외부로 나타는 패킷을 체크하여 필터링함.
	- 나가는 패킷의 소스 아이피는 내부 네트워크의 대역인 것이 정상. 이게 아니라면 위조된 패킷.
- **(다) Blackhole**
	- 특정 아이피나 아이피 대역에 대해 비정상 시도가 감지되었을 경우 가상의 널 인터페이스로 보내 패킷 통신이 되지 않도록 하는 것.
- **(라) Unicast RPF**
	- 위 필터링 방법을 사용하지 않고도 비정상 트래픽을 효율적으로 필터링하는 방법.
	- 인터페이스를 통해 들어오는 패킷의 소스 아이피에 대해 라우팅 테이블을 확인하여 들어온 인터페이스로 다시 나가는지 확인하는 원리.
	- 한 인터페이스로 소스가 10.10.10.10이라면 나갈때도 같은 인터페이스로 목적지가 10.10.10.10인지 확인하여 비정상 여부를 판단함.

## 3. 라우터를 통한 네트워크 보안
#### 1) 콘솔, AUX, VTY 포트 패스워드 보안
- 콘솔 포트는 케이블을 이용하여 직접 터미널에 연결하여 라우터를 조작할 수 있도록 하며 장애 처리 시 많이 사용된다.
- 패스워드를 설정하지 않은 콘솔 포트에 접속하게 되면 아무런 인증 절차 없이 사용이 가능하므로 콘솔을 사용하여 라우터에 접근할 가능성이 있는 경우 콘솔 패스워드를 반드시 설정해야 한다.
	- `line console 0`
	- `login -> password cisco -> end`
- VTY 포트는 원격지에서 텔넷을 통하여 접속 시 사용되는 패스워드를 설정한다. AUX 포트는 현재 잘 사용하지 않으며 VTY와 동일하다.
	- `line vty 0 4` / `line aux 0`
		- 0 4의 뜻은 포트를 0, 1, 2, 3, 4번 가상 회선을 총 5개를 쓴다는 의미며 5명의 유저가 접속할 수 있다.
	- `login -> password cisco -> end`

#### 2) 텔넷 접근 제한
- 기본적으로 vty 포트는 외부로부터의 연결 시도를 모두 받아들임. 이러한 특징을 악용하여 무한대 공격시도를 통하여 라우터 공격이 가능함.
- 허가된 아이피를 가진 사용자에게만 연결 시도를 허용하는 것이 안전.
- 일단 액세스 리스트로 접근 제어 목록을 생성하고 적용하면 된다.
	- `conf t로 먼저 config 모드 진입`
	- `access-list 10 permit host 192.168.0.1`
	- `access-list 10 permit host 192.168.1.1`
	- `access-list 10 deny all`
	- `line vty 0 4 -> access-class 10 in`
- SSH는 암호화 통신을 하므로 텔넷 대신 SSH를 사용하도록 한다.
	```
	** config 모드 **
	hostname [라우터 이름]
	IP domain-name [도메인 이름]
	crypto key generate rsa
	IP ssh time-out [타임아웃값]
	IP ssh authentication-retries [재시도값]
	line vty 0 4
	** line config 모드 **
	transport input ssh
	end
	```

#### 3) SNMP 설정
- SNMP는 TCP/IP 네트워크를 모니터링하고 관리하기에 효율적이다.
- 많은 시스템에서 SNMP의 읽기 권한은 기본적으로 설정되어있기 때문에 이를 이용하는 공격자들이 많음.
- 기본 community string 값은 public으로 되어있음. 이 값을 변경해야 한다.
- access-list를 이용하여 접근통제를 해야한다.
	```
	conf t
	snmp-server community x27swf3 ro 11
	snmp-server contact fake@go.kr
	access-list 11 permit host 211.1.2.5
	access-list 11 deny all
	interface FastEternet 0/0
	ip access-group 11 in
	end
	show access-list
	```
	- snmp를 사용하지 않는다면 `no snmp-server`로 서비스를 제거하는게 좋다.
	- 또한 SNMP 3버전은 암호화를 지원하지만 1,2는 평문으로 정보를 전송한다. 따라서 3버전의 지원 여부를 확인해야 한다.

#### 4) 불필요한 서비스 제거
- **(가) 개요**
	- 불필요한 서비스는 보안 위협의 요소가 된다.
- **(나) ICMP**
	- **ICMP MTU Discovery**
		- 데이터링크 계층에서 출발/목적지 사이를 지나는 패킷 크기를 조절해주는 역할을 한다. ICMP 패킷을 차단하더라도 MTU Discovery를 제공하는 패킷은 허용해야 네트워크가 동작이 가능함.
		- Type 3, 4만 허용하여 MTU Discovery를 담당하는 패킷만 허용하고 나머지는 차단해야한다.
		```
		en
		conf t
		access-list 103 permit icmp any any 3 4
		access-list 103 deny icmp any any
		access-list 103 permit ip any any
		interface FastEthernet 0/0
		ip access-group 103 in
		end
		```
	- **ICMP Redirect**
		- 악의적 공격자들은 해당 패킷을 전송하여 네트워크를 지나는 패킷의 방향을 바꿔 정보 수집이 가능하므로 차단하는 것을 권장함.
		```
		en
		conf t
		interface FastEthernet 0/0
		no ip redirects
		end
		```
	- **ICMP Directed Broadcasts**
		- 이걸 허용하면 외부에서 브로드캐스트 주소로 특정 패킷을 전송하여 해당 네트워크의 모든 호스트에 전달할 수 있다. 도스나 디도스... 예시로 스머프 공격 악용이 가능하므로 차단한다.
		```
		conf t
		interface...
		no ip directed-broadcast
		```
	- **ICMP Mask Reply**
		- 라우터가 해당하는 네트워크의 서브넷 마스크를 전송하도록 한다. 네트워크의 구성을 알아낼 수 있으므로 기능을 차단하는 것이 권장됨.
		- 인터페이스 진입 후 `no ip mask-reply`
	- **ICMP Unreachable**
		- 특정 포트가 열려있는지 판단하기 위해 주로 사용하는 메시지.
		- 스캐닝 시간 증가와 공격 대상의 상태를 알 수 없게 하기 위하여 차단을 권장.
		- 인터페이스 진입 후 `no ip unreachables`
	- **ICMP Timestamp and Information Requests**
		- 공격자로 하여금 네트워크 현황을 알 수 있게 해주는 취약점이므로 차단하는 것을 권장한다.
		```
		access-list 102 permit icmp any any timestamp-request
		access-list 102 permit icmp any any information-request
		access-list 102 permit ip any any
		interface FastEthernet 0/0
		ip access-group 102 in
		end
		```
- **(다) Source Route**
	- 패킷이 전송되는 경로를 각각의 시스템이나 네트워크에 설정된 라우팅 경로를 통하지 않고 패킷의 발송자가 설정할 수 있는 기능. 악용될 소지가 있으므로 중지하는 것이 좋음.
		- `conf t` 후 `no ip source-route`
- **(라) Small Service**
- **(마) Finger 서비스**
- **(바) HTTP Server 서비스**
- **(사) CDP 서비스**
- **(아) proxy-arp 서비스**
- **(자) 기타 불필요 서비스 차단**
