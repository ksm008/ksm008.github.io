## 1. Snort 침입탐지시스템
### (1) 개요
- 1998년 마틴 로시가 개발한 오픈소스 기반 네트워크 침입탐지시스템.
- 스니퍼, 로거, 침입탐지/방지 모드를 제공한다.

### (2) 스노트 규칙(Rule) 설정
#### 1) 개요
- 크게 룰 헤더, 룰 옵션으로 구성됨.
	- **룰 헤더**
		- 검사 대상 패킷과 규칙이 매칭되었을 때 수행할 작업을 정의하는 부분. 
		- 규칙의 기본 구조를 정의하며 액션, 프로토콜, 아이피 주소, 포트 번호, 방향성 등을 지정한다.
	- **룰 옵션**
		- 패킷을 검사하기 위한 세부 조건을 정의하는 부분.
		- 메시지 출력 설정, 콘텐츠 검사, TCP 플래그 검사 등 다양한 탐지 조건을 지정함.
	- **예시**
		- `alert tcp any any -> 10.10.10.0/24 21 (msg:"FTP root user access";content:"USER root"; nocase; sid: 1000001; rev:1;)`

#### 2) 룰 헤더(Rule Header) 설정
- **(가) 액션**
	- 패킷이 규칙에 매칭되었을 떄 수행할 처리 방식.
	- **주요 액션**
		- alert : 경고 발생, 해킷을 로그로 남김
		- log : 경고 없이 패킷을 로그에 남김
		- pass : 패킷을 무시(허용), 해당 패킷에 대해 다른 규칙을 적용하지 않음.
		- activate : 경고 발생, 대응하는 dynamic 규칙을 활성화함.
		- dynamic : activate 규칙에 의해 활성화되며 log 규칙과 동일하게 동작.
		- drop : 패킷 차단, 로그에 남김.
		- reject : 패킷 차단, 로그에 남긴 후 TCP는 TCP Reset, UDP는 ICMP 오류 메시지를 전송
		- sdrop : 패킷 차단, 로그에는 안남김.
- **(나) 프로토콜**
	- TCP, UDP, ICMP, IP 등을 지정 가능.
- **(다) 아이피 주소**
	- 모든 아이피는 any
	- 특정 아이피 제외는 느낌표(!)
	- 아이피 리스트는 대괄호로 묶고 콤마로 구분 
		- `[192.168.56.10, 192.168.56.11]`
	- 대역 표기 가능
		- `192.168.56.0/24`
- **(라) 포트 번호**
	- 단일, 범위, 리스트 가능.
	- 범위는 콜론으로.
		- 1:1023
		- 1024:
		- :49151
	- 포트 리스트는 대괄호로 묶고 콤마로 구분
		- `[20,21,22,23,80,443]`
	- IP, ICMP 같이 포트 개념이 없는 프로토콜은 any를 지정하여 문법 구조를 유지. 포트 번호가 없어도 생략은 불가능함.
- **(마) 방향 지시자**
	- 단방향 지시자는 `->`, 양방향은 `<>`
	- 오른쪽에서 왼쪽 방향은 지원하지 않음.
- **(바) 환경 변수 지정**
	- `/etc/snort/snort.conf`에 환경 변수를 지정할 수 있다.
	- ipvar, portvar 대신 그냥 var를 쓸 수도 있음.
	```
	ipvar EXTERNAL_NET any
	ipvar HOME_NET 172.30.3.0/24
	portvar HTTP_PORTS [80,8080]
	portvar HTTPS_PORTS 443
	```
	- **예시**	
		- `log tcp $EXTERNAL_NET any <> $HOME_NET 443`

#### 3) 룰 옵션 설정 : 일반 옵션 설정

| 옵션        | 설명                                                                                                                           |
| --------- | ---------------------------------------------------------------------------------------------------------------------------- |
| msg       | 이벤트 발생 시 출력할 이벤트 메시지를 지정                                                                                                     |
| reference | 규칙과 관련된 외부 취약점 정보(CVE 등)를 참조하기 위해 사용함.                                                                                       |
| sid       | - 규칙을 식별하기 위한 고유 ID.<br>- 1 ~ 1,000,000 미만 : 스노트 개발팀이나 공식 규칙 제공자가 사용하는 예약 아이디 범위.<br>- 1,000,000 이상 : 사용자 정의 규칙 작성 시 권장하는 ID |
| classtype | 규칙의 공격 유형을 지정함. 유형별로 기본 우선순위가 결정되며 priority 옵션으로 이를 변경할 수 있다.                                                                |
| priority  | 규칙의 우선순위를 지정한다. 우선순위는 1이 가장 높은 우선순위임 숫자가 커질수록 낮아짐.                                                                           |
| rev       | 규칙의 수정 번호로 규칙이 변경될 때마다 1씩 증가함.                                                                                               |

- 규칙 작성시 msg, sid, rev 옵션 사용이 권장되며 sid는 필수임. 없으면 오류 발생.
- 순서 의존성이 없어서 아무렇게나 써도 됨.
- **(가) 규칙 설정 및 alert 메시지 예시**
	```
	alert tcp $EXTERNAL_NET any -> $HOME_NET $HTTP_PORTS (msg:"[CVE-2014-6271]Bash Vulnerability Requested Header"; flow:established,to_server; content"(){"; http_header; reference:cve,2014-6271; classtype:web-application-activity; priority:1; sid:3000001; rev:3)
	```
	- alert 예시는 귀찮아잉
- **(나) 규칙 작성 시 주의 사항**
	- `[룰 헤더] [공백] [룰 옵션]`순으로 작성한다. 줄 바꿈 없이 한 줄로 작성해야 함.
	- 룰 옵션은 괄호 내부에 작성. 각 옵션은 세미콜론으로 끝나고 옵션명과 옵션 값은 콜론으로 구분한다.
	- 옵션 값이 문자열일 경우 큰 따옴표를 이용한다.

#### 4) 룰 옵션 설정 : 페이로드 탐지 및 범위 관련 옵션
- **content**
- **offset**
- **depth**
- **distance**
- **within**
- **nocase**

#### 5) 룰 옵션 설정 : 페이로드 > HTTP 관련 옵션


## 2. iptables 침입차단시스템
### (1) 개요
- 리눅스 커널의 netfilter 기능을 관리자가 설정하고 제어할 수 있도록 하는 도구.
- 패킷 필터링을 설정하기 위한 명령어 기반 관리 도구.

### (2) 주요 기능
- 패킷 필터링 기능 제공
- 상태 검사 기능 제공
- 중요한건 어떻게 사용하느냐

### (3) 주요 용어 정리
#### 1) 테이블
- iptables에서 제공하는 기능을 분류하는 단위로 네트워크 패킷 필터링을 위해서는 filter 테이블을 사용함.
- filter, nat, mangle, raw 등이 있다.

#### 2) 체인(Chain)
- 규칙을 적용하는 단위를 말한다.
- 필터 테이블에서 사용되는 기본 체인은 다음과 같음.
	- INPUT / OUTPUT / FORWARD
	- INPUT은 외부에서 들어오는거
	- OUTPUT은 외부로 나가는거
	- FORWARD는 그냥 경유하는 패킷. 패킷 필터링 게이트웨이 역할.

#### 3) 규칙
- 패킷을 필터링 하기 위한 조건.

#### 4) 타깃(Target)
- 설정한 규칙에 일치하는 패킷이 발생했을 때 적용할 동작을 의미함.
	- ACCEPT는 허용
	- DROP은 즉시 폐기. 응답 없이.
	- REJECT는 패킷 거부하고 송신자에게 ICMP 오류 메시지를 전송한다.
	- LOG : 패킷 정보를 로그에 기록한다.
- iptables는 체인 내 설정한 규칙을 상단부터 순차적으로 검사하며 조건에 일치하는 규칙을 만나면 해당 타깃의 동작을 수행하고 규칙 검사를 중단한다. 단, 로그 타깃은 예외적으로 패킷을 기록한 후에도 다음 규칙 검사를 계속 진행한다.

### (4) 사용법
#### 1) 기본 형식
- `iptables [테이블 설정] [체인 설정] [룰 설정] [타겟 설정]`
	- `iptables -t filter -A INPUT -p tcp --dport 443 -j ACCEPT`

#### 2) 테이블 설정
- 테이블을 명시하지 않으면 filter 테이블이 적용됨. 일반적으로 패킷 필터링이 목적이면 -t filter 옵션을 생략하고 사용한다.

#### 3) 체인 설정
- -A : 마지막 행에 규칙 추가
- -I : 지정한 체인에 규칙을 삽입. `-I 체인명 행번호` 형식으로 삽입 위치를 지정할 수 있고 행번호 생략 시 가장 앞에 규칙이 삽입됨.
- -D : 지정한 체인에서 특정 규칙 삭제. -I 처럼 체인명, 행번호로 삭제 가능.
- -F : 체인명 : 모든 규칙 한번에 삭제. flush.

#### 4) 규칙 설정
- **(가) 프로토콜 지정**
	- 프로토콜은 TCP, UDP, ICMP 등을 지정할 수 있으며 지정하지 않으면 모든 프로토콜을 의미.
- **(나) 호스트 식별 아이피 주소 지정**
	- **-s, -d**
		- -s는 출발지 아이피 주소나 네트워크.
		- -d는 목적지겠죠?
		- 둘 다 단일로 지정할 수도 있고 CIDR 표기법도 가능(192.168.159.0/24)
- **(다) TCP/UDP 서비스 식별 포트 번호 지정**
	- ****--sport, --dport
		- 알잘딱
		- `1024:` 처럼 콜론이 뒤면 1024번 이상, `:1023`처럼 콜론이 뒤면 이하. `1:1023` 처럼 사이에 있으면 범위.
		- 포트 번호 대신 `/etc/services`에 정의된 서비스명으로도 할 수 있다. 
			- `-p tcp --dport 또는 --sport https`
- **(라) TCP 프로토콜 관련 제어 플래그 지정**
	- `iptables -p -tcp --syn`
		- SYN 패킷을 검사하기 위함.
	- `iptables -p -tcp --tcp-flags [검사 대상 플래그] [설정된 플래그]`
		- `iptables -p tcp --tcp-flags ALL SYN,FIN`
			- 모든 제어 플래그를 검사했을 때 SYN, FIN만 설정된 패킷을 의미
		- `iptables -p tcp --tcp-flags SYN,FIN SYN,FIN `
	- `iptables -p -icmp --icmp-type [메시지 타입]`
		- `-p icmp --icmp-type echo-request` 
			- echo-request 대신 숫자 8도 가능하다. echo-reply의 경우 숫자 0에 해당.

#### 5) 타겟 설정
- `-j`로 설정하는 거. ACCEPT, DROP, REJECT, LOG가 있음.
- 차단을 위해서는 DROP을 당연히 권장하는게...
	- REJECT 방식은 ICMP 오류 메시지 응답을 전송하므로...
		- 불필요한 네트워크 트래픽 증가
		- 공격자가 서비스 거부 공격에 악용
		- 침입차단시스템의 존재 및 패킷 필터링 정책 추론에 활용
		- 등 위험이 있음.

#### 6) 기타 설정
- **(가) 체인에 설정된 규칙 확인**
	- -L 옵션으로 지정한 체인에 등록된 규칙 목록을 출력할 수 있음. 체인명을 생략하면 모든 체인의 규칙 목록 출력.
	- `iptables -L [체인명] -n --line-numbers`
	- -n 옵션은 아이피 주소와 포트번호를 숫자 형식으로 출력한다.
	- --line-numbers 옵션은 각 규칙의 행 번호를 출력한다.
- **(나) 체인에 기본 정책 설정하기**
	- -P 옵션으로 기본 정책을 설정할 수 있음. 모든 규칙에 일치하지 않는 패킷에 대해서 마지막으로 적용되는 정책.
	- 기본적으로 네거티브 정책 사용을 권장함.
		- 네거티브는 기본이 차단, 나머지 규칙에 따라 허용.
		- 포지티브는 기본이 허용, 나머지 규칙에 따라 차단.
		- 당연히 네거티브가 안전하겠지
- **(다) 정책 정보를 저장하고 복원하기**
	- `iptables-save > [저장할 파일명]`
	- `iptables-restore < [복원할 파일명]`
	- 리눅스 마스터에도 나왔던거.

### (5) iptables 정책 설정 실습 1 : 비상태 기반 정책
#### 1) 호스트의 특정 서비스만 외부 접근을 허용하고 그 외 모든 접근을 차단하는 정책
- **(가) 정책 목적**
	- 호스트의 HTTPS(443/tcp)와 DNS 서비스(53/tcp, 53/udp)만 외부 접근을 허용하고, 그 외 모든 접근을 차단하는 정책 설정
	- 인풋과 아웃풋의 기본 정책은 DROP으로 설정한다.
- **(나) 정책 설정**
	- 현재 시점은 서버에서 호스트의 외부 접근을 다룬다. 즉 호스트가 요청을 하면 서버쪽에서 응답을 하는 것.
	- 그러면 인풋에 대해서는 --dport, 아웃풋에 대해서는 --sport를 사용하게 된다
	- 기본 설정을 먼저 진행한다.
		```
		iptables -P INPUT DROP
		iptables -P OUTPUT DROP
		```
	- 그 후에는 목적에 알맞게 설정해주면 된다.
		```
		iptables -A INPUT -p tcp --dport 443 -j ACCEPT
		iptables -A INPUT -p tcp --dport 53 -j ACCEPT
		iptables -A INPUT -p udp --dport 53 -j ACCEPT
		iptables -A INPUT -j DROP (기본이 DROP이므로 생략가능)
		
		iptables -A OUTPUT -p tcp --sport 443 -j ACCEPT
		iptables -A OUTPUT -p tcp --sport 53 -j ACCEPT
		iptables -A OUTPUT -p udp --sport 53 -j ACCEPT
		iptables -A OUTPUT -j DROP (기본이 DROP이므로 생략가능)
		```
	- 주로 서버는 요청을 받는 쪽이므로 인풋일 때 목적지 포트를 확인하고, 아웃풋일때 출발지 포트를 확인한다.
	- 하지만 요청을 보내는 클라이언트는 서버의 특정 포트로 보내는게 목적이므로 아웃풋일때 목적지 포트를 확인하고, 인풋일때 출발지 포트를 확인한다.
	- 나머지 문제도 똑같은 방식이고 이 정도 난이도는 산업기사에서만 나오는 듯.

### (6) iptables 정책 설정 실습 2 : 상태 기반(Stateful) 정책
#### 1) 개요
- **(가) 상태(state) 설정**
	- `iptables -m state --state [NEW | ESTABLISHED | RELATED | INVALID]`
- **(나) 상태 유형**
	- NEW는 말 그대로 새로운거. TCP 연결의 경우 첫 SYN 패킷이 NEW 상태. 최초 연결 정보를 생성하는 패킷 형태다.
	- ESTABLISHED는 상태 추적 테이블에 이미 연결 정보가 있는 패킷의 상태다. TCP의 경우 SYN 패킷 이후 종료할 때까지 서로 주고받으면 이 상태가 됨.
	- RELATED 상태는 상태 추적 테이블에 있는 기존 연결과 논리적으로 연관된 새로운 연결을 생성하는 패킷 상태다. 예시로 FTP 제어 채널 연결 이후 새로 생성되는 데이터 채널 패킷은 RELATED.
	- INVALID 상태는 알잘딱
- **(다) 프로토콜별 연결 상태 추적**
	- **TCP**
		- 호스트가 최초로 SYN 패킷을 수신하면 상태 추적 테이블에 새로운 연결 정보가 등록되고 NEW 상태가 됨.
		- 이후 같은 연결의 모든 TCP 패킷은 ESTABLISHED가 된다.
	- **UDP**
		- UDP는 비연결형 프로토콜이다. 세션 유지를 안함...
		- 그래서 최초 패킷을 수신하면 출발/목적지 아이피와 포트번호를 기반으로 임시 연결 정보를 등록하고 NEW 상태가 됨.
		- 일정시간동안 동일한 연결의 UDP 응답 패킷은 ESTABLISHED 상태로 관리되고, 시간이 지나면 연결 정보는 자동으로 사라짐.

#### 2) 실습 2-1, 호스트의 특정 서비스만 외부 접근을 허용하고 그 외 모든 접근을 차단하는 정책.
- **(가) 정책 목적**
	- 아까와 같지만 상태 기반으로 설정한다.
	- 호스트의 HTTPS(443/tcp)와 DNS 서비스(53/tcp, 53/udp)만 외부 접근을 허용하고, 그 외 모든 접근을 차단하는 정책 설정
	- 인풋과 아웃풋의 기본 정책은 DROP으로 설정한다.
- **(나) 정책 설정**
	- 일단 처음에 똑같이 기본 정책을 DROP으로 하는건 같음. -P 인풋 드랍, 아웃풋 드랍.
	- 그 다음에는 일단 ESTABLISHED, RELATED 상태인 놈들은 다 허용을 시킨다. 이미 연결이 성립이 되었으니 허용시키는 것.
	- 그 다음으로 인풋은 각 서비스 별로 처음 연결을 생성하는 패킷을 허용한다. TCP의 경우 --syn 옵션을 쓰면 된다.
	- 그리고 아웃풋도 일단 ESTABLISHED, RELATED 상태 패킷은 허용한다. 
	```
	iptables -P INPUT DROP
	iptables -P OUTPUT DROP
	
	iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
	iptables -A INPUT -p tcp --syn --dport 443 -m state --state NEW -j ACCEPT
	iptables -A INPUT -p tcp --syn --dport 53 -m state --state NEW -j ACCEPT
	iptables -A INPUT -p udp --dport 53 -m state --state NEW -j ACCEPT
	
	iptables -A OUTPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
	```
	- 결국 알아야 할 것은 기본적으로 ESTABLISHED,RELATED 상태 패킷은 허용하도록 한다. 그리고 호스트가 외부로 나가는게 먼저인지, 그냥 받는게 먼저인지를 보고 작성해야 한다.

### (7) iptables 정책 설정 실습 3 : 비정상 TCP 패킷 탐지 정책

#### 1) 비정상 TCP 연결 시도 탐지
- **(가) 탐지 정책**
	- `iptables -A INPUT -p tcp !--syn -m state --state NEW -j LOG --log-prefix"[Forged TCP DETECTED]"`
	- `!--syn`은 SYN 제어 플래그가 설정되지 않은 패킷을 의미한다.
	- 그러므로 SYN 제어 플래그 없이 새롭게 연결을 시도하는 비정상 TCP 패킷을 탐지하고 로그에 작성하게 된다. 
	- 로그 경로 기본은 `/var/log/messages`에 작성됨.

#### 2) 비정상 SYN/FIN TCP 패킷 탐지
- `iptables -A INPUT -p tcp --tcp-flags SYN,FIN SYN,FIN -m state --state NEW -j LOG --log-prefix"[Forged SYN/FIN DETECTED]"`
	- SYN, FIN 제어 플래그가 동시에 설정된 비정상적인 TCP 패킷을 탐지한다.
	- 연결 설정과 종료를 동시에 할 순 없으므로 위조된 패킷이다.
