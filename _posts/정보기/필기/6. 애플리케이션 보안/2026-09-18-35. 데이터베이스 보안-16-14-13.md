## 1. 데이터베이스 기본 개념
#### 1) 데이터베이스 정의
- 알잘딱

#### 2) 키의 유형
- 후보키 : 유일성, 최소성 만족
- 슈퍼키 : 유일성만 만족
- 기본키 : 후보키 중 하나를 선정하여 지정
- 대체키 : 여러 개의 후보키 중 기본키를 제외한 나머지 키
- 외래키 : 한 릴레이션의 속성의 집합이 다른 릴레이션에서 기본키로 이용되는 키

#### 3) 무결성의 종류 
- 키 무결성 : 같은 키 값을 가진 튜플이 존재해선 안된다.
- 개체 무결성 : 기본키는 널값을 가질 수 없다.
- 참조 무결성 : 외래키는 참조 릴레이션에 존재하는 값이거나 널값이어야 한다.

#### 4) 트랜잭션
- **(가) 정의**
	- 논리적 기능을 수행하기 위한 작업의 단위
	- 한거번에 수행되어야 할 일련의 데이터베이스 연산
	- 병행 제어 및 회복 작업의 논리적 단위.
- **(나) 트랜잭션의 ACID 성질** 
	- 원자성 : Atomicity. 트랜잭션 내의 모든 연산은 반드시 한꺼번에 완료되거나 아님 취소되어야 함
	- 일관성 : Consistency. 트랜잭션이 성공적으로 완료되면 일관성 있는 데이터베이스 상태로 변환. 단 프로그램 실행 중 일관성 위반은 노상관
	- 격리성 : Isolation. 트랜잭션이 실행 중에 있는 연산 중간 결과는 다른 트랜잭션이 접근 불가
	- 영속성 : Durability. 트랜잭션이 그 실행을 성공적으로 완료하면 결과는 영속적이다. 완료된 결과의 영속성을 보장해야 함.

## 2. 데이터베이스 보안 요구사항
### (1) 데이터베이스 보안
#### 1) 개요
- 해로운 것으로부터 데이터베이스를 보호
- 보안을 강화하면 해커가 들어와도 데이터베이스는 암호화되어 있기 때문에 볼 수 없음
- 데이터베이스 시스템 보안 요구사항은 아래와 같다.
	- 사용자 인증
	- 접근통제
	- 무결성 보장
	- 감사
	- 비밀 데이터의 보호 및 관리

### (2) 보안위협
#### 1) 데이터베이스 보안 위협
- **(가) 개요**
	- 유출, 부적절한 데이터 처리/수정으로 인한 무결성 손상이 발생 가능함
	- 또한 도스도 발생할 수 있음
- **(나) 주요 위협**
	- **애그리게이션(Aggregation, 집성)**
		- 여러 소스로 민감하지 않은 정보를 수집하여 민감한 정보를 생성함
		- 낮은 등급으로 높은 등급 만듬
		- 집성에 대한 대응책으로 제안된것은 없음
	- **추론(inference)**
		- 일반적인 데이터로부터 비밀정보를 획득할 수 있는 가능성을 의미
		- 사용자가 통계적인 데이터 값으로 개별적 데이터 항목에 대한 정보를 추적하지 못하도록 하여야 함. 통제하기 가장 어려운 위협이다.
		- 추론 대응책으로는 Polyinstantiation, Partition, Cell suppression, Noise, Perturbation 등이 있음.
		- **다중사례화(Polyinstatiation)**
			- 낮은 등급자가 레코드 입력 시 높은 등급자가 존재하고 있다는 것을 오류 확인을 통해 확인하는걸 방지하기 위한 방법.
			- 두 가지 버전의 동일 객체를 생성함으로서 낮은 수준의 주체가 실체 정보를 알지 못하게 함.
			- 보안 수준을 갖지 않은 엔티티에게 거짓 정보를 제공하는 방법임
