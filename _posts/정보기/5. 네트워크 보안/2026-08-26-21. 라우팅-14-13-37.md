## 1. 라우팅 개요
#### 1) 기본 개념
- 패킷을 전송하기 위해 송신자측에서 목적지까지의 경로를 정하고 정해진 경로를 따라 패킷을 전달하는 일련의 과정.
- 최선의 경로를 결정하게 된다.
- 알고리즘 관리자가 직접 라우팅 테이블을 설정하는 정적 라우팅 알고리즘, 네트워크 환경 변화에 따라 능동적으로 대처가 가능한 동적 라우팅 알고리즘으로 구분됨.
- 장단점은 알잘딱

#### 2) 라우팅 프로토콜
- 라우팅을 하는 프로토콜이겠지
- TCP/IP, IPX 같은 프로토콜은 라우팅을 받는 고객이므로 라우티드 프로토콜이라고 부름.
- RIP, OSPF 같은 길을 만들어주는 프로토콜이 라우팅 프로토콜.
- 목적지에 대한 이정표를 라우팅 테이블이라고 부름. 이건 프로토콜마다 다르다.
- AS(autonomous system)는 하나의 관리 도메인에 속해 있는 라우터의 집합을 말한다.
- AS 내에 운영되는 라우팅 프로토콜을 IGP 라고 하며, AS 간에 라우팅 정보를 교환하기 위한 프로토콜을 EGP라고 한다.

## 2. 유니캐스트 라우팅
### (1) 라우팅 알고리즘
#### 1) 거리벡터 라우팅(DV, distance-vector)
- **(가) 개요**
	- 거리벡터 라우팅에서 가장 각 노드가 가장 먼저 만드는건 인접한 이웃들의 기초 정보를 이용한 자신의 최소 비용 트리다.
	- 자신의 모든 이웃에게 자신이 가지고 있는 인터넷에 대한 정보가 불완전하더라도 자신이 알고 있는 네트워크 정보를 끊임없이 알려준다.
- **(나) 거리 벡터**
	- 최소 비용트리처럼 목적지까지의 경로를 제공하지는 않는다. 
	- 목적지까지의 최소비용만을 제공함.

#### 2) 링크-상태 라우팅
- **(가) 링크 상태 데이터베이스**
	- 링크 상태 라우팅을 사용하여 최소비용 트리를 작성하기 위해 각 노드는 각 링크의 상태를 알아야 한다. 때문에 네트워크의 완전한 맵이 필요함.
	- 링크의 상태집합을 링크상태 데이터베이스(LSDB, link-state database) 라고 부른다.
	- 각 노드가 모든 인터넷에 대한 정보가 포함된 이런 LSDB는 플러딩(flooding)이라 불리는 과정을 통해 만들어진다.

#### 3) 경로 벡터 라우팅(PV, path-vector)
-  **(가) 스패닝 트리**
	- 경로-벡터 라우팅에서 소스부터 모든 목적지까지의 경로는 스패닝 트리에 의해 결정된다. 하지만 스패닝 트리는 최소비용 트리가 아니다. 이것은 스패닝 트리 고유의 규칙을 적용시켜 근원지에서부터 작성되는 트리.
	- 목적지까지 하나 이상의 경로가 있다면 근원지는 가장 최선의 규칙을 사용하는 경로를 선택한다.

### (2) 유니캐스트 라우팅 프로토콜
#### 1) RIP(Routing Information Protocol)
- **(가) 개요**
	- RIP은 가장 오래되고 널리 사용되는 내부 라우팅 프로토콜.
	- 각 라우터는 거리 벡터 알고리즘을 사용하며 라우팅 테이블에 자율 시스템 내의 다양한 네트워크에 도착하는 방법과 거리를 홉수로 저장한다.
	- 여러 한계가 있지만 설정하기 쉽고 간단해서 널리 사용되었다.
	- RIP은 거리벡터, OSPF는 링크상태, BGP는 경로벡터 알고리즘이다.
	- RIP는 제록스 네트워크 시스템에서 시작되었다. 하지만 유닉스의 BSD버전이 RIP를 널리 사용될 수 있게 만들었다.
	- RIP에는 IPv4에서 사용할 수 있는 RIP 버전1, 2와 IPv6에서 사용할 수 있는 RIPng가 있다. 프로토콜의 기본 동작은 세 버전에서 거의 동일하지만 전송하는 메시지의 포맷이 조금씩 다르다.
- **(나) 홉 카운트**
	- 지연, 대역폭 등과 같은 링크와 라우터 성능 요소로 좀 더 간단하고 독립적으로 나타내기 위해 비용은 네트워크 수를 의미하는 홉 수로 정의됨.
	- RIP에서 경로의 최대 비용은 15. 16은 무한대로 생각한다. 
	- 이러한 이유로 RIP은 AS에서 사용되며 15홉 이내의 반지름을 가지게 된다.
- **(다) 포워딩 테이블**
	- RIP에서 포워딩 테이블은 3개의 열을 가지는 테이블.
	- 첫 번째 열은 목적지 네트워크의 주소
	- 두 번째 열은 패킷이 전송되어야 할 다음 라우터 주소
	- 세 번째 열은 목적지에 도달하기 위해 홉수로 표현된 비용.
- **(라) RIP 구현**
	- 라우터의 RIP 소프트웨어는 RIP 메세지로 서로 통신한다.
	- UDP를 사용하며 RIP 1,2는 520번, RIPng는 521번 포트를 사용함.
	- RIP는 다른 라우팅 프로토콜처럼 3계층으로 간주되지만 애플리케이션처럼 메시지를 보낸다.
	- RIP 원래 버전은 RIP-1이라고도 부르는데 지금의 RIP에 비해 기능이 적었음.
	- RIP-2는 CIDR 등의 기능을 지원하도록 수정되었다. RIPng는 IPv6와의 호환성을 위해 새로 만들어진 버전.
- **(마) 문제점**
	- **느린 수렴(convergence)**
		- RIP에서 사용하는 거리 벡터 알고리즘은 모든 라우터가 라우팅 정보를 정기적으로 공유하도록 설계됨. 
		- 이는 모든 라우터가 같은 정보를 갖게 되기까지 오랜 수렴시간이 들며 토폴로지 변화가 전파되는데 시간이 많이 걸린다.
		- **수렴**
			- 모든 라우터가 네트워크의 위치에 대한 같은 정보를 가지게 되어 상대방에게 도착하는 가장 좋은 경로를 찾을 수 있는 상황.
	- **라우팅 루프**
		- 네트워크에 변화가 생겼을 때 즉시 라우팅 경로에 반영하지 못하므로 특정 경로에 루프가 생길 수 있음.
	- **무한 세기(infinite counting)**
		- 느린 수렴에 관한 문제 중 하나는 도착할 수 없어진 네트워크를 도착할 수 있다고 착각한 라우터가 엉뚱한 RIP 메시지를 생성하여 라우터 사이에서 계속 주고 받는 것.
		- 이걸 무한 세기 문제라고 함.
	- **작은 무한값**
		- RIP는 느린 수렴 문제를 물이기 위해 무한값으로 작은 값을 사용한다.
		- 네트워크 홉수가 15까지만 사용할 수 있으므로 네트워크 규모에 제한을 받음.
		- 매트릭을 홉수로 제한함에 따라 회선 속도가 같은 다른 정보를 라우팅에 반영할 수 없기 때문에 최적의 경로를 항상 선택할 수는 없다.
- **(바) 해결방안**
	- **Triggered update**
		- 홉수 변경시 즉시 통보하여 복구 시간을 줄임
	- **Hold down**
		- 매트릭이 무한대일시 일정 시간 동안 경로를 갱신하지 않고 전체 네트워크의 경로가 새로 갱신될 때까지 기다림.
	- **Split horizon**
		- 라우터 A가 B를 거쳐 C로 전송하는 경우, B와 C 사이에 장애가 발생한다면 A와 B 사이에서 루프가 발생할 수 있음. 이를 해결하기 위해 A가 B에게 보낸 정보는 다시 A에게 보내지 않음.
	- **Route Posioning**
		- 회선의 고장을 감지하면 즉시 해당 경로의 매트릭을 16으로 지정하여 전체 네트워크에 방송함으로써 도달 불가능을 신속하게 알림.

#### 2) RIPv2
- **(가) 개요**
	- RIPv1의 예약필드를 사용하여 기능을 확장함.
	- 기본동작은 v1과 동일하며 서브넷마스크 식별, 경로정보 인증, AS 구별, 브로드캐스트와 멀티캐스트 전송 등의 기능이 추가됨.
	- 하지만 최대 홉수는 여전히 15로 제한되어 확장성 문제는 여전히 해결하지 못함.
- **(나) 비교**
	- **CIDR과 VLSM의 지원**
		- RIPv2에서는 CIDR과 VLSM을 지원
	- **메시지 전달**
		- 멀티캐스팅도 지원하여 일반 호스트의 물필요한 패킷 프로세싱을 줄임.
	- **인증**
		- 메시지마다 인증이 가능하다.
	- **호환성**
		- RIP-2는 1과 동일한 메시지 포맷을 사용한다.

#### 3) IGRP(Interior Gateway Routing Protocol)
- **(가) 개요**
	- RIP는 홉수 제한으로 대규모 네트워크에는 적용하기가 어려웠고 매트릭으로 홉수만을 사용하기 때문에 네트워크 상태를 적절히 반영하기 어려웠다. 이런 문제점을 해소하고자 시스코에서 제안함.
	- IGRP는 하나의 매트릭 값만을 사용하는 대신 다섯가지의 네트워크 파라미터를 이용하여 거리벡터를 계산한다. 이는 네트워크 상황에 맞게 알고리즘을 적절히 변형할 수 있음을 의미한다.

#### 5) OSPF(Open Shortest Path First)
- **(가) 개요**
	- OSPF는 RIP와 같은 인트라 도메인 라우팅 프로토콜. 하지만 OSPF는 링크 상태 라우팅 프로토콜을 기반으로 함. OSPF는 개방형 프로토콜로 사양이 공개되어 있음.
	- 네트워크에 변화가 생겼을 경우에만 네트워크 전체에 플러딩 과정을 수행함으로써 라우팅 정보를 신속하게 갱신하여 수렴시간, 라우팅 트래픽의 양을 줄임.
	- 최적경로 계산을 위해 다익스트라 알고리즘을 이용함.
	- OSPF는 보안을 위해 인증을 지원하고 세 가지 아이피 주소 형태인 클래스 단위, 서브넷 단위, 클래스 비사용 주소지정을 지원한다. 매우 큰 AS에서 OSPF를 사용할 때는 라우터 그룹으로 묶어 계층 토폴로지를 만들 수 있다.
	- 크거나 성능이 뛰어난 AS에서는 OSPF, 작고 간단한 네트워크는 RIP를 사용하는 것이 일반적.
- **(나) OSPF의 계층 구조**
	- 큰 네트워크를 잘 제어하고 관리할 수 있도록 OSPF에서는 큰 AS가 계층 구조를 가질 수 있음. 계층 구조에서는 연결된 라우터가 네트워크를 영역(Area)으로 묶고, 영역은 논리적 백본을 사용하여 연결된다.
	- 이런 영역은 큰 AS 내에 있는 작은 AS와 비슷하게 행동한다. 따라서 기관에서 큰 네트워크 트래픽을 관리하기 위해 AS를 관리하는 것처럼 영역 내에서 지역적인 제어가 가능함.
	- 라우터의 브로드캐스팅은 영역 내로 제한되어 있어 영역 외부로 라우팅 정보 패킷이 전달되지 않음. 영역 간의 정보 전달은 오직 영역 경계 라우터(Area Border Router)를 통해서만 수행된다.

#### 6) BGP4(Border Gateway Protocol version 4)
- 경계게이트웨이 프로토콜 버전4(BGP4)는 현재 인터넷에서 사용하고 있는 유일한 인터넷 도메인 라우팅 프로토콜.
- 경로 벡터 알고리즘을 기반으로 하고 있지만 인터넷에서 네트워크의 접근성에 대한 정보를 제공하기에 알맞음.
- RIP와 같이 거리벡터에 기초한 알고리즘이지만 패스 벡터 알고리즘에는 홉수 대신 AS 번호를 매트릭으로 사용함.

## 3. 라우터 보안
#### 1) 라우터 개요
#### 2) 라우터 모드
- **(가) 라우터 모드 종류**
	- 유저 모드 : 주로 테스트, 현재 상태를 할 수 있는 제한된 명령어 상태
	- Previleged 모드 : 모든 명령어 이용 가능, 컨픽 파일 조정 가능
	- 구성(Configuration) 모드 : 라우터의 구성 파일을 변경하는 경우에 사용하는 모드.
	- RXBOOT : 라우터의 패스워드를 모르는 경우나 라우터의 이미지 파일(IOS)에 문제가 생긴 경우에 복구를 위해 사용하는 모드. (ROMMON 모드)라고도 하며, ROM Monitor 모드를 줄여서 부르는 말
	- Setup 모드 : 라우터를 처음 구매해서 전원을 키거나 구성파일이 없는 경우 라우터가 부팅하면서 자동으로 들어가는 모드.
	- 구성 모드로 들어가는 명령
		- `Router#config terminal
		- `Router(config)#`
- **(나) 모드 변경 방법**
	- `router>enable` : 사용자 모드에서 특권 모드로 변경
	- `router#disable` : 특권 모드에서 사용자 모드로 변경
	- `router#configure terminal` : 구성 모드로 변경. `conf t`도 가능.
	- `CTRL + Z나 exit` : config 모드에서 빠져나온다.
- **(다) config 모드** 
	- **Configuration**
		- `R1(config)#`
	- **interface**
		- `R1(config-if)#`
		- 특정 인터페이스에 해당하는 명령어를 실행한다.
	- **Subinterface**
		- `R1(config-subif)#`
		- 서브 인터페이스에 대한 명령을 실행한다.
	- **Controller**
		- `R1(config-controller)#`
		- 컨트롤 모드의 설정을 실행한다.
	- **Line**
		- `R1(config-line)#`
		- 라인에 대한 명령을 실행한다.
	- **Router**
		- `R1(config-router)#`
		- 라우팅 프로토콜에 관련된 설정을 실행한다.

```shell
	router(config)#hostname Router-A
	router-A(config)#^z /* Ctrl + z는 한번에 Previleged로 빠져나오고, exit은 단계별로 빠져나옴. */
	router-A#write memory /* 현재 RAM에 있는 구성 파일을 NVRAM(Non Volatile RAM) 에 저장 */
```
- **배너 설정**
	- 꼭 `#`을 써야하는 것은 아니고 배너 창을 연 기호로 끝내면 된다.
```shell
	router(config)# banner motd #
	Enter TEXT message.  End with the character '#'.
	경고: 인가된 관리자만 접속하시오.
	#
	router(config)#
``` 
- **시간 설정**
	- `router(config)#ntp server 시간서버IP`
- **세팅값을 NVRAM에 저장해서 리부팅 시에도 적용**
	- `router#copy running-config startup-config`
- **취소 명령**
	- 구성 모드에서 한 번 입력한 명령을 취소할 때 원래 명령 앞에 no를 입력하면 된다.
	- `router-A(config)#no hostname`
- **interface ip address 변경**
	```shell
	router(config)#interface serial 0 /* 인터페이스 선택 */
	router(config-if)#no ip address  /* 기존 아이피 삭제 */
	router(config-if)#ip address 172.16.4.1 255.255.255.0
	/* 형식은 ip address (아이피) (서브넷 마스크) */
	```

#### 4) 라우터 암호 설정
- 콘솔 패스워드 설정 : 로그인 후 enable을 실행하여 Privileged EXEC 모드로 들어가도록 한다. 이후 설정을 변경하기 위해 conf t를 실행하여 Global Configuration 모드로 들어간 후 콘솔을 지정하여 암호를 재설정하면 된다.
	```
	Router#conf t
	Enter configuration commands, one per line.  End with CNTL/Z.
	Router(config)#line console 0
	Router(config-line)#password ksm008
	Router(config-line)#^Z
	```
- 터미널 패스워드 설정 : 원격 관리를 위한 로그인에 필요한 암호를 Terminal password 또는 Virtual password라고 한다.
	```
	Router#conf t
	Enter configuration commands, one per line. End with CNTL/Z.
	Router(config)#line vty 0 4
	Router(config-line)#password ksm008
	Router(config-line)#^Z
	```
- Enable 패스워드 및 Enable Secret 패스워드 설정
	- Privileged EXEC 모드로 접근하기 위해서는 enable 명령어를 실행하여 암호를 입력해야함.
	- 이때 암호는 enable password 또는 enable secret을 이용할 수 있는데 차이는 암호 저장 방식. 평문이냐 암호화되어 저장되냐...
	- 라우터에 enable secret과 password가 같이 존재하는 경우 항상 secret 값만 확인한다. enable secret이 세팅되어 있지 않은 경우에만 enable password 값을 물어본다.

#### 5) 라우터 자체 보안 설정
- **(가) 기본 접근통제**
	- 암호설정을 통한 접근통제 : 사용자마자 계정, 패스워드를 설정한 수 텔넷을 이용하여 라우터에 접속할 때 계정 및 패스워드를 이용하여 로그인하도록 설정.
	```
	Router#conf t
	Enter configuration commands, one per line. End with CNTL/Z.
	Router(config)#username ksm008 password ksm008
	Router(config)#line vty 0 4
	Router(config-line)#login local
	Router(config-line)#^Z
	```
- IP 주소 필터링을 통해 텔넷 연결을 제한하여 보안을 강화할 수 있음. 특정 아이피의 접속을 허용하고 그 외 접속은 필터링하도록 ACL을 10번으로 생성하고 VTY에 적용한다.
	```
	Router#conf t
	Enter configuration commands, one per line. End with CNTL/Z.
	Router(config)#access-list 10 permit 219.252.48.200
	Router(config)#access-list 10 deny any
	Router(config)#line vty 0 4
	Router(config-line)#access-class 10 in
	Router(config-line)#^Z
	```
- 사용자별 권한 수준 지정 : 시스코 라우터에서는 0과 15단계까지 권한 레벨이 있으므로 사용자별로 권한 수준을 지정하여 보안 강화가 가능함.
	- `Router(config)#username ksm008 privilege 권한레벨 password ****`
