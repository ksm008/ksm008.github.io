## 1. 네트워크 관리
#### 1) 정의
- 네트워크 자원을 관리해서 사용자에게 안정적인 서비스를 제공하기 위함
- 네트워크 상태를 파악하고 장애 발생 시 적절한 제어기능을 수행하여 보고서를 제출하는 등의 행위.

#### 2) 필요성
- 네트워크의 규모가 커지고 이질적인 네트워크가 공존함에 따라 전체 네트워크의 원활한 동작을 위해.
- ISP(인터넷 서비스 제공업자) 사업자들이 인터넷 서비스에 대한 신뢰도를 높이기 위함.

#### 4) 네트워크의 5대 관리 기능
- **계정/구성/성능/장애/보안** 관리 기능을 한다.

## 2. SNMP
#### 1) SNMP 개념
- Simple Network Manager Protocol은 관리자와 에이전트의 개념을 사용함.
- 호스트인 관리자는 라우터나 서버인 에이전트의 집단을 제어하고 감시함.
- SNMP는 관리 대상의 물리적 특성과 하부 네트워크 기술로부터 관리 작업을 분리함. 이는 또는 상이한 제조회사들이 만든 라우터에 의해 연결된 서로 다른 LAN과 WAN으로 구성되는 이질적인 인터넷에서도 사용될 수 있음.
- SNMP 기반 도구
	- **NMS(Network Management System) :** 네트워크 상의 자원들을 모니터링하고 제어하기 위한 도구
	- **MRTG(Multiple Router Traffic Grapher) :** SNMP 기반의 장비 모니터링 프로그램으로 주 용도는 네트워크 트래픽 사용량 모니터링이지만 벤더에서 제공하는 SNMP MIB값을 사용하여 다양한 정보를 수집할 수 있음.

#### 2) 관리자와 에이전트
- 관리는 관리자와 에이전트 간의 간단한 상호작용에 의해 수행됨.
- 에이전트는 데이터 베이스에 성능 정보를 저장하고
- 관리자는 그 값을 데이터베이스에서 읽어감.
- 또한 관리자는 라우터로 하여금 특정한 동작을 행하도록 할 수 있음.

#### 3) 관리 구성요소
- SNMP는 관리를 위해 두 가지 프로토콜, SMI(Structure of Management)와 MIB(Management Information Base)를 사용함.
- 인터넷에서의 관리는 SMI, MIB, 그리고 SNMP의 협동 작업.
- **(가) SNMP의 역할**
	- 관리자와 에이전트 사이에 교환되는 패킷의 형식을 정의함.
	- SNMP 패킷에서 객체(변수)의 상태(값)을 읽고 변경한다.
- **(나) SMI의 역할**
	- 객체에 이름을 붙이고 유형을 정의하며 객체와 값을 부호화하는 방법을 나타내기 위한 일반적인 규칙을 정의함.
	- SMI는 공통된 정보 표현방식을 규정해서 각종 장비 간에도 통신이 이루어 질 수 있도록 함.
	- 하지만 객체와 유형과의 연결은 관여하지 않음.
- **(다) MIB의 역할**
	- 관리될 각 개체를 위해 객체의 수를 결정하고, 이들을 SMI에 의해 정의된 규칙에 따라 이름을 붙이며 이름이 지어진 각 객체에 유형을 연결함.
- **(라) 유사성**
	- 세 관리 요소는 코딩의 각 부분과 유사하다.
		- SMI는 언어 문법을 담당
		- MIB는 선언과 정의를 담당
		- SNMP는 프로그램 코딩을 하는 것과 유사.

#### 4) SNMP 주요 연산
- **(가) 개요**
	- SNMP는 아래를 가능하게 하는 프로그램.
		- 관리자가 에이전트에서 정의된 객체의 값을 읽고 저장함.
		- 에이전트가 비정상적 상황에 대한 경고 메시지를 관리자에게 보냄.
- **(나) PDU(Protocol Data Unit)**
	- SNMPv3는 여덟 유형의 프로토콜 데이터 유닛을 정의한다.
		- **GetRequest**
		- **Get-NextRequest**
		- **GetBulkRequest**
		- **SetRequest**
		- **Response**
		- **Trap**
		- **InformRequest**
		- **Report**
	- **SNMP 데이터 수집 방식**
		- **폴링 방식**
			- 매니저가 에이번트에게 요청하면 에이전트가 UDP 161번 포트를 사용하여 보내줌.
		- **이벤트 리포팅 방식**
			- 에이전트가 이벤트 발생시 매니저에게 Trap 메시지로 알리고 매니저가 UDP 162번 포트를 사용함.
		- 폴링은 에이전트가, 이벤트 리포팅은 매니저가 포트를 사용함.
- **(다) SNMP 메시지 형식**
	- SNMP 메시지는 버전, 커뮤니티, SNMP PDU로 이루어져 있다.
	- 만약 SNMP 메시지 앞에 UDP 헤더가 붙으면 UDP 데이터그램이 된다.
	- 만약 UDP 데이터그램 앞에 IP 헤더가 붙으면 IP 패킷이 된다.
- **(라) 커뮤니티 스트링(Community String)**
	- 커뮤니티 스트링은 매니저가 에이전트로부터 데이터를 요청하기 위해 사용하는 패스워드
	- 서로 다르 접근수준을 가지는 두 가지 주요 커뮤니티 스트링이 존재함.
		- 읽기 전용 스트링 : 매니저가 장치 내의 MIB에 보관되어 있는 데이터를 읽을 수 있음 (public)
		- 읽기쓰기 스트링 : 해당 데이터를 읽고 수정이 가능함. (private)
	- 많은 기업들이 해당 커뮤니티 스트링은 변경하지 않음. 
		- 따라서 UDP 포트 161으로 연결하여 장치의 상태 정보를 읽을 수 있다면 누구라도 장치를 재설정이 가능함.
	- 커뮤니티 스트링이 SNMPv1, v2에서는 평문으로 전송됨. 때문에 도청한 공격자가 쉽게 접근이 가능.
	- v3에서는 암호화 기능을 가지기 때문에 암호화, 메시지 무결성, 인증 보안을 제공함.

## 3. 원격 접속 서비스
### (1) 원격접속 프로토콜
#### 1) TELNET
- **(가) 개요**
	- TErminaL NETwork의 약자.
	- ISO에서 제안된 가상 터미널 서비스에 대한 표준 TCP/IP 프로토콜. 자신의 터미널이 원격 시스템에 있는 터미널처럼 보이도록 원격 시스템과의 연결 설정을 가능하게 함.
- **(나) 원격 로그인**
	- 원격 로그인을 수행해야 하고 이 때 텔넷 클라이언트와 서버 프로그램이 사용됨.

#### 2) RLogin
- Rlogin은 원격지 접속을 지원하는 프로토콜.
- 인터넷 표준은 아니고 BSD 게열 시스템 간의 원격 접속을 위해 설계됨.
- 텔넷에 비해 단순하고 별도의 옵션 협상 기능을 제공하지 않음.

#### 3) SSH(Secure Shell)
- **(가) 개요**
	- 암호화된 원격 터미널 서비스나 파일 송수신 등을 하기 위해 개발된 응용 프로그램이나 프로토콜.
	- TCP 22번 포트를 기본으로 사용하며 평문 송수신 서비스의 취약점을 대체하기 위해 설계됨.
	- 초기 SSH-1은 텔넷과 보안을 제공하지 않는 다른 원격 프로그램 로그인 방식을 대체하기 위해 안전한 원격 로그인을 제공하는데 초점을 맞춤. SSH-2는 초기 방식의 보안 취약점을 수정함.
	- SSH-1은 SSH-2와 호환되지 않음.
- **(나) 컴포넌트**
	-
