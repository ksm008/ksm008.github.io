## 1. 침입차단시스템(방화벽, Firewall) 개요
### (1) 기본 개념
#### 1) 정의
- 모르면 병신

#### 2) 특징
- 방화벽은 접근제어 목록을 통해 네트워크에 전송되는 트래픽에 대한 보안 정책을 설정함.

### (2) 방화벽의 기능 및 역할
#### 1) 개요
- 패스

#### 2) 방화벽의 기능
- **(가) 접근통제**
- **(나) 사용자 인증**
- **(다) 감사 및 로그 기능**
- **(라) 프라이버시 보호**
- **(마) 서비스 통제**
- **(바) 데이터 암호화**

### (3) 방화벽의 한계점, 향후 발전방향
#### 1) 한계
- **(가) 방화벽은 악성 소프트웨어 침투 방어에 한계가 있다.**
	- 패킷 아이피나 포트 번호로 접근제어를 하는게 다여서 바이러스, 웜, XSS 코드 등 문서나 프로그램 내부는 탐지 불가.
- **(나) 방화벽은 악의적인 내부 사용자의 공격을 막을 수 없다.**
	- 내부에서 하면 어쩔건데
- **(다) 방화벽은 자신을 통과하지 않은 통신에 대한 제어 역시 불가능하다.**
	- 방화벽 통신 선로가 아닌 무선, 사설 통신 선로(모뎀)을 통하면 우회가 가능함
- **(라) 방화벽은 전혀 새로운 형태의 공격을 막을 수 없다.**
	- 이미 등록한 정책으로만 방어하기 때문에 능동적 방어가 불가능

#### 2) 향후 발전 방향
- ASIC을 이용한 하드웨어 형태의 장비가 출시됨으로 성능이 크게 개선되고 네트워크 장비와 비슷한 수준의 트래픽 처리 능력을 갖추게 되어 성능문제는 어느정도 해결됨.
- UTM의 등장으로 통합 위협관리 솔루션에는 방화벽 뿐만 아니라 IPS, VPN, 안티 바이러스 등 다양한 보안기능이 하나의 솔루션에 통합되어 복합 해킹 공격 등을 능동적이고 효과적이게 방어 가능.
- **UTM**
	- 다양한 보안 솔루션을 하나의 장비에 탑재하여 운영 가능한 올인원 통합 보안 솔루션.

### (4) 방화벽의 설계 원칙
#### 1) 고려사항
- 어떤 자원을 보호할 것이고
- 위협은 뭐가 있고
- 어떤 사용자를 인증할거고
- 보호해야 할 자원의 중요도는?

#### 2) 설계 원칙
- 디폴트가 허용이면 금지되지 않은 것은 허용되고
- 디폴트가 금지면 허용되지 않은 것은 금지된다
- 사용자는 전자를 선호하고 보안전문가는 후자를 권하는 편
- 방화벽 설치 여부는 리눅스는 `traceroute`, 윈도우에서 `tracert` 명령어를 쓰면 됨.
	- `*` 만 표시된 곳은 라우터에서 필터링 해주고 있거나 방화벽이 존재한다고 생각 가능.

#### 3) 방화벽의 운영 정책
- Deny All
	- 차단 우선, 후 허용
	- 중요 서버의 접속이나 외부에서 내부 망으로의 접속차단 정책.
- Permit All
	- 허용 우선, 후 차단
	- 주로 내부망에서 외부로의 접속차단 정책

## 2. 침입차단시스템의 유형 분류
### (1) 개요
- 크게 2가지로 분류
	- **패킷 필터링 시스템 :** 네트워크/전송 계층에서 수행됨
	- **응용 게이트웨이 방식 :** 응용 계층에서 수행됨
- 패킷 필터링 시스템은 수신된 패킷의 TCP/IP 헤더 부분만을 이용하는 수동적 시스템
- 응용 게이트웨이 방식은 수신된 패킷을 응용 계층의 서비스 단위로 프록시 기능을 이용하는 능동적 시스템

### (2) 패킷 필터링 시스템
#### 1) 기본 개념
- 이 시스템에 사용되는 라우터는 스크린 라우터/ 패킷 필터링 라우터라고도 부름.
- 발신지/목적지 주소, 사용하고 있는 세션과 애플리케이션 프로토콜에 기반하여 데이터의 흐름을 통제함.

#### 2) 패킷 필터링 방법
- **(가) 개요**
	- 패킷의 아이피 주소와 서비스 종류에 대한 정보를 이용하여 설정된 보안 규칙에 의해 내부 네트워크를 보호하는 방법.
	- 사용되는 정보는 아래와 같음.
		- 발신지/목적지 아이피 주소
		- 발신지/목적지 포트 번호
		- 트래픽의 방향(인, 아웃바운드)
		- 프로토콜의 형태(IP, TCP, UDP, IPX 등)
		- 패킷의 상태(SYN 혹은 ACK)
	- 패킷 필터링 방법을 일반적으로 분류하면 아이피 주소에 의해 접속을 통제하는 아이피 주소를 이용한 패킷 필터링 방법과 서비스(포트)를 이용하여 접속을 통제하는 서비스를 이용한 패킷 필터링 방법으로 구분할 수 있음.
- **(나) IP 주소를 이용한 패킷 필터링**
	- 가장 단순한 방법은 프로토콜을 고려하지 않는 것.
	- 패킷 내 아이피 주소만 보고 흐름을 제한한다.
	- 위조된 발신지 주소를 가진 패킷 차단, 외부 호스트가 내부 호스트와 통신하는 것을 허용가능.
	- 하지만 미세한 보안 정책은 수행 불가능.
- **(다) 서비스를 이용한 패킷필터링 방법**
	- 패킷 내의 서비스 포트 번호를 이용하여 필터링을 수행함.
	- 미세한 보안 정책을 수행할 수 있음.

#### 3) 패킷 필터링의 장점
- **단순성**
	- 동작 방식이 간단하다
- **고속처리**
	- 프로토콜의 헤더 정보를 모니터링하여 비교만 하면 되므로 빠름
- **투명성**
	- 사용자는 방화벽의 존재를 알지 못하는 상태에서 보안 서비스 제공 받음

#### 4) 패킷 필터링의 단점
- 정교 제어 불가
- 로그/감사 기능 부족
- 대부분은 사용자 인증 구조 지원하지 않음.
- 네트워크 계층구조 스푸핑 같은 TCP/IP 명세와 프로토콜 스택 안의 문제점을 이용하는 공격 등에 취약함
- 접근제어 결정에 사용하는 변수가 적어 구성을 잘못하면 보안에 허점이 생기기 쉬움.
- 패킷 단편화 공격을 탐지할 수 없음

#### 5) NAT(Network Address Translation)
- **(가) 개요**
	- 패킷 필터링과 상태 유지 방화벽은 NAT라 불리는 제 2의 보안체제를 제공함.
	- 네트워크 주소 변환인 NAT는 사설 주소와 범용 주소의 매핑을 제공함
	- 동시에 가상 사설 네트워크를 지원함.
	- 한 곳에서 내부 통신을 위해 사설 주소를 사용하고 다른 네트워크와의 통신에는 범용 인터넷 주소를 사용할 수 있게 해줌.
	- NAT 소프트웨어를 실행하는 NAT 기능이 있는 라우터를 통해 글로벌 인터넷으로 연결되어야 함.
	- 라우터에 비해 적은 숫자의 유효 아이피 주소만으로도 많은 시스템이 인터넷에 접속할 수 있게 해줌.
	- NAT에서 내부 네트워크와 외부 네트워크는 자연스럽게 두 개의 네트워크로 분리됨.
	- 외부에서 내부 네트워크로 직접적인 접근이 불가능하게 되므로 네트워크 보안 효과를 가져옴.
- **(나) 주소 변환**
	- NAT 라우터를 통해 나가는 모든 패킷은 근원지 주소를 범용 NAT 주소로 변환하고, 외부에서 들어오는 모든 패킷은 범용 NAT주소인 목적지를 적절한 사설 주소로 변환함.
- **(다) 하나의 아이피 주소 사용(Static NAT)**
	- 하나의 내부 주소와 외부 주소를 1:1로 매핑한다.
- **(라) 아이피 주소 풀 사용(Dynamic NAT)**
	- 여러 개의 내부 주소와 하나의 외부 주소를 1대 다로 매핑하여 동적으로 움직임
- **(마) 아이피 주소와 포트 주소 사용(PAT, Port Address Translation)**
	- 하나의 공인 아이피를 다수의 사설 아이피가 포트번호로 구분하여 주소를 매핑한다.

### (3) 스테이트풀 패킷 검사 침입차단시스템
#### 1) 개요
- 패킷 정보를 검토하면서 TCP 연결에 관한 정보를 기록함.
- TCP 순서 번호를 추적하여 순서번호를 이용한 세션 하이재킹 같은 공격을 막음.
- 네트워크/전송 계층에서 동작함.
- 연결이 시작되면 패킷의 모든 계층인 모든 헤더, 페이로드, 트레일러 등을 조사한다.
- **특징**
	- 각각, 그리고 모든 통신 채널을 추적하는 상태 테이블을 관리함.
	- UDP와 ICMP 같은 비연결지향적 프로토콜을 추적하는 데이터를 제공함.
	- 패킷 안의 데이터 상태와 문맥을 갱신하고 저장함.

#### 2) 작동 원리
- 데이터 링크 계층에서 SYN 패킷을 전송받으면 접근제어 정책에 의해 상태 테이블에 남겨놓는 허용 여부를 결정함.
- 금지된 패킷은 로그 저장하고 전송을 수행하지 않음.
- 허용된 패킷은 네트워크 계층으로 전송시킴.
- SYN이 아닐 경우 상태 테이블의 패킷정보 여부를 검사함. 존재하면 네트워크로 전송, 존재하지 않으면 접근제어 정책에 따라 전송여부를 결정함.

#### 3) 장단점
- 패킷 필터링 방화벽과 동일한 성능을 수행하고 패킷 상태 정보에 대한 보안성을 높일 수 있음.
- 네트워크 계층 이하에서 동작하는 Stateful Packet Inspector 모듈을 통하여 전체 계층에 대한 상태를 조사할 수 있으며 사용자의 특별한 설정 없이 투명성을 제공함.
- 하지만 SYN 패킷의 검사를 시작으로 상태 테이블을 유지하기 때문에... 연결 요청의 첫 패킷 헤더가 공격당할 경우 잘못된 상태 테이블을 구성할 수 있음.
- **심층 패킷 검사(deep packet inspection, DPI)**
	- 네트워크 트래픽을 조정하기 위해 쓰는 기술.
	- 데이터 파일을 검토하고 사업상 중요한 파일에 높은 우선순위를 부여하여 덜 중요한 온라인 물질을 정리함.
	- 더 중요한 트래픽이 진행되는 동안 특정 데이터 패킷이 그 목적지로 갈 수 있는지, 막히거나 연기되어야 하는지를 결정함.
	- 기술들은 아래와 같음.
		- 패킷 필터링
		- 애플리케이션 게이트웨이
		- 스테이트풀 인스펙션
		- 딥 패킷 익스펙션

### (4) 프락시 방화벽(Proxy)
#### 1) 프록시 서비스
- 침입차단시스템 호스트에서 실행되는 전문화된 애플리케이션 또는 서버 프로그램으로서 침입차단시스템에 사용되는 배스천호스트에 설치되어 운영됨.
- 서버와 클라이언트를 필요로 함.
- **장점**
	- 가능하면 응용프로그램 계층까지 전체적으로 패킷 안의 정보를 검사함.
	- 패킷 필터링보다는 나은 보안을 제공함.
	- 보호되는 시스템과 보호되지 않는 시스템 사이의 연결을 차단시킴.
- **단점**
	- 몇몇 프록시 방화벽은 제한된 응용프로그램 번호만 지원함
	- 트래픽 성능이 떨어짐
	- 응용프로그램 기반 프록시 방화벽은 확장성과 성능에 대한 논점을 일으킴
	- 클라이언트/서버 모델을 깨뜨리며 보안을 위해서는 바람직하지만 몇몇의 경우 기능상의 단점이 있음.
