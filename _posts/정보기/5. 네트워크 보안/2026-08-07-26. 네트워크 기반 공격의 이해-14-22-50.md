## 1. 네트워크 기반 위협
#### 1) 네트워크를 취약하게 만드는 요인들
- 많은 공격 지점 : 대규모 네트워크에서는 더 많은 취약지점이 존재함.
- 공유 : 공유네트워크로 연결된 시스템들은 더 많은 수의 사용자가 접근할 수 있음.
- 시스템의 복잡성 : 네트워크 운영/제어 시스템은 단일 컴퓨터 시스템을 위한 운영체제보다 훨씬 복잡할 가능성이 높다.

#### 2) 네트워크 위협의 유형
- 물리적 위협과 기술적 위협으로 나뉜다.
	- 기술적 위협은 수동적/능동적 공격으로 나뉜다.
- 수동적 공격은 통신회선상의 정보를 무단으로 취득하는 행위. 통신회선에 제3자의 접속시도를 방지하는 방법과 데이터를 암호화하여 기밀성을 보장하는 방법으로 방어할 수 있음.
	- 스니핑, 도청 등이 이에 해당함.
- 능동적 공격은 통신회선상의 정보를 변조, 위조하는 행위. 암호화와 함께 데이터의 무결성을 확인하는 방법으로 방어 가능.
	- 재전송 공격, 변조, 도스/디도스, 하이재킹 등이 이에 해당한다.

## 2. 네트워크 기반 보안위협 및 대응책
### (1) 서비스 거부공격(DoS)
#### 1) DoS(Denial of Service) 공격의 정의
- 시스템에 과부하를 일으켜 정보 시스템의 사용을 방해하는 방식.
- 정상적인 서비스를 못하도록 방해하는 것. 
- 언제든지 정보를 사용할 수 있어야 하는 가용성을 떨어트리는 것이 목적이다.
- 서비스 거부 공격을 단일 컴퓨터로 하면 DoS, 대규모로 좀비 PC를 사용하여 DoS를 진행하면 DDoS(Distributed Denial of Service)가 된다.
- 소프트웨어 취약점을 이용한 공격(poison 패킷 이용)과 flooding(플러딩) 유형 공격으로 구분 가능.
- **DoS 공격의 다른 분류 기준**
	- 파괴 공격 : 디스크, 데이터, 시스템 파괴
	- 시스템 자원 고갈 공격 : CPU, 메모리, 디스크 사용에 과다한 부하 가중
	- 네트워크 자원 고갈 공격 : 쓰레기 데이터로 네트워크 대역폭 고갈

#### 2) TCP SYN Flooding Attack
- **(가) 개요**
	- SYN Flooding 공격은 TCP 연결 설정 과정 중에 3-Way Handshaking 과정에서 Half-Open 연결 시도가 가능하다는 취약점을 이용한 공격.
	- **Half-Open 연결**
		- 어떤 문제가 발생하여 한 장비가 상대방에게 알리지 않은 채 연결을 닫거나 중지할 때 반개방 연결 상태가 발생한다. 
		- 한 장비는 ESTABLISHED 상태에 머물러 있지만 다른 장비는 CLOSED 상태나 다른 임시 상태에 머무르는 것을 이야기함.
		- 반개방 연결 상태의 예로 한 장비의 소프트웨어가 붕괴되거나 연결 중간에 재시작 시켰다던가, 또는 갑작스런 사고로 두 장비가 동기화 되지 못한 경우를 들 수 있음.
	- 공격대상 시스템은 외부로부터 접속 요청을 더 이상 받아들일 수가 없게 되어 정상적인 서비스를 제공할 수 없게 된다.
	- 다수의 syn 신호를 보내놓고 ack 신호를 반송하지 않으면 공격 대상은 일정시간동안 신호를 기다리게 된다.
	- 이 공격은 윈도우 시스템 뿐만 아니라 인터넷에 연결되어 TCP 기반 서비스(웹, FTP 또는 메일서버 등)를 제공하는 모든 시스템에 피해를 줄 수 있다.

>**시작주소 Spoofing**<br>
>DoS 공격에 사용되는 패킷의 공통된 특징은 조작된 시작 주소지. 이를 시작 주소 스푸핑이라고 한다. 시스템의 네트워크 코드에 마음대로 접근할 수 있다면 조작된 시작 주소를 생성하기는 매우 쉬움. 이는 주로 raw socket interface를 통해서 행해지게 됨. 이 인터페이스는 네트워크를 테스트하거나 프로토콜을 연구하는 목적으로 개발된 것으로 정상 작업에는 전혀 필요하지 않은 기능임.
{: .prompt-info }

- **(나) SYN Flooding Attack 공격 과정**
	1. 공격자는 시작 주소가 위조된 상당히 많은 양의 SYN 메시지를 목적지에 보냄. 이 패킷 각각에 대해서 서버는 정보를 저장하고 다시 SYN+ACK를 조작된 주소로 보낸다.
	2. 만약 SYN 패킷을 송신하지 않은 TCP가 SYN+ACK 패킷을 수신하면 RST 패킷을 회신하여 연결설정 작업중단을 요청하고 RST 패킷을 수신한 서버는 연결설정 과정을 중단하고 연결 테이블의 자료 구조를 해제한다.
	3. 하지만 위조 IP 주소가 너무 바쁘거나 사용하지 않는 주소인경우 RST 패킷이 서버로 회신되지 않고, 서버는 정해진 시간동안 계속 SYN+ACK 패킷을 재전송하며 연결 설정 시도를 반복함.
	4. RST 패킷 수신에 의한 연결설정 작업 중단을 막기 위해 사용하지 않는 IP 주소로 SYN 패킷의 출발지 주소를 위조하는 것이 일반적.
	5. 공격자가 매우 많은 패킷을 목적 시스템에 보내면 그 서버의 TCP 연결 테이블은 꽉 차게 되고 이후 들어오는 연결은 거부된다.
- **(다) 보안대책**
	- 방화벽 또는 DDoS 대응장비를 이용하여 동일 Client(IP)의 연결(SYN) 요청에 대한 임계치(Threshold) 설정을 통해 과도한 연결요청이 발생하는 것을 차단한다. iptables를 이용하면 된다.
	- `iptables -A INPUT -p TCP --dport 80 --syn -m connlimit --connlimit-above 5 -j DROP` : TCP 80포트 연결 요청에 대하여 동일 출발지 IP로 동시 연결 개수가 5개 초과 시 이를 차단한다.
	- Syn_Cookie를 사용하여 대응할 수 있다. 서버에서 클라이언트로 보내는 SYN+ACK 패킷에 임의로 생성되는 시퀀스 넘버 대신 서버에서 암호화 기술을 이용해 인증 정보가 담긴 시퀀스 넘버를 생성하여 클라이언트에 보내는 것.
	- 클라이언트로부터 SYN 패킷을 받더라도 Syn_Cookie만 보내고 세션을 닫아버리기 때문에 애초에 공격이 통하지 않게 된다.
		- 리눅스에서는 `# sysctl -w net.ipv4.tcp_syncookies=1`를 통하여 기능을 활성화할 수 있다.
	- First SYN Drop 설정을 한다. 연결 요청 패킷을 보내는 클라이언트가 실제로 존재하는지 파악하는 방법. 클라이언트로 전송된 첫 SYN은 Drop하여 재요청 패킷이 도착하는지 확인하여 출발지가 위조되었는지 판단함. 대부분의 공격 툴이 다량의 SYN요청을 생성할 뿐 패킷 Drop시 재전송을 수행하지 않는다는 점을 이용한 방법.
	- TCP 연결 테이블(Backlog Queue)엔트리 선택적 삭제 기법은 연결 테이블이 오버플로우가 될 때 일부 엔트리를 삭제함으로써 새로운 SYN 패킷을 처리할 수 있게 만드는 것.
	- 연결 테이블 확장은 연결 테이블에 할당된 메모리를 확장하여 TCP는 SYN 플러딩 공격에 보다 오래 버틸 수 있게 함. 하지만 이 기법들은 정상적인 연결을 삭제할 수 있고 지속 공격에 대한 솔루션이 될 수 없다는 문제점이 있음.
		- 리눅스에서는 `# sysctl -w net.ipv4.tcp_max_syn_backlog = 1024` : TCP Backlog Queue의 크기를 1024로 늘린다.

>**Syn 쿠키 기법**<br>
>- SYN 쿠키 기법은 SYN 패킷을 수신한 서버가 시간정보, 클라이언트 IP 주소, 클라이언트 시작 순서번호, 비밀번호 등을 입력값으로 해시값(Hash Value)을 쿠키로 구한 다음, 이를 서버 시작 순서번호(ISN)로 하는 SYN+ACK 패킷을 클라이언트로 회신한다. 
>- 그리고 이에 대한 정상적인 ACK 패킷을 수신할 때까지 연결 테이블에 자료구조 설정을 미룸. 서버가 사용한 쿠키는 시간정보, 비밀번호 등이 포함되어 재사용하거나 위조할 수 없는 값이므로 서버가 송신한 SYN+ACK 패킷을 정상적으로 수신하지 않은 공격자는 확인번호(ack no)를 추론할 수 없다.  때문에 ACK 패킷을 위조하여 서버에게 전송할 수 없다. 
>- 따라서 위조 SYN 패킷을 수신한 서버는 정상적인 ACK 패킷을 수신하지 않게 되어 위조 SYN 패킷에 의한 연결 테이블의 자원이 소진되는 현상을 방지할 수 있게 되는 것.
{: .prompt-info }

#### 3) SMUFT Attack(스머프 공격)
- **(가) 개요**
	- @everyone으로 언급한다음 이 새끼가 그랬어요 하고 거짓말하는거	
	- 광범위한 효과로 도스 공격 중 가장 피해가 그고 인기 있는 공격 형태 중 하나.
	- IP 위장과 ICMP의 특징을 이용한 공격.
	- 공격자가 출발지 IP 주소를 목표 시스템으로 스푸핑하고 목적지 주소를 직접 브로드캐스트 주소로 설정한 다음 Ping 메시지지를 송신하고, Ping 메시지를 수신한 네트워크의 모든 시스템이 Ping 응답 메시지를 출발지 IP 주소로 전송함으로 공격 목표를 마비시킴.
	- 직접적인 ICMP 브로드캐스트와 세가지 구성 요소인 공격자, 증폭 네트워크 공격대상 서버(표적)을 이용한다.
	- **직접 브로트캐스트 주소(Directed Broadcast)**
		- IP 주소의 네트워크 ID는 특정 네트워크 주소 정보를 가지고, 호스트 ID의 모든 비트는 1로 설정된 주소.
	- **증폭 네트워크(Amplifier Network)**
		- ICMP Echo Request 브로드캐스트 메시지를 받아서 희생자(Target)에게 다수의/증폭된 ICMP Echo Reply를 전송하는 네트워크를 말한다.
	- **Fraggle Attack**
		- ICMP 대신 UDP를 사용함. 위장된 희생자의 IP 주소로 브로드캐스팅을 함. 호스트는 수많은 네트워크의 응답으로 시스템상의 문제를 일으키게 된다.
- **(나) 공격방법**
	- 공격자는 IP를 공격대상 서버의 IP주소로 위장하여 ICMP를 브로드캐스트로 다수의 시스템에 전송한다.
	- ICMP를 수신한 다수의 시스템은 ICMP Echo 패킷을 공격자가 아닌 공격대상 서버로 전송하게 됨.
	- 대상서버는 다수의 ICMP Echo를 수신하게 되어 시스템 성능에 문제를 일으키게 됨.
	- 이때 다수의 시스템은 브로드캐스트에 대한 응답으로 다수의 ICMP Echo 패킷을 발생시키기 때문에 증폭 네트워크라고 불리게 됨.
	- **Amplification Attack(증폭 공격)**
		- Amplification 공격에 의해 대상시스템을 겨낭하도록 조작된 시작 주소를 가진 패킷들이 중계시스템에 보내진다. Smurf, Fraggle이라는 프로그램도 이 방법을 사용했음.
- **(다) 보안대책**
	- 중간매개지로 쓰이는 것을 막기 위해 라우터에서 다른 네트워크로부터 자신의 네트워크로 들어오는 IP directed broadcast 패킷을 막도록 설정한다.
	- 호스트는 IP broadcast address로 전송된 ICMP 패킷에 대해 응답하지 않도록 시스템을 설정할 수 있다.
	- 동일한 ICMP Echo Reply 패킷이 다량으로 발생한다면 해당 패킷들을 침입차단 시스템을 통해 모두 차단시킴.

#### 4) LAND Attack
- **(가) 개요**
	- 시스템을 나쁜 상태에 빠지게 하는 공격이다. 
	- 자기가 자기 자신에게 계속해서 요청과 응답을 하게 만들어 버리는 것.
	- 패킷을 전송할 때 출발지 IP 주소와 목적지 IP 주소 값을 똑같이 만들어서 공격 대상에 보내는 것. 이 때 조작된 IP 주소값은 공격 대상의 IP 주소.
	- SYN Flooding처럼 동시 사용자 수를 증가시키며, CPU에도 부하를 주게 된다.
- **(나) 보안대책**
	- **탐지방법**
		- 공격자가 보낸 패킷의 TCP를 분석
		- TCP 패킷의 소스 IP, 포트와 목적지 IP, 포트가 동일한지 확인한다. (소스 주소가 내부 IP인 패킷을 차단한다.)
		- 공격자가 보내는 패킷을 카운트하여 공격인정 시간 내에 공격인정 횟수가 많으면 LAND Attack으로 간주함.
	- **조치방법**
		- 라우터나 패킷 필터링 도구를 이용하여 자신의 시스템 주소와 동일한 소스 주소를 가진 외부 패킷을 필터링함.
		- 공격정보를 네트워크, 시스템 관리자에게 알림으로써 관리자가 침입차단시스템에서 소스 아이피/포트와 목적지 아이피/포트와 동일하면 차단하도록 설정함.

#### 5) Ping of Death
- **(가) 개요**
	- 공격의 기본은 ping을 이용하여 ICMP 패킷을 정상 크기보다 아주 크게 만드는 것. 정상 크기는 65,535 바이트

#### 6) Teardrop Attack

### (2) DDoS 공격
#### 1) DDoS 공격 발전형태
- **(가) 1999년~**

- **(나) 2005년~**

- **(다) 현재**
	- 대응시스템을 우회, 압도하기 위한 고도화된 디도스 공격 유형이 등장함. 
		- 스마트 어택, Memcached Reflection Attack, Carpet Bombing 등 
		- **스마트 어택**
			- 그냥 더 정교하고 고도화된 디도스	
		- **카펫 바밍**
			- 같은 대역대의 여러 아이피로 트래픽을 분산시켜 공격하는 방식. 공격 유무 판별, 대상 식별이 어려움.
	- **랜섬 디도스**가 등장함. 디도스 공격 협박을 통해 돈을 갈취함.

#### 2) DDoS 공격 개요
- 다수의 서버, 피씨를 이용해 비정상적인 트래픽을 유발시켜서 대상 시스템을 마비시키는 공격 행위.
- 공격자는 취약한 서버를 공격하여 악성코드를 배포하고, 유포지/경유지 서버에서 악성코드를 내려 받은 서버/기기들을 이용하여 봇넷을 구축.
- 공격자는 봇넷에 명령을 전달하여 대규모의 트래픽을 유발시키거나 취약한 서버를 악용하여 반사공격을 수행함. 이 때 공격자의 위치나 구체적인 발원지를 파악하는 일은 거의 불가능에 가까움.
- **봇넷**
	- 악성코드 등에 의해 감염된 피해 PC, IoT 기기, 서버들로 구성된 네트워크 집단으로 주로 공격자의 공격 도구로 사용됨.

#### 3) 구성 요소
- 공격자 : 마스터 서버에서 공격 명령을 내리는 사람
- 마스터 / C&C 서버 : 공격자의 직접 명령을 받은 시스템. 여러 대의 에이전트를 관리.
- 핸들러 프로그램 : 마스터 시스템의 역할을 수행하는 프로그램
- 에이전트 : 공격 대상에 직접적인 공격을 가하는 시스템. 악성코드에 감염된 시스템이다. 슬레이브, 좀비라고도 함.
- 데몬 프로그램 : 에이전트 시스템 역할을 수행하는 프로그램.
- 표적 : 공격 대상.

#### 4) 봇, 봇넷
- **(가) 개요**

#### 5) 전통적인 디도스 공격
- **(가) 트리누(Trinoo) 공격**
	- 많은 호스트로부터 통합된 UDP flood 서비스 거부 공격을 유발하는데 사용된 도구. 몇 개의 서버와 많은 수의 클라이언트로 이루어짐.
- **(나) TFN(Tribed Flood Network) 공격**
	- 트리누와 거의 유사한 분산 서비스 거부 도구. 많은 소스에서 하나, 혹은 여러개의 목표 시스템에 대해 서비스 거부 공격을 수행함. (Trinoo의 약간 발전된 형태로 믹스터(Mixter)라는 사람이 개발)
	- TFN은 UDP flood 공격을 할 수 있을 뿐만 아니라 TCP SYN flood 공격, ICMP echo 요청 공격, ICMP 브로드캐스트 공격(smurf 공격)을 할 수도 있다.
- **(다) Stacheldraht 공격**
	- Stacheldraht는 철조망이라는 뜻. 
	- 트리누와 TFN을 참고하여 제작된 도구. 마스터 시스템 및 자동적으로 업데이트되는 에이전트 데몬과의 사이에 통신을 할 때 암호화하는 기능이 추가되었다.
- **(라) TFN2K 공격**
	- TFN의 발전된 형태.
	- 통신에 특정 포트가 사용되지 않고 암호화되어있고, 프로그램에 의해 UDP, TCP, ICMP가 복잡적으로 사용되며 포트도 임의로 결정된다.
	- 지정된 TCP 포트에 백도어를 실행시킬 수 있다.

#### 7) 최신 DDoS 공격유형
- **(가) 대역폭 공격(1) - UDP, ICMP Flooding**
	- **UDP Flooding**
		- 출발지 아이피를 위/변조한 후 UDP 프로토콜로 대규모 데이터를 생성하여 피해 대상 시스템을 향해 전달한다. 대상 서버에서 UDP 포트를 사용하지 않아도 공격이 가능하고 공격을 수행하는 감염된 기기가 많을수록 위험도가 증가함.
		- 단순한 공격방식, 강력한 효과로 현재도 많이 사용되는 방식.
	- **ICMP Flooding**
		- ICMP Request 패킷을 이용하여 피해서버로 대량의 ICMP 패킷을 생성해 전달하여 피해서버의 대역폭을 고갈시키는 공격방식이다. 반사공격과 다르게 ICMP Flooding은 증폭이 발생하지 않기 때문에 공격기기의 대역폭에 따라 공격 규모가 결정됨.
- **(나) 대역폭 공격(2) - DRDoS(Distributed Reflection Denial of Service)**
	- **DRDoS 개요**
		- 별도의 에어진트 설치 없이 프로토콜 구조의 취약점을 이용해 정상적인 서비스를 운영하는 시스템을 분산 반사 서비스 거부 공격의 에이전트로 활용하여 공격함.
		- 다양한 형태로 나타날 수 있음. 
			1. TCP의 연결설정과정인 3-웨이-핸드셰이크의 취약점을 이용한다. 위조된 주소의 syn 요청을 반사서버로 전달하여 Echo Reply가 공격대상으로 향하도록 하는 방법.
			2. ICMP 프로토콜의 Echo Request와 Echo Reply를 이용. 위조된 주소의 Echo Request를 반사 서버로 전달하여 Echo Reply가 공격대상으로 향하도록 하는 방법.
			3. UDP 프로토콜 서비스를 제공하는 서버를 반사서버로 이용하여 그 응답이 공격 대상으로 향하도록 하는 방법.
		- UDP 프로토콜을 사용하는 DNS, NTP, SNMP, CHARGEN 등의 서비스를 이용한 DRDoS 공격은 크게 반사와 증폭 공격 형태로 나타난다.
	- **DRDoS 공격의 위협요소(일반 DDoS 공격과의 차이점)**
		- 분사 반사 서비스 거부 공격이 분산 서비스 거부 공격보다 위협적인 이유는 아래와 같다.
			1. 패킷이 전송되는 경로가 무수히 많음. 공격자가 전송한 위조 SYN 패킷은 즉시 흩어지게 되는데, 직접 공격 시스템이나 네트워크로 향하는 것이 아닌 네트워크에 연결된 수많은 TCP 반사 서버로 보내지게 됨.
			2. 반사 서버의 단계적 사용 및 확산이다. 엄청난 양의 반사 서버 목록을 보유하고 있다면 공격 초기에는 일부분을 사용하여 공격대상 서버에 지속적으로 집중적인 패킷을 전송할 수 있다. 그리고 점차 반사 서버를 추가함으로써 공격 경로를 끊임없이 변경할 수 있다.
			3. 위조 SYN 패킷 근원지의 IP를 랜덤으로 생성하는 전통적인 분산 서비스 공격 방법과 다르게 공격대상 IP를 근원지의 IP로 위조하여 전송하기 때문에 역추적하기 쉽지 않다.
	- **DRDoS 공격 종류**
		- **DNS Reflection Attack**
			- 공격자가 피해자의 IP로 위장(스푸핑)하여 네임서버에 비정상 DNS 질의를 요청하고, 요청을 받은 네임서버는 DNS 응답값을 위장한 IP로 전송하여 공격대상의 회선 대역폭을 고갈시키는 공격.
			- 공격 트래픽 양을 높이기 위해 단순 DNS Query가 아닌 Zone의 모든 정보를 요청하는 Any Type 레코드를 요청하는 특징이 있다.
			- DNS 서버가 악용되지 않도록 하기 위해서는 아래 사항을 점검해야 한다.
				- 공개용이 아닌 내부자용 DNS(Resolving)서버라면 서버 설정을 통해 내부 사용자 주소만 Recursive Query가 가능하도록 제한한다.
				- 서버 방화벽(iptables 등) 또는 네트워크 보안 장비를 통해서 특정 byte 이상의 DNS 질의에 대한 응답을 차단하거나 동일 IP에 대해 단위 초당 요청 개수 제한(limit 설정)을 설정한다.
		- **NTP Reflection Attack**
			- 시간동기화를 위해 사용되는 NTP(Network Time Protocol) 서버를 반사서버로 악용한 공격.
			- NTP서버에 가능한 많은 응답 패킷을 만들어 내기 위해 monlist를 요청하는 비정상 패킷을 보내서 응답값을 공격 payload로 활용하는 공격 유형.
			- **monlist**
				- 최근 접속한 최대 600개의 접속 호스트에 대한 정보룰 응답 받을 수 있는 명령어로 v2.4.7 이상에서는 해당 명령어가 삭제됨.
			- **payload**
				- 통신 패킷에서 헤더나 메타데이터를 제외한 본문 데이터에 해당하는 부분.
		- **CLDAP Reflection Attack**
			- CLDAP(Connection-less Lightweight Directory Access Protocol)이란 네트워크상에서 디렉터리를 연결/검색/수정하기 위해 사용되는 프로토콜.
			- CLDAP Reflection Attack은 CLDAP 서버를 반사서버로 악용한 공격. 
			- CLDAP Reflection Attack 패킷은 UDP 프로토콜을 사용하며 389번을 출발지 포트로 사용.
		- **SSDP Reflection Attack**
			- SSDP는 UPnP(Universal Plug and Play) 장치를 탐색할 때 주로 사용되는 프로토콜로서 네트워크 상의 다른 장치를 찾거나 알리는 역할을 수행함. 웹캠, 공유기, 미디어, 스마트TV 등을 구성하는 IoT 기기들에 널리 사용됨.
			- SSDP 기능을 악용하여 가능한 많은 Search 명령을 보내어 공격함.
		- **Memcached Attack**
			- Memcached 서비스는 내부에서 DB 부하감소 및 응답속도 증가를 위해 분산된 메모리에 데이터를 캐싱하는 서비스. 내부에서만 접근하여 사용하도록 설계되었으며 Key 값으로 Data를 매핑하는 구조.
			- 저장된 캐싱 데이터를 가능한 한 많이 요청하는 request 명령을 요청하고 스푸핑된 피해자의 IP로 대규모 응답이 가게 만드는 공격기법.
		- **CoAP Reflection Attack**
			- CoAP/Constrained Application Protocol이란 IoT 기기들을 위해 사용되는 프로토콜의 일종. 저전력 컴퓨터들을 위해 만들어진 간단한 UDP 프로토콜. HTTP 형식과 유사하며 5683번 포트를 사용.
			- **CoAP(코앱)**
				- REST 기반의 경량 메시지 전송 프로토콜.
- **(다) 자원 소진 공격**
	- **SYN Flooding** 
		- TCP의 3방향핸드셰이크 악용한 공격기법. SFN Flag만 지속적으로 전달하고 돌아오는 SYN/ACK 응답을 주지 않아서 피해 서버의 자원을 소모하게 만듬.
			- bps에 비해 높은 pps를 보이는 것이 특징. 대역폭 공격과 다르게 대규모의 트래픽을 발생시키지 않아도 서비스 접속불가를 유도할 수 있다.
	- **ACK Flooding**
		- SYN Flooding과 비슷하다. 다량의 ACK Packet을 피해대상에게 보내서 자원을 소모하게 만든다.
	- **DNS Query Flooding**
		- DNS Query Flooding은 DNS 서버에 대량의 DNS 질의를 보내서 정상 서비스를 할 수 없게 만드는 공격이다.

>**UDP 서비스를 이용한 DRDoS 공격 유형**<br>
>- DNS 증폭 DRDoS 공격 : DNS 서버(반사서버)에 많은 양의 레코드 정보를 요구하는 DNS 질의 타입(ANY, TXT등)을 요청하여 공격 대상에게 대량의 트래픽 증폭을 유발시킴.
>- NTP 증폭 DRDoS 공격 : NTP서버(반사서버)에 최근 접속한 클라이언트 목록(monlist 명령)을 요청하여 대량의 응답 트래픽(증폭)을 유발시킨다.
>- SNMP 증폭 : SNMP agent에 MIB와 같은 정보를 대량 요청(GetBulkRequest)하여 공격 대상자에게 대량 트래픽을 유발시킨다.
>- CHARGEN 증폭 : CHARGEN 서버에 접속 시 대량의 문자열을 전송하여 공격대상자에게 대량 트래픽을 유발시킴.

- **(라) 웹/DB 부하공격**
	- **GET Flooding**
		- TCP... 3방향핸드셰이크... HTTP GET 메소드 요청을 통해 웹 서버 자원 소진
		- 동시에 DB서버 자원도 소진시켜 정상 웹 서비스 이용 차단시킴
	- **Slowloris Attack(Slow HTTP Header DoS)**
		- GET Flooding에 비해 규모가 작음. 단 기간에 폭발적으로 요청하는 것이 아닌 오랜 시간 동안 지속적으로 공격을 수행함.
		- 정상적인 HTTP 패킷의 헤더에는 캐리지 리턴 & 라인 피드가 2번 나타난다. 첫 개행 문자는 헤더의 종료, 두 번째 개행 문자는 전체 헤더의 종료를 의미함.
		- 만약 헤더의 마지막에 개행 문자를 하나만 전송하면 웹 서버는 헤더가 모두 도착하지 않은걸로 간주하고 연결을 유지한다. 그러면 대기 상태가 유지되어 서버의 자원을 잠식하게 된다.
	- **RUDY Attack(Slow HTTP POST DoS)**
		- POST Method를 이용하는 대표적인 Slow 공격유형이다.
		- POST 요청은 전달할 데이터의 크기를 Content-Length 헤더에 삽입하여 보내게 되는데 이 크기를 매우 크게 설정한 후 서버로 전달할 데이터를 장시간에 걸쳐 조금씩 분할하여 전달하게 함.
	- **Slow read Attack(Slow HTTP Read DoS)**
		- TCP 통신에서 사용되는 windows size를 악용한 공격기법. 클라이언트마다 한 번에 처리할 수 있는 패킷의 크기가 다르기 때문에 해당 크기를 windows size 필드를 통해 전달하며 windows size를 기준으로 패킷을 주고 받음
		- 이 공격은 windows size를 낮게 설정하여 서버로 전달하고, 해당 사이즈를 기준으로 통신하면서 데이터 전송이 완료될 때까지 연결을 유지하게 만들어 연결 자원을 고갈시킨다.
	- **GET Flooding with Cache-Control(CC Attack)**
		- 일반적으로 웹서버의 부하를 감소시키기 위해 캐싱서버를 운영하여 많이 요청받는 데이터를 웹 서버가 아닌 캐싱서버를 통해 응답하도록 구축함.
		- 공격자는 HTTP 메시지의 캐시 옵션을 조작하여 캐싱서버가 아닌 웹 서버가 직접 처리하도록 유도하여 캐싱서버의 기능을 무력화시키고 웹 서버 자원을 소진시킴.
		- **Cache-Control 헤더**
			- HTTP의 요청이나 응답에 대한 캐싱을 수행하는 방법을 관리하는 지시어. 장비가 수행하는 기본 캐싱 동작을 변경함. CC Attack에서는 no-store, must-revalidate로 변경한다.
	- **동적 HTTP Request Flooding 공격**
		- GET Flooding이나 CC 공격은 지정된 웹 페이지를 지속적으로 공격한다. 이 두 공격은 웹 방화벽을 통해 특징적인 HTTP 요청 패턴을 방어할 수 있음.
		- 요청 페이지를 지속적으로 변경하여 웹 페이지를 동적으로 요청할 수 있음.
	- **기타 서비스 마비 공격**
		- **해시도스(HashDoS) 공격**
			- 웹 서버는 클라이언트로부터 전달받는 HTTP 메시지의 매개정보, 즉 파라미터를 관리하기 위해 해시테이블을 사용한다.
			- 조작된 매개정보를 포함한 다량의 메시지는 해시테이블의 검색을 위한 인덱스로 사용된다. 여기서 해시값에 충돌을 발생시켜 정확한 값을 찾기 위해 모든 해시테이블을 검사하게 되고 CPU 자원을 소진하게 되어 정상적인 서비스를 방해한다.
		- **헐크도스(HulkDoS) 공격**
			- 웹서버의 가용량을 모두 사용하도록 만드는 GET Flooding 공격 유형.
			- 공격대상 웹사이트 주소 URL을 지속적으로 변경하여 DDoS 차단 정책을 우회하는 특징을 가진다.

>**SIP Flood**<br>
>VoIP 전화연결에서 많이 사용하는 프로토콜을 Session Initiation Protocol(SIP)이라고 함. SIP flood 공격은 하나의 INVITE request를 가짜 시작주소에 넣어 보내거나 혹은 봇넷을 이용한 DDoS를 통해서 보냄. 이 공격은 SIP 프록시 서버에 부담을 주게 된다. 연속된 INVITE request를 처리하면서 서버가 자원을 소진하게 되고, 두 번째로 네트워크의 용량이 차게 된다. 전화를 받는 수신자도 희생감이다. 수신자의 시스템은 연속되는 가짜 전화로 부담이 가기 때문에 정상적인 전화를 받을 수 없게 됨.

			- 평상시 발생하는 기본 트래픽(bps, pps, 동시접속수) 정보를 인지하고 이상 트래픽의 발생을 주기적으로 모니터링 해야함.
		- **화이트리스트 방식의 방화벽 설정**
			- 필요한 서비스에 대한 최소한의 정책만 열고 모든 프로토콜과 포트는 차단하는 설정을 통해 기타 포트로 들어오는 공격에 대한 방어가 가능함.
			- 단, 서비스하고 이는 모든 포트에 대한 정보를 알고 있어야 함.
		- **서버 분산을 통한 가용성 확보**
			- Load Balancer를 이용하여 서버 부하를 분산함으로써 서버 장애를 최소화할 수 있다.
	- **디도스 대응서비스를 통한 방어 준비**
		- 0단계 - 사전준비
			- 서비스 알아봐라
		- 1단계 - 공격인지
			- 우리 문제인지 아님 공격이 들어오는건지 파악
		- 2단계 - 공격 정보 파악
			- 만약 디도스 공격이 들어오면 뭔 공격인지 파악부터.
			- **대역폭 공격**
				- bps, pps가 평소보다 높지만 동시접속수는 변동이 없음.
				- UDP는 연결을 맺지 않고 트래픽만 발생시키기 때문.
			- **자원 소진 공격**
				- bps는 높지 않지만 pps가 높음.
				- 정확한 공격 식별을 위해 네트워크 트래픽 분석 툴인 wireshark나 tcpdump를 사용.
			- **웹/데이터베이스 부하 공격**
				- 다량의 HTTP 요청을 통해 웹서버와 DB 서버 연동에 부하를 유발하여 연결 수치가 높음.
				- Connection 수가 급증하면 wireshark, 웹서버의 Access Log 등을 확인하여 원인을 파악하기.
		- 3단계 - 방어서비스 적용
		- 4단계 - 서비스 모니터링
		- 5단계 - 사후 조치

### (3) 네트워크 스캐닝
#### 1) 사이버 공격을 위한 준비활동
- 정보 수집은 풋프린팅, 스캐닝, 목록화 3단계를 거침
- 풋프린팅은 정보 수집 초기
- 스캐닝은 핑, 포트 스캔, 운영체제 확인 등으로 더 세부적인 정보를 수집하는 과정
- 목록화는 수집한 정보를 토대로 라우팅 테이블이나 SNMP 같은 더 실용적인 정보를 수집하여 시스템 취약점 분석 및 공격 방법 결정을 위한 지표로 작성하는 과정.

#### 2) 풋 프린팅
- 공격자가 공격대상에 대한 다양한 정보를 수집하기 위해 널리 사용하는 방법 중 하나.
- 사회공학기법이 일반적. 비밀번호 등을 수첩, 메모지에 적어두면 가로채어 정보를 수집하는 방법.
- 공격 대상이 스스로 공개한 여러가지 정보를 풋 프린팅하여 공격대상의 IP 블록, 사용자 이름 및 계정, 전화번호 등과 같은 정보들을 수집.

#### 3) 스캔 공격 분류
- **(가) 스캐닝 기본 개념**
	- 네트워크나 시스템 주변조사를 수행하는 풋 프린팅과는 달리 실제 공격방법을 결정하거나 공격에 이용될 수 있는 네트워크 주소, 시스템이 제공하는 서비스 등의 정보를 얻기 위해 수행되는 방법.
	- 공격자는 스캐닝을 통해 대상의 네트워크 보안장비 사용 현황, 우회 가능 네트워크 구조, 해당 네트워크 내의 시스템 플랫폼 형태, 시스템 운영체제의 커널 버전 종류, 제공 서비스 종류 등 다양한 정보를 알 수 있다.
- **(나) 포트 스캔 분류**
	- 기법은 Sweep, Open Scan, Stealth Scan, Security Scan으로 분류 가능.
	- Sweep은 네트워크 구조를 조사하기 위해 존재하는 시스템에 대한 작동 유무를 검사함.
	- Open Scan은 시스템에서 제공하는 서비스를 확인하기 위해 사용됨. 
	- Stealth Scan은 Sweep과 Open Scan에서 공격자의 노출이 되는 단점을 보완하고 보안장비에 대한 우회기능이 추가된 기법.

#### 4) 포트 스캔 공격 종류
- **(가) Sweep** 
	- **개요**
		- Sweep은 특정 네트워크에 대하여 해당 네트워크에 속해있는 시스템의 작동 유무를 판단할 수 있는 기법. 
		- 목표 대상 기관에서 사용, 소유하는 IP 주소와 네트워크 범위를 알아낼 수 있음.
		- 요청에 의한 응답을 수행하는 클라이언트/서버 구조를 기반으로 하고 있으며 동작은 요청에 대한 응답 여부를 판단하는 방법을 사용함.
		- Sweep의 종류에는 사용하는 프로토콜에 따라 ICMP, TCP, UDP Sweep이 있음.
- **(나) Open 스캔**
	- **개요**
		- Open 스캔은 시스템 자체 활성화 여부를 더해 스캔하는 포트에 해당하는 서비스 활성화 여부를 조사할 수 있는 방법.
		- 포트를 스캔하여 포트가 열려있다면 해당 시스템이 활성화 되어 있는 것으로 판단할 수 있을 뿐 아니라 해당 포트가 제공하는 서비스를 예측할 수 있다.
		- Open 스캔 방법은 사용하는 프로토콜에 따라 TCP, UDP 스캔 기법으로 나뉨. 둘 다 스캔하려고 하는 목적 포트로 연결을 시도 후 응답 형태를 보고 활성화 여부를 판단함.
	- **TCP Scan**
		- 연결 완료 여부에 따라 Full Open Scan과 Half Open 스캔으로 나뉨.
		- **Full Open Scan(TCP Connect Scan)**
			- 포트가 열려있는 경우 대상시스템으로부터 SYN/ACK 패킷을 수신하면 그에 대한 ACK 패킷을 전송함으로 연결을 완료함.
			- 포트가 닫혀있을 경우 대상 시스템이 연결 요청을 받아들이지 못하므로 RST/ACK 패킷을 전송한다.
			- 포트에 접속을 시도해 완전한 TCP 연결을 맺어 신롸성 있는 결과를 얻을 수 있으나 속도가 느리고 로그를 남겨 탐지가 가능하다.
		- **Half Open Scan(TCP SYN Scan)**
			- 로그를 남기지 않아 추적이 불가능하도록 하는 기법.
			- 세션을 완전히 연결하지 않고 반 연결로만 포트 활성화 여부를 판단함.
			- SYN/ACK 패킷을 받으면 즉시 RST 패킷을 보내 연결을 끊어 연결 시도 세션에 대한 로그를 남기지 않도록 함.
			- 하지만 SYN 세그먼트 전송기록은 남게 되므로 스캐닝 공격 사실을 완전히 숨길순 없음.
	- **UDP Scan**
		- UDP는 연결없이 송수신을 진행하기 때문에 ICMP Port Unreachable 에러 메시지를 통해 포트의 활성화 유무를 확인한다. 
		- 아무런 응답이 없으면 해당 포트의 활성화를 의미함.
		- 하지만 UDP 패킷은 네트워크를 통해 전달되는 동안 라우터나 방화벽에 의해 손실될 수 있기 때문에 해당 포트 스캔은 신뢰하기 어렵다.
- **(다) Stealth 스캔**
	- **개요**
		- 핸드셰이킹 연결 기법을 사용하는게 아니라 TCP 헤더를 조작하여 특수한 패킷을 만든 후 스캔 대상 시스템에 보내 그 응답으로 포트 활성화 여부를 알아내는 기법.
		- TCP FIN/ACK/단편화 스캔 등이 있다.
		- 세션을 완전히 성립하지 않고 포트 활성화 여부를 알아내기 때문에 로그도 남지 않는다. 관리자는 어떤 아이피를 가진 공격자가 자신의 시스템을 스캔했는지 확인불가.
	- **FIN, NULL, XMAS 스캔**
		- TCP FIN(Finish) 스캔은 TCP 헤더 내에 FIN 플래그(Flag)를 설정하여 공격대상 시스템으로 메시지를 전송하면 스캔 대상 시스템의 포트가 열려 있을 경우에는 응답이 없고, 포트가 닫혀있는 경우에만 RST(reset) 패킷이 되돌아오게 됨.
		- NULL과 XMAS 패킷을 전송하는 경우에도 이와 같은 결과를 얻을 수 있다. NULL 패킷은 TCP 헤더 내에 ACK, FIN, RST, SYN, URG 플래그를 모두 설정하여 전송하는 패킷. 
		- 이렇게 설정하여 전송한 두 패킷 역시 포트가 열려 있을 때는 응답이 없고, 포트가 닫혀있을 경우에만 RST 패킷이 돌아온다.
	- **TCP ACK 스캔**
		- 포트 오픈 여부가 아닌 방화벽의 룰셋을 테스트하기 위한 스캔.
			- 대상 방화벽이 상태 기반(Stateful)인지, 대상 포트가 방화벽에 의해 필터링 되고 있는지 여부
	- **Decoy 스캔**
		- Decoy는 유인한다는 의미. 미끼... 
		- 스캔을 당하는 대상 호스트에서 스캐너 주소를 식별하기 어렵도록 실제 스캐너 주소 외에 다양한 위조된 주소로 스캔하는 방식을 말함.
		- 다양한 IP로 스캐너 주소를 위조하여 관리자가 스캔을 누가 하는지 어렵게 함.
	- **FTP 바운스 스캔**
		- 현재는 잘 사용하지 않는다.
		- 취약한 FTP 서버에서 PORT 명령어를 통해 다른 시스템의 포트 활성화 여부를 확인할 수 있는데, 이 방법은 방화벽에 취약한 FTP 서버가 있을 때 유용하다.
		- 하지만 정작 이런 취약점이 존재하는 FTP 서버가 없다...
	- **정리**
		- **TCP Connect** : TCP 세션 수립 여부 확인
		- **TCP Half Open(SYN Scan)** : SYN 패킷만 전송하여 연결 요청만. 세션 수립 없음
		- **TCP ACK 스캔** : TCP ACK 플래그를 ON으로 설정하여 패킷 송신
		- **TCP FIN 스캔 :** FIN 플래그 ON
		- **TCP Null 스캔 :** 모든 플래그를 OFF
		- **Xmas 트리 스캔 :** 모든 플래그를 ON
		- **UDP 스캔 :** UDP 패킷을 송신하는 방법

#### 5) 대표적인 스캔 도구
- **(가) NMAP(Network Mapper)**
	- 모든 운영체제에서 사용 가능한 스캔 도구. 
	- 운영체제의 종류, 사용 서비스에 대한 정보, FTP 서버의 취약점을 이용한 bounce 공격을 수행할 수 있는 스캔 도구.
	- 프로그램 소스를 공개하여 많은 사용자들이 직접 소스를 업그레이드도 가능. 최근에는 윈도우용 GUI도 지원.
	- **사용법**
		- `nmap [scan type] [options] <target>`
		-
