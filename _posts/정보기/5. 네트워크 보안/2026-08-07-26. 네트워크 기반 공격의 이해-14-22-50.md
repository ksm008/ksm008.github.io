## 1. 네트워크 기반 위협
#### 1) 네트워크를 취약하게 만드는 요인들
- 많은 공격 지점 : 대규모 네트워크에서는 더 많은 취약지점이 존재함.
- 공유 : 공유네트워크로 연결된 시스템들은 더 많은 수의 사용자가 접근할 수 있음.
- 시스템의 복잡성 : 네트워크 운영/제어 시스템은 단일 컴퓨터 시스템을 위한 운영체제보다 훨씬 복잡할 가능성이 높다.

#### 2) 네트워크 위협의 유형
- 물리적 위협과 기술적 위협으로 나뉜다.
	- 기술적 위협은 수동적/능동적 공격으로 나뉜다.
- 수동적 공격은 통신회선상의 정보를 무단으로 취득하는 행위. 통신회선에 제3자의 접속시도를 방지하는 방법과 데이터를 암호화하여 기밀성을 보장하는 방법으로 방어할 수 있음.
	- 스니핑, 도청 등이 이에 해당함.
- 능동적 공격은 통신회선상의 정보를 변조, 위조하는 행위. 암호화와 함께 데이터의 무결성을 확인하는 방법으로 방어 가능.
	- 재전송 공격, 변조, 도스/디도스, 하이재킹 등이 이에 해당한다.

## 2. 네트워크 기반 보안위협 및 대응책
### (1) 서비스 거부공격(DoS)
#### 1) DoS(Denial of Service) 공격의 정의
- 시스템에 과부하를 일으켜 정보 시스템의 사용을 방해하는 방식.
- 정상적인 서비스를 못하도록 방해하는 것. 
- 언제든지 정보를 사용할 수 있어야 하는 가용성을 떨어트리는 것이 목적이다.
- 서비스 거부 공격을 단일 컴퓨터로 하면 DoS, 대규모로 좀비 PC를 사용하여 DoS를 진행하면 DDoS(Distributed Denial of Service)가 된다.
- 소프트웨어 취약점을 이용한 공격(poison 패킷 이용)과 flooding(플러딩) 유형 공격으로 구분 가능.
- **DoS 공격의 다른 분류 기준**
	- 파괴 공격 : 디스크, 데이터, 시스템 파괴
	- 시스템 자원 고갈 공격 : CPU, 메모리, 디스크 사용에 과다한 부하 가중
	- 네트워크 자원 고갈 공격 : 쓰레기 데이터로 네트워크 대역폭 고갈

#### 2) TCP SYN Flooding Attack
- **(가) 개요**
	- SYN Flooding 공격은 TCP 연결 설정 과정 중에 3-Way Handshaking 과정에서 Half-Open 연결 시도가 가능하다는 취약점을 이용한 공격.
	- **Half-Open 연결**
		- 어떤 문제가 발생하여 한 장비가 상대방에게 알리지 않은 채 연결을 닫거나 중지할 때 반개방 연결 상태가 발생한다. 
		- 한 장비는 ESTABLISHED 상태에 머물러 있지만 다른 장비는 CLOSED 상태나 다른 임시 상태에 머무르는 것을 이야기함.
		- 반개방 연결 상태의 예로 한 장비의 소프트웨어가 붕괴되거나 연결 중간에 재시작 시켰다던가, 또는 갑작스런 사고로 두 장비가 동기화 되지 못한 경우를 들 수 있음.
	- 공격대상 시스템은 외부로부터 접속 요청을 더 이상 받아들일 수가 없게 되어 정상적인 서비스를 제공할 수 없게 된다.
	- 다수의 syn 신호를 보내놓고 ack 신호를 반송하지 않으면 공격 대상은 일정시간동안 신호를 기다리게 된다.
	- 이 공격은 윈도우 시스템 뿐만 아니라 인터넷에 연결되어 TCP 기반 서비스(웹, FTP 또는 메일서버 등)를 제공하는 모든 시스템에 피해를 줄 수 있다.

>**시작주소 Spoofing**<br>
>DoS 공격에 사용되는 패킷의 공통된 특징은 조작된 시작 주소지. 이를 시작 주소 스푸핑이라고 한다. 시스템의 네트워크 코드에 마음대로 접근할 수 있다면 조작된 시작 주소를 생성하기는 매우 쉬움. 이는 주로 raw socket interface를 통해서 행해지게 됨. 이 인터페이스는 네트워크를 테스트하거나 프로토콜을 연구하는 목적으로 개발된 것으로 정상 작업에는 전혀 필요하지 않은 기능임.
{: .prompt-info }

- **(나) SYN Flooding Attack 공격 과정**
	1. 공격자는 시작 주소가 위조된 상당히 많은 양의 SYN 메시지를 목적지에 보냄. 이 패킷 각각에 대해서 서버는 정보를 저장하고 다시 SYN+ACK를 조작된 주소로 보낸다.
	2. 만약 SYN 패킷을 송신하지 않은 TCP가 SYN+ACK 패킷을 수신하면 RST 패킷을 회신하여 연결설정 작업중단을 요청하고 RST 패킷을 수신한 서버는 연결설정 과정을 중단하고 연결 테이블의 자료 구조를 해제한다.
	3. 하지만 위조 IP 주소가 너무 바쁘거나 사용하지 않는 주소인경우 RST 패킷이 서버로 회신되지 않고, 서버는 정해진 시간동안 계속 SYN+ACK 패킷을 재전송하며 연결 설정 시도를 반복함.
	4. RST 패킷 수신에 의한 연결설정 작업 중단을 막기 위해 사용하지 않는 IP 주소로 SYN 패킷의 출발지 주소를 위조하는 것이 일반적.
	5. 공격자가 매우 많은 패킷을 목적 시스템에 보내면 그 서버의 TCP 연결 테이블은 꽉 차게 되고 이후 들어오는 연결은 거부된다.
- **(다) 보안대책**
	- 방화벽 또는 DDoS 대응장비를 이용하여 동일 Client(IP)의 연결(SYN) 요청에 대한 임계치(Threshold) 설정을 통해 과도한 연결요청이 발생하는 것을 차단한다. iptables를 이용하면 된다.
	- `iptables -A INPUT -p TCP --dport 80 --syn -m connlimit --connlimit-above 5 -j DROP` : TCP 80포트 연결 요청에 대하여 동일 출발지 IP로 동시 연결 개수가 5개 초과 시 이를 차단한다.
	- Syn_Cookie를 사용하여 대응할 수 있다. 서버에서 클라이언트로 보내는 SYN+ACK 패킷에 임의로 생성되는 시퀀스 넘버 대신 서버에서 암호화 기술을 이용해 인증 정보가 담긴 시퀀스 넘버를 생성하여 클라이언트에 보내는 것.
	- 클라이언트로부터 SYN 패킷을 받더라도 Syn_Cookie만 보내고 세션을 닫아버리기 때문에 애초에 공격이 통하지 않게 된다.
		- 리눅스에서는 `# sysctl -w net.ipv4.tcp_syncookies=1`를 통하여 기능을 활성화할 수 있다.
	- First SYN Drop 설정을 한다. 연결 요청 패킷을 보내는 클라이언트가 실제로 존재하는지 파악하는 방법. 클라이언트로 전송된 첫 SYN은 Drop하여 재요청 패킷이 도착하는지 확인하여 출발지가 위조되었는지 판단함. 대부분의 공격 툴이 다량의 SYN요청을 생성할 뿐 패킷 Drop시 재전송을 수행하지 않는다는 점을 이용한 방법.
	- TCP 연결 테이블(Backlog Queue)엔트리 선택적 삭제 기법은 연결 테이블이 오버플로우가 될 때 일부 엔트리를 삭제함으로써 새로운 SYN 패킷을 처리할 수 있게 만드는 것.
	- 연결 테이블 확장은 연결 테이블에 할당된 메모리를 확장하여 TCP는 SYN 플러딩 공격에 보다 오래 버틸 수 있게 함. 하지만 이 기법들은 정상적인 연결을 삭제할 수 있고 지속 공격에 대한 솔루션이 될 수 없다는 문제점이 있음.
		- 리눅스에서는 `# sysctl -w net.ipv4.tcp_max_syn_backlog = 1024` : TCP Backlog Queue의 크기를 1024로 늘린다.

>**Syn 쿠키 기법**<br>
>- SYN 쿠키 기법은 SYN 패킷을 수신한 서버가 시간정보, 클라이언트 IP 주소, 클라이언트 시작 순서번호, 비밀번호 등을 입력값으로 해시값(Hash Value)을 쿠키로 구한 다음, 이를 서버 시작 순서번호(ISN)로 하는 SYN+ACK 패킷을 클라이언트로 회신한다. 
>- 그리고 이에 대한 정상적인 ACK 패킷을 수신할 때까지 연결 테이블에 자료구조 설정을 미룸. 서버가 사용한 쿠키는 시간정보, 비밀번호 등이 포함되어 재사용하거나 위조할 수 없는 값이므로 서버가 송신한 SYN+ACK 패킷을 정상적으로 수신하지 않은 공격자는 확인번호(ack no)를 추론할 수 없다.  때문에 ACK 패킷을 위조하여 서버에게 전송할 수 없다. 
>- 따라서 위조 SYN 패킷을 수신한 서버는 정상적인 ACK 패킷을 수신하지 않게 되어 위조 SYN 패킷에 의한 연결 테이블의 자원이 소진되는 현상을 방지할 수 있게 되는 것.
{: .prompt-info }

#### 3) SMUFT Attack(스머프 공격)
- **(가) 개요**
	- @everyone으로 언급한다음 이 새끼가 그랬어요 하고 거짓말하는거	
	- 광범위한 효과로 도스 공격 중 가장 피해가 그고 인기 있는 공격 형태 중 하나.
	- IP 위장과 ICMP의 특징을 이용한 공격.
	- 공격자가 출발지 IP 주소를 목표 시스템으로 스푸핑하고 목적지 주소를 직접 브로드캐스트 주소로 설정한 다음 Ping 메시지지를 송신하고, Ping 메시지를 수신한 네트워크의 모든 시스템이 Ping 응답 메시지를 출발지 IP 주소로 전송함으로 공격 목표를 마비시킴.
	- 직접적인 ICMP 브로드캐스트와 세가지 구성 요소인 공격자, 증폭 네트워크 공격대상 서버(표적)을 이용한다.
	- **직접 브로트캐스트 주소(Directed Broadcast)**
		- IP 주소의 네트워크 ID는 특정 네트워크 주소 정보를 가지고, 호스트 ID의 모든 비트는 1로 설정된 주소.
	- **증폭 네트워크(Amplifier Network)**
		- ICMP Echo Request 브로드캐스트 메시지를 받아서 희생자(Target)에게 다수의/증폭된 ICMP Echo Reply를 전송하는 네트워크를 말한다.
	- **Fraggle Attack**
		- ICMP 대신 UDP를 사용함. 위장된 희생자의 IP 주소로 브로드캐스팅을 함. 호스트는 수많은 네트워크의 응답으로 시스템상의 문제를 일으키게 된다.
- **(나) 공격방법**
	- 공격자는 IP를 공격대상 서버의 IP주소로 위장하여 ICMP를 브로드캐스트로 다수의 시스템에 전송한다.
	- ICMP를 수신한 다수의 시스템은 ICMP Echo 패킷을 공격자가 아닌 공격대상 서버로 전송하게 됨.
	- 대상서버는 다수의 ICMP Echo를 수신하게 되어 시스템 성능에 문제를 일으키게 됨.
	- 이때 다수의 시스템은 브로드캐스트에 대한 응답으로 다수의 ICMP Echo 패킷을 발생시키기 때문에 증폭 네트워크라고 불리게 됨.
	- **Amplification Attack(증폭 공격)**
		- Amplification 공격에 의해 대상시스템을 겨낭하도록 조작된 시작 주소를 가진 패킷들이 중계시스템에 보내진다. Smurf, Fraggle이라는 프로그램도 이 방법을 사용했음.
- **(다) 보안대책**
	- 중간매개지로 쓰이는 것을 막기 위해 라우터에서 다른 네트워크로부터 자신의 네트워크로 들어오는 IP directed broadcast 패킷을 막도록 설정한다.
	- 호스트는 IP broadcast address로 전송된 ICMP 패킷에 대해 응답하지 않도록 시스템을 설정할 수 있다.
	- 동일한 ICMP Echo Reply 패킷이 다량으로 발생한다면 해당 패킷들을 침입차단 시스템을 통해 모두 차단시킴.

#### 4) LAND Attack
- **(가) 개요**
	- 시스템을 나쁜 상태에 빠지게 하는 공격이다. 
	- 자기가 자기 자신에게 계속해서 요청과 응답을 하게 만들어 버리는 것.
	- 패킷을 전송할 때 출발지 IP 주소와 목적지 IP 주소 값을 똑같이 만들어서 공격 대상에 보내는 것. 이 때 조작된 IP 주소값은 공격 대상의 IP 주소.
	- SYN Flooding처럼 동시 사용자 수를 증가시키며, CPU에도 부하를 주게 된다.
- **(나) 보안대책**
	- **탐지방법**
		- 공격자가 보낸 패킷의 TCP를 분석
		- TCP 패킷의 소스 IP, 포트와 목적지 IP, 포트가 동일한지 확인한다. (소스 주소가 내부 IP인 패킷을 차단한다.)
		- 공격자가 보내는 패킷을 카운트하여 공격인정 시간 내에 공격인정 횟수가 많으면 LAND Attack으로 간주함.
	- **조치방법**
		- 라우터나 패킷 필터링 도구를 이용하여 자신의 시스템 주소와 동일한 소스 주소를 가진 외부 패킷을 필터링함.
		- 공격정보를 네트워크, 시스템 관리자에게 알림으로써 관리자가 침입차단시스템에서 소스 아이피/포트와 목적지 아이피/포트와 동일하면 차단하도록 설정함.

#### 5) Ping of Death
- **(가) 개요**
	- 공격의 기본은 ping을 이용하여 ICMP 패킷을 정상 크기보다 아주 크게 만드는 것. 정상 크기는 65,535 바이트

#### 6) Teardrop Attack
- **(가) 개요**

		- 패킷을 단편화되어있다는 신호만 보내고 실제로는 그대로 보내어 시스템이 재조합 과정에서 오류를 발생시키도록 함

### (2) DDoS 공격
#### 1) DDoS 공격 발전형태
- **(가) 1999년~**
	- 단순한 형태의 도스 공격만 있었음
- **(나) 2005년~**

- **(다) 현재**
	- 대응시스템을 우회, 압도하기 위한 고도화된 디도스 공격 유형이 등장함. 
		- 스마트 어택, Memcached Reflection Attack, Carpet Bombing 등 
		- **스마트 어택**
			- 그냥 더 정교하고 고도화된 디도스	
		- **카펫 바밍**
			- 같은 대역대의 여러 아이피로 트래픽을 분산시켜 공격하는 방식. 공격 유무 판별, 대상 식별이 어려움.
	- **랜섬 디도스**가 등장함. 디도스 공격 협박을 통해 돈을 갈취함.

#### 2) DDoS 공격 개요
- 다수의 서버, 피씨를 이용해 비정상적인 트래픽을 유발시켜서 대상 시스템을 마비시키는 공격 행위.
- 공격자는 취약한 서버를 공격하여 악성코드를 배포하고, 유포지/경유지 서버에서 악성코드를 내려 받은 서버/기기들을 이용하여 봇넷을 구축.
- 공격자는 봇넷에 명령을 전달하여 대규모의 트래픽을 유발시키거나 취약한 서버를 악용하여 반사공격을 수행함. 이 때 공격자의 위치나 구체적인 발원지를 파악하는 일은 거의 불가능에 가까움.
- **봇넷**
	- 악성코드 등에 의해 감염된 피해 PC, IoT 기기, 서버들로 구성된 네트워크 집단으로 주로 공격자의 공격 도구로 사용됨.

#### 3) 구성 요소
- 공격자 : 마스터 서버에서 공격 명령을 내리는 사람
- 마스터 / C&C 서버 : 공격자의 직접 명령을 받은 시스템. 여러 대의 에이전트를 관리.
- 핸들러 프로그램 : 마스터 시스템의 역할을 수행하는 프로그램
- 에이전트 : 공격 대상에 직접적인 공격을 가하는 시스템. 악성코드에 감염된 시스템이다. 슬레이브, 좀비라고도 함.
- 데몬 프로그램 : 에이전트 시스템 역할을 수행하는 프로그램.
- 표적 : 공격 대상.

#### 4) 봇, 봇넷
- **(가) 개요**
	- 원격에서 해당 시스템을 제어할 수 있는 프로그램을 봇이라 함. 이런 봇에 감염된 PC나 디바이스는 앞에 좀비를 붙인다.
		- 일반적으로 봇은 웜/바이러스, 백도어, 스파이웨어, 루트킷 등 다양한 악성코드들의 특성을 복합적으로 가지고 있다.
		- 봇은 공격자의 명령에 따라 활동하며 공격자가 감염된 PC나 디바이스를 제어하여 정보 유출, 스팸 메일 발송, 디도스 공격, 트래픽 스니핑, 키로깅 등 다양한 형태의 공격을 수행함.

	- 봇넷은 명령과 제어를 위해 사용하는 프로토콜에 따라 IRC(Internet Relay Chat) 봇넷, HTTP 봇넷, P2P 봇넷으로 분류할 수 있으며 네트워크 구성에 따라 중앙 집중형 방식으로 분류할 수 있다.

		- 이를 통해 악성 봇 PC는 C&C 서버가 아닌 싱크홀 서버로 접속하여 공격자의 명령으로부터 피해를 방지할 수 있다.

			- DGA(Domain Generation Algorithm) 기법

#### 5) 전통적인 디도스 공격
- **(가) 트리누(Trinoo) 공격**
	- 많은 호스트로부터 통합된 UDP flood 서비스 거부 공격을 유발하는데 사용된 도구. 몇 개의 서버와 많은 수의 클라이언트로 이루어짐.
- **(나) TFN(Tribed Flood Network) 공격**
	- 트리누와 거의 유사한 분산 서비스 거부 도구. 많은 소스에서 하나, 혹은 여러개의 목표 시스템에 대해 서비스 거부 공격을 수행함. (Trinoo의 약간 발전된 형태로 믹스터(Mixter)라는 사람이 개발)
	- TFN은 UDP flood 공격을 할 수 있을 뿐만 아니라 TCP SYN flood 공격, ICMP echo 요청 공격, ICMP 브로드캐스트 공격(smurf 공격)을 할 수도 있다.
- **(다) Stacheldraht 공격**
	- Stacheldraht는 철조망이라는 뜻. 
	- 트리누와 TFN을 참고하여 제작된 도구. 마스터 시스템 및 자동적으로 업데이트되는 에이전트 데몬과의 사이에 통신을 할 때 암호화하는 기능이 추가되었다.
- **(라) TFN2K 공격**
	- TFN의 발전된 형태.
	- 통신에 특정 포트가 사용되지 않고 암호화되어있고, 프로그램에 의해 UDP, TCP, ICMP가 복잡적으로 사용되며 포트도 임의로 결정된다.
	- 지정된 TCP 포트에 백도어를 실행시킬 수 있다.

#### 7) 최신 DDoS 공격유형
- **(가) 대역폭 공격(1) - UDP, ICMP Flooding**
	- **UDP Flooding**
		- 출발지 아이피를 위/변조한 후 UDP 프로토콜로 대규모 데이터를 생성하여 피해 대상 시스템을 향해 전달한다. 대상 서버에서 UDP 포트를 사용하지 않아도 공격이 가능하고 공격을 수행하는 감염된 기기가 많을수록 위험도가 증가함.
		- 단순한 공격방식, 강력한 효과로 현재도 많이 사용되는 방식.
	- **ICMP Flooding**
		- ICMP Request 패킷을 이용하여 피해서버로 대량의 ICMP 패킷을 생성해 전달하여 피해서버의 대역폭을 고갈시키는 공격방식이다. 반사공격과 다르게 ICMP Flooding은 증폭이 발생하지 않기 때문에 공격기기의 대역폭에 따라 공격 규모가 결정됨.
- **(나) 대역폭 공격(2) - DRDoS(Distributed Reflection Denial of Service)**
	- **DRDoS 개요**
		- 별도의 에어진트 설치 없이 프로토콜 구조의 취약점을 이용해 정상적인 서비스를 운영하는 시스템을 분산 반사 서비스 거부 공격의 에이전트로 활용하여 공격함.
		- 다양한 형태로 나타날 수 있음. 
			1. TCP의 연결설정과정인 3-웨이-핸드셰이크의 취약점을 이용한다. 위조된 주소의 syn 요청을 반사서버로 전달하여 Echo Reply가 공격대상으로 향하도록 하는 방법.
			2. ICMP 프로토콜의 Echo Request와 Echo Reply를 이용. 위조된 주소의 Echo Request를 반사 서버로 전달하여 Echo Reply가 공격대상으로 향하도록 하는 방법.
			3. UDP 프로토콜 서비스를 제공하는 서버를 반사서버로 이용하여 그 응답이 공격 대상으로 향하도록 하는 방법.
		- UDP 프로토콜을 사용하는 DNS, NTP, SNMP, CHARGEN 등의 서비스를 이용한 DRDoS 공격은 크게 반사와 증폭 공격 형태로 나타난다.

>**UDP 서비스를 이용한 DRDoS 공격 유형**<br>
>- DNS 증폭 DRDoS 공격 : DNS 서버(반사서버)에 많은 양의 레코드 정보를 요구하는 DNS 질의 타입(ANY, TXT등)을 요청하여 공격 대상에게 대량의 트래픽 증폭을 유발시킴.
>- NTP 증폭 DRDoS 공격 : NTP서버(반사서버)에 최근 접속한 클라이언트 목록(monlist 명령)을 요청하여 대량의 응답 트래픽(증폭)을 유발시킨다.
>- SNMP 증폭 : SNMP agent에 MIB와 같은 정보를 대량 요청(GetBulkRequest)하여 공격 대상자에게 대량 트래픽을 유발시킨다.
