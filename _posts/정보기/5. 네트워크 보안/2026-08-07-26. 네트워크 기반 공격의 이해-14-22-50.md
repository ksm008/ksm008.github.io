## 1. 네트워크 기반 위협
#### 1) 네트워크를 취약하게 만드는 요인들
- 많은 공격 지점 : 대규모 네트워크에서는 더 많은 취약지점이 존재함.
- 공유 : 공유네트워크로 연결된 시스템들은 더 많은 수의 사용자가 접근할 수 있음.
- 시스템의 복잡성 : 네트워크 운영/제어 시스템은 단일 컴퓨터 시스템을 위한 운영체제보다 훨씬 복잡할 가능성이 높다.

#### 2) 네트워크 위협의 유형
- 물리적 위협과 기술적 위협으로 나뉜다.
	- 기술적 위협은 수동적/능동적 공격으로 나뉜다.
- 수동적 공격은 통신회선상의 정보를 무단으로 취득하는 행위. 통신회선에 제3자의 접속시도를 방지하는 방법과 데이터를 암호화하여 기밀성을 보장하는 방법으로 방어할 수 있음.
	- 스니핑, 도청 등이 이에 해당함.
- 능동적 공격은 통신회선상의 정보를 변조, 위조하는 행위. 암호화와 함께 데이터의 무결성을 확인하는 방법으로 방어 가능.
	- 재전송 공격, 변조, 도스/디도스, 하이재킹 등이 이에 해당한다.

## 2. 네트워크 기반 보안위협 및 대응책
### (1) 서비스 거부공격(DoS)
#### 1) DoS(Denial of Service) 공격의 정의
- 시스템에 과부하를 일으켜 정보 시스템의 사용을 방해하는 방식.
- 정상적인 서비스를 못하도록 방해하는 것. 
- 언제든지 정보를 사용할 수 있어야 하는 가용성을 떨어트리는 것이 목적이다.
- 서비스 거부 공격을 단일 컴퓨터로 하면 DoS, 대규모로 좀비 PC를 사용하여 DoS를 진행하면 DDoS(Distributed Denial of Service)가 된다.
- 소프트웨어 취약점을 이용한 공격(poison 패킷 이용)과 flooding(플러딩) 유형 공격으로 구분 가능.
- **DoS 공격의 다른 분류 기준**
	- 파괴 공격 : 디스크, 데이터, 시스템 파괴
	- 시스템 자원 고갈 공격 : CPU, 메모리, 디스크 사용에 과다한 부하 가중
	- 네트워크 자원 고갈 공격 : 쓰레기 데이터로 네트워크 대역폭 고갈

#### 2) TCP SYN Flooding Attack
- **(가) 개요**
	- SYN Flooding 공격은 TCP 연결 설정 과정 중에 3-Way Handshaking 과정에서 Half-Open 연결 시도가 가능하다는 취약점을 이용한 공격.
	- **Half-Open 연결**
		- 어떤 문제가 발생하여 한 장비가 상대방에게 알리지 않은 채 연결을 닫거나 중지할 때 반개방 연결 상태가 발생한다. 
		- 한 장비는 ESTABLISHED 상태에 머물러 있지만 다른 장비는 CLOSED 상태나 다른 임시 상태에 머무르는 것을 이야기함.
		- 반개방 연결 상태의 예로 한 장비의 소프트웨어가 붕괴되거나 연결 중간에 재시작 시켰다던가, 또는 갑작스런 사고로 두 장비가 동기화 되지 못한 경우를 들 수 있음.
	- 공격대상 시스템은 외부로부터 접속 요청을 더 이상 받아들일 수가 없게 되어 정상적인 서비스를 제공할 수 없게 된다.
	- 다수의 syn 신호를 보내놓고 ack 신호를 반송하지 않으면 공격 대상은 일정시간동안 신호를 기다리게 된다.
	- 이 공격은 윈도우 시스템 뿐만 아니라 인터넷에 연결되어 TCP 기반 서비스(웹, FTP 또는 메일서버 등)를 제공하는 모든 시스템에 피해를 줄 수 있다.

>**시작주소 Spoofing**<br>
>DoS 공격에 사용되는 패킷의 공통된 특징은 조작된 시작 주소지. 이를 시작 주소 스푸핑이라고 한다. 시스템의 네트워크 코드에 마음대로 접근할 수 있다면 조작된 시작 주소를 생성하기는 매우 쉬움. 이는 주로 raw socket interface를 통해서 행해지게 됨. 이 인터페이스는 네트워크를 테스트하거나 프로토콜을 연구하는 목적으로 개발된 것으로 정상 작업에는 전혀 필요하지 않은 기능임.
{: .prompt-info }

- **(나) SYN Flooding Attack 공격 과정**
	1. 공격자는 시작 주소가 위조된 상당히 많은 양의 SYN 메시지를 목적지에 보냄. 이 패킷 각각에 대해서 서버는 정보를 저장하고 다시 SYN+ACK를 조작된 주소로 보낸다.
	2. 만약 SYN 패킷을 송신하지 않은 TCP가 SYN+ACK 패킷을 수신하면 RST 패킷을 회신하여 연결설정 작업중단을 요청하고 RST 패킷을 수신한 서버는 연결설정 과정을 중단하고 연결 테이블의 자료 구조를 해제한다.
	3. 하지만 위조 IP 주소가 너무 바쁘거나 사용하지 않는 주소인경우 RST 패킷이 서버로 회신되지 않고, 서버는 정해진 시간동안 계속 SYN+ACK 패킷을 재전송하며 연결 설정 시도를 반복함.
	4. RST 패킷 수신에 의한 연결설정 작업 중단을 막기 위해 사용하지 않는 IP 주소로 SYN 패킷의 출발지 주소를 위조하는 것이 일반적.
	5. 공격자가 매우 많은 패킷을 목적 시스템에 보내면 그 서버의 TCP 연결 테이블은 꽉 차게 되고 이후 들어오는 연결은 거부된다.
- **(다) 보안대책**
	- 방화벽 또는 DDoS 대응장비를 이용하여 동일 Client(IP)의 연결(SYN) 요청에 대한 임계치(Threshold) 설정을 통해 과도한 연결요청이 발생하는 것을 차단한다. iptables를 이용하면 된다.
	- `iptables -A INPUT -p TCP --dport 80 --syn -m connlimit --connlimit-above 5 -j DROP` : TCP 80포트 연결 요청에 대하여 동일 출발지 IP로 동시 연결 개수가 5개 초과 시 이를 차단한다.
	- Syn_Cookie를 사용하여 대응할 수 있다. 서버에서 클라이언트로 보내는 SYN+ACK 패킷에 임의로 생성되는 시퀀스 넘버 대신 서버에서 암호화 기술을 이용해 인증 정보가 담긴 시퀀스 넘버를 생성하여 클라이언트에 보내는 것.
	- 클라이언트로부터 SYN 패킷을 받더라도 Syn_Cookie만 보내고 세션을 닫아버리기 때문에 애초에 공격이 통하지 않게 된다.
		- 리눅스에서는 `# sysctl -w net.ipv4.tcp_syncookies=1`를 통하여 기능을 활성화할 수 있다.
	- First SYN Drop 설정을 한다. 연결 요청 패킷을 보내는 클라이언트가 실제로 존재하는지 파악하는 방법. 클라이언트로 전송된 첫 SYN은 Drop하여 재요청 패킷이 도착하는지 확인하여 출발지가 위조되었는지 판단함. 대부분의 공격 툴이 다량의 SYN요청을 생성할 뿐 패킷 Drop시 재전송을 수행하지 않는다는 점을 이용한 방법.
	- TCP 연결 테이블(Backlog Queue)엔트리 선택적 삭제 기법은 연결 테이블이 오버플로우가 될 때 일부 엔트리를 삭제함으로써 새로운 SYN 패킷을 처리할 수 있게 만드는 것.
	- 연결 테이블 확장은 연결 테이블에 할당된 메모리를 확장하여 TCP는 SYN 플러딩 공격에 보다 오래 버틸 수 있게 함. 하지만 이 기법들은 정상적인 연결을 삭제할 수 있고 지속 공격에 대한 솔루션이 될 수 없다는 문제점이 있음.
		- 리눅스에서는 `# sysctl -w net.ipv4.tcp_max_syn_backlog = 1024` : TCP Backlog Queue의 크기를 1024로 늘린다.

>**Syn 쿠키 기법**<br>
>- SYN 쿠키 기법은 SYN 패킷을 수신한 서버가 시간정보, 클라이언트 IP 주소, 클라이언트 시작 순서번호, 비밀번호 등을 입력값으로 해시값(Hash Value)을 쿠키로 구한 다음, 이를 서버 시작 순서번호(ISN)로 하는 SYN+ACK 패킷을 클라이언트로 회신한다. 
>- 그리고 이에 대한 정상적인 ACK 패킷을 수신할 때까지 연결 테이블에 자료구조 설정을 미룸. 서버가 사용한 쿠키는 시간정보, 비밀번호 등이 포함되어 재사용하거나 위조할 수 없는 값이므로 서버가 송신한 SYN+ACK 패킷을 정상적으로 수신하지 않은 공격자는 확인번호(ack no)를 추론할 수 없다.  때문에 ACK 패킷을 위조하여 서버에게 전송할 수 없다. 
>- 따라서 위조 SYN 패킷을 수신한 서버는 정상적인 ACK 패킷을 수신하지 않게 되어 위조 SYN 패킷에 의한 연결 테이블의 자원이 소진되는 현상을 방지할 수 있게 되는 것.

#### 3) SMUFT Attack(스머프 공격)
- **(가) 개요**
	- @everyone으로 언급한다음 이 새끼가 그랬어요 하고 거짓말하는거	
	- 광범위한 효과로 도스 공격 중 가장 피해가 그고 인기 있는 공격 형태 중 하나.
	- IP 위장과 ICMP의 특징을 이용한 공격.
	- 공격자가 출발지 IP 주소를 목표 시스템으로 스푸핑하고 목적지 주소를 직접 브로드캐스트 주소로 설정한 다음 Ping 메시지지를 송신하고, Ping 메시지를 수신한 네트워크의 모든 시스템이 Ping 응답 메시지를 출발지 IP 주소로 전송함으로 공격 목표를 마비시킴.
	- 직접적인 ICMP 브로드캐스트와 세가지 구성 요소인 공격자, 증폭 네트워크 공격대상 서버(표적)을 이용한다.
	- **직접 브로트캐스트 주소(Directed Broadcast)**
		- IP 주소의 네트워크 ID는 특정 네트워크 주소 정보를 가지고, 호스트 ID의 모든 비트는 1로 설정된 주소.
	- **증폭 네트워크(Amplifier Network)**
		- ICMP Echo Request 브로드캐스트 메시지를 받아서 희생자(Target)에게 다수의/증폭된 ICMP Echo Reply를 전송하는 네트워크를 말한다.
	- **Fraggle Attack**
		- ICMP 대신 UDP를 사용함. 위장된 희생자의 IP 주소로 브로드캐스팅을 함. 호스트는 수많은 네트워크의 응답으로 시스템상의 문제를 일으키게 된다.
- **(나) 공격방법**
	- 공격자는 IP를 공격대상 서버의 IP주소로 위장하여
