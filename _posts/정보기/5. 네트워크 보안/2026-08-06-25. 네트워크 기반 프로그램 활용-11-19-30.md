## 1. 네트워크 기반 프로그램 활용
#### 1) 연결테스트(ping)
- **(가) 개요**
	- ping 명령은 인터넷으로 접속하려는 원격 호스트가 정상적으로 운영되고 있는지를 확인하는 진단 목적으로 사용한다.
	- ping 명령은 ICMP를 사용하는 유틸리티. ICMP 타입 중에서도 Echo Request(Type 8) 타입을 지정하여 대상 시스템으로 ICMP 패킷을 전송하고, 그 대상 시스템으로부터 Echo Reply(Type 0) 패킷을 수신함으로써 접근성(Reachability)을 확인하게 된다.
	- 서버에 따라서 해킹이나 간접 부하를 줄이기 위해 ping 명령에 응답하지 않도록 설정하는 경우도 있음.
	- **+ ICMP(Internet Cotrol Message Protocol)**
		- 인터넷 제어 메시지 프로토콜.
		- TCP/IP 기반의 인터넷 통신 서비스에서 인터넷 프로토콜(IP)과 조합하여 통신 중에 발생하는 오류의 처리와 전송 경로의 변경 등을 위한 제어 메시지를 취급하는 무연결 전송(connectionless transmission)용의 프로토콜(RFC, 792) OSI 기본 참조 모델의 네트워크 계층에 해당함.
	- **+ping 명령어 제공 정보**
		- 대상 시스템에 ICMP 패킷이 도달 가능한지?
		- ICMP 패킷이 대상 시스템을 왕복하는데 걸리는 시간?
		- ICMP 패킷의 손실률?
- **(나) 입력 문법 및 실행 결과**
	- **리눅스**
		- `ping [-option] ip_address | host_name`
			- `-c count` : 지정한 숫자만큼 ICMP 패킷을 송수신한다.
			- `-i wait`  : ICMP 패킷 송신 간의 대기시간이다. 디폴트는 1초.
			- `-s packet_size` : ICMP 송신 패킷의 데이터 크기. 디폴트는 56 바이트.
			- `ping 192.168.0.100`
			- `ping www.domain.com -s 100 -c 10` : domain.com에 100 바이트 크기로 10회 송수신
	- **윈도우**
		- 실행 결과


#### 2) 경로추적(traceroute)
- **(가) 동작원리**
	- 종단(End) 노드 사이에 있는 여러 중계 노드(L3장비/라우터) 각 구간에 대한 네트워크 상태를 관리하기 위한 명령어로 네트워크의 라우팅 문제점을 찾아내는 목적으로 많이 사용한다. 
	- 중계 노드의 개수, IP 주소, 응답시간 등을 파악할 수 있다.
	- traceroute는 패킷의 TTL(Time to Live)를 하나씩 증가시켜보낸다. 
	- **TTL**
		- 목적지를 찾기 위해 경유하는 라우터의 개수. 라우터를 거치면서 1씩 감소하고, 목적지 도착 전에 TTL 값이 0이면 폐기한다. 라우팅의 무한 루프를 막기 위해 사용한다.
	- 1의 TTL을 가지는 패킷은 도착한 라우터에서 TTL이 감소하고 ICMP 메시지가 출발지로 보내진다.
	- 목적지에 도달할 때까지 패킷을 보내는데, 이 패킷은 사용 불가능한 포트인 33434번을 붙여서 간다.
	- 만약 Unreachable Port라는 ICMP 메시지를 받으면 trace가 목적지에 도달했음을 알 수 있게 된다.
	- **+ tracert(윈도우 동작방식)**
		- traceroute 명령은 UDP 패킷을 이용하는 반면 tracert 명령은 ICMP Echo Request(Type 8)과 ICMP Echo Reply(Type 0)을 이용함.
- **(나) traceroute의 활용**
	- traceroute 결과에서 응답시간이 `*`로 표시되는 경우 침입차단시스템 등의 접근통제리스트에 의해 traceroute의 UDP 패킷이 보안상의 이유로 차단되었거나 실제 해당 구간에 문제가 발생한 경우로 볼 수 있음.
	- 해결방법은 다음과 같다.
		- 지정한 주소가 실제로 존재하는지 체크하고 없다면 패킷이 멈춘 곳을 알려준다.
		- 수행속도가 느리면 어느 지점에서 시간을 많이 잡아먹는지 확인한다.
		- 패킷이 적당한 곳을 통해서 라우팅되고 있는지 확인한다.
		- `*` 모양이 생기는 곳이 있는지 확인한다.
- **+ traceroute 관련 설정**
	- 보안이나 네트워크 성능 향상을 위해 ICMP Echo Reply나 ICMP Time Exceed를 막아놓는데, 이런 이유로 traceroute 명령 결과를 분석하는 경우에는 경로상의 타임아웃(Timeout) 현상보다는 어느 구간에서 지연(Delay)이 발생하는지를 살펴보는 것이 중요하다.
- **(다) 입력 문법 및 실행 결과**
	- `traceroute [-option] ip_address | host_name [packet_len]`
		- `-m max_hop` : 최대 TTL 지정
		- `-p port` : UDP 포트를 지정. 기본은 33434.
		- `-q n_queries` : 각 TTL마다 전달하는 탐색 패킷의 횟수이다. 기본은 3.
		- `-w wait_time` : 탐색 중 응답을 기다리는 시간. 기본는 5초.
		- `packet_len` : 탐색 패킷의 크기.
		- `traceroute -q 4 192.168.0.100` : 192.168.0.100에 TTL마다 4회 탐색한다.
	- 5초동안 응답 결과가 없으면 `*` 기호로 표시한다.
