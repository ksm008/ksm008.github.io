## 1. 침입탐지시스템(IDS)
### **(1) IDS(Intrusion Detection System) 개요**
#### 1) 기본 개념
- 침입탐지시스템은 네트워크에서 사용되는 자원의 무결성, 비밀성, 가용성을 저해하는 비정상적인 사용과 오용, 남용 등의 행위가 가능한 한 실시간으로 탐지하여 관리자에게 경고메시지를 보내주고 대응하는 시스템.
- 외부 침입에 대한 정보를 수집하고 분석하여 침입활동을 탐지해 이에 대응하도록 보안 담당자에게 통보하는 기능을 수행하는 네트워크 보안 시스템.

#### 2) 특징
- 내/외부망의 접속점에 위치하여 방화벽의 부족한 부분을 보강하기 위해 사용.
- IDS 도구의 기본 목적은 의심스러운 행동을 발견하고 관리자의 스크린으로 메시지를 전달하거나 경고음 발생 등 침입에 대한 탐지.
- 전통적 IDS는 공격의 증거를 찾기 위해 네트워크 트래픽 분석의 역할을 수행했으나, IDS는 시스템의 침해 여부를 보기 위해 액세스 로그들을 조사하여 파일을 분석하는 것으로 변하였으며, 또한 허니팟 개념으로 점차 확장/변화중.

#### 3) 장/단점
- 대충 장점은 해킹에 대해 더 적극적인 방어가 가능하고 탐지가 뛰어나며 근원지 추적이 가능하다...
- 단점은 대규모 사용이 어렵고 관리하기 어렵고 보안사고에 대한 근본적인 해결책은 되지 못함.

#### 4) IDS의 실행단계
- **데이터 수집 단계(Raw Data Collection) :** 탐지대상(시스템 사용내역, 패킷 등)으로부터 생성되는 데이터를 수집하는 감사 데이터(audit data) 수집 단계.
- **데이터 가공 및 축약(Data Reduction and Filtering) 단계 :** 수집된 감사 데이터를 침입 판정이 가능하도록 의미있는 정보로 전환시키는 단계. 
- **침입분석 및 탐지 단계 :** 데이터를 분석하여 침입 여부를 판단하는 침입 탐지 시스템의 핵심 단계로 여러가지 기법이 있음. 시스템의 비정상적인 사용을 탐지하는 비정상적 행위 탐지 기법과 시스템의 취약점, 응용 프로그램의 버그 등을 탐지하는 오용 탐지 기법이 있다. 최근에는 비정상적 행위 탐지기법과 오용 탐지기법을 혼합하여 사용하는 하이브리드형 탐지기법이 많다.
- **보고 및 대응(Reporting and Response) 단계 :** 시스템의 침입 여부가 침입으로 판정된 경우 이에 대한 적절한 대응을 자동으로 취하거나, 보안관리자에게 침입사실을 보고하여 보안관리자가 조치를 취하게 한다.

### (2) IDS의 종류
#### 1) IDS의 종류
- 머 대충 여러가지로 나뉨...
	- 탐지방법 - 행위 / 지식
	- 대응방법 - 수동 / 능동
	- 데이터 수집원 - 호스트 로그파일 / 네트워크 패킷
	- 탐지시점 - 사후 / 실시간

#### 2) 탐지방법에 의한 분류
- **(가) 규칙-기반 침입탐지(지식기반/오용 침입탐지/Misuse Detection)**
	- **기본 개념**
		- 특징을 비교하여 탐지함. 기존 침입 방법을 DB에 저장했다가 패턴과 일치, 유사한 경우에 침입이라 판단.
		- 시그니처의 예시
			- 루트 사용자 이름으로 텔넷을 시도한다던가
			- 시스템 프로그램을 복제 시도한다던가
			- 패스워드 파일을 복제시도한다던가...
		- 오탐율(긍정 오류)이 낮음.
		- 트로이목마나 백도어 탐지 가능.
		- 하지만 지속적으로 공격 패턴을 갱신해야 하고 패턴이 없는 공격은 탐지 불가.
	- **오용침입**
		- 시스템이나 응용 소프트웨어의 약점을 통하여 시스템에 침입할 수 있는 공격 형태를 말함.
		- 이러한 침입에 대한 시나리오를 패턴으로 저장하고 유사한 형태의 행위가 발생되면 침입으로 판정함.
	- **종류**
		- **전문가 시스템**
			- if-then-rule에서 공격 패턴들을 정의하고 일치하는 경우에 정해진 규칙에 따라 행동을 수행함.
		- **상태전이 모델**
			- 공격 패턴에 따라 시스템의 상태 변화를 미리 상태전이도로 표현함. 상태변화를 계속 추적
		- **패턴 매칭**
			- 알려진 공격 패턴을 시나리오 형태로 DB에 저장한 후 비교하여 판단함.
- **(나) 통계적 변형 탐지(행위기반/비정상 침입탐지/Anomaly Detection)**
	- **기본 개념**
		- 사용자의 행동 양식을 분석한 후 정상적인 행동과 비교해 이상한 행동, 급격한 변화가 빌견되면 불법침입으로 탐지함
		- 프로파일의 예
			- 근무 시간의 네트워크 트래픽 중 웹 트래픽 평균 비중이 15퍼센트
			- 특정 호스트에 대한 로그인 시도가 5번 이상 연속으로 실패하지 않음
			- CPU 사용률이 80% 이상이 되는 시간이 5분 이상 계속되지 않음
		- 인공지능 알고리즘을 사용하여 스스로 판단 가능
		- 알려지지 않은 새로운 공격탐지가 가능하다.
		- 하지만 오탐율이 높고 정상/비정상 구분을 위한 임계치 설정이 어려움.
	- **종류**
		- **통계적 분석 방법**
			- 사용자/시스템 행위에 대한 이전 정보를 기반으로 정상행위로 판단되는 통계적인 프로파일을 생성하고 주기적으로 갱신한다.
		- **예측 가능한 패턴 생성 방법**
			- 정상 패턴 범위를 벗어났을때...
		- **신경망 모델**
			- 적응학습 기술을 사용하여 탐지함. 행위 정보를 학습하며 탐지까지.

#### 4) 데이터 수집원에 의한 분류
- **(가) 네트워크 기반 IDS(Netowork-based IDS)**
	- 네트워크에서의 패킷 헤더, 데이터 및 트래픽 양 등 로그를 분석하여 침입 여부를 판단함.
	- 시스템 감사 자료가 아닌 네트워크를 통해 전송되는 패킷 정보를 수집, 분석하여 침입을 탐지함.
	- **장점**
		- 트래픽을 감시할 수 있는 몇몇 위치에만 설치하므로 초기 구축 비용이 저렴.
		- 운영체제에 독립적
		- 캡처된 트래픽에 대해서 침입자가 흔적 제거 어려움
	- **단점**
		- 암호화된 패킷 분석 불가
		- 스위칭 환경에서는 구축 비용이 더 많이 듬
		- 기가비트 급 고속 네트워크 환경에서는 패킷 손실이 많아 탐지율이 떨어짐
		- 호스트에서 수행되는 세부 행위에 대하여 탐지 불가
- **(나) 호스트 기반 IDS(Host-based IDS)**
	- 호스트 시스템으로부터 생성되고 수집된 감사 자료를 탐지에 사용함.
	- 시스템 이벤트 감시를 통한 정확한 침입 탐지가 가능함.
	- **장점**
		- 정확한 탐지, 다양한 대응책 수행 가능
		- 암호화, 스위칭 환경에 적합
		- 추가 하드웨어 불필요
	- **단점**
		- 각 시스템마다 설치해야하므로 다양한 OS를 지원해야 함
		- 시스템에 추가적인 부하가 걸림
		- 구현이 용이하지 않음

### (4) IDS의 응용
#### 1) 긍정오류(False Positive)와 부정오류(False negative)
- 긍정오류 : 합법 사용자를 침입자로 판단
- 부정오류 : 침입자를 합법 사용자로 판단
- 침입 탐지를 적용할 때는 절충과 기술의 요소를 적절히 사용해야 함.

#### 2) 허니팟
- **(가) 개요**
	- 특정 보안 문제를 해결하거나 보안 시스템을 대체하는 역할은 하지 않지만...
	- 잠재적 공격자에 대한 조기 경보 제공, 보안 전략의 결점 파악, 조직 전체의 보안의식 향상과 같이 전반적인 보안 매커니즘을 향상시키는 기능을 수행함.
	- 실제로 자료를 가진 호스트인것처럼 인터넷 상에 존재하여 해커, 악의적인 내부자 등을 속여 침해당하고 그 기법을 분석함.
	- 유인해서 일부로 공격당함.
- **(나) 설계목표**
	- 공격 성향이 있는 자를 중요한 시스템으로부터 다른 곳으로 끌어내도록 설계한 유도 시스템.
	- **목적**
		- 중요 시스템에 접근하는 공격자를 다른 방향으로 돌림
		- 공격자 동작에 관한 정보 수집
		- 관리자가 반응할 수 있도록 공격자로 하여금 시스템에 충분히 오랜 시간 동안 머무르기를 유도함
- **(다) 특징**
	- 다른 보안 시스템처럼 성능이 시스템 자원에 영향을 받지 않는다. 허니팟은 단지 자신에게 보내진 패킷만 수집하기 대문에 데이터를 처리하기 위해 고성능의 시스템을 사용할 필요가 없음.
	- 취약점에 대한 패치가 발표되지 않은 시점에 발생하는 공격인 제로데이(Zero-day) 공격 등을 사전에 탐지할 수 있는 예방통제 기술.
	- 허니팟으로 유인하여 시스템 논리적인 파괴 및 손실을 방지하는데 목적을 둠.
- **(라) 단점**
	- 미러링 포트에 설치되는 침입탐지시스템과 달리 일반 포트에 설치되어 자신에게 오는 패킷만 수집하므로 네트워크 전반에 대한 침입정보를 분석할 수 없음.
	- 공격자가 허니팟을 알아차릴 경우 우회하거나 마비시키는 공격을 가할 수 있음.

### (5) 스노트(Snort)
#### 1) 개요
- IDS의 일종.
- 트래픽 분석, 오버플로우, 포트스캔, CGI 공격 등 다양한 공격과 스캔을 탐지할 수 있음.
#### 2) snort 룰(시그너처) 형식
- **(가) 개요**
	- snort 룰/시그니처는 크게 헤더 부분과 바디 부분으로 구성됨.
	- 헤더는 처리할 패킷을 판단하는 기준을 명시하고 바디 부분은 alert message나 패킷 데이터를 조사하기 위한 내용을 기술. 
- **(나) 룰 헤더 형식**
	- `[동작 방식 (액션)][프로토콜][아이피 주소 / 포트][방향 지시자 ( -> 화살표)][목표 아이피와 포트]`
- **(다) 룰 헤더 필드**
	- **액션**
		- 룰 매칭시 처리 방법을 의미함.
			- **alert :** alert를 발생시키고 로그를 남김
			- **log :** 패킷을 로그에 남긴다.
			- **pass :** 패킷을 무시함.
			- **activate :** alert를 발생시키고 대응하는 dynamic rule을 활성화한다. 
			- **dynamic :** activate rule에 의해 활성확되고, log rule과 동일하게 동작함.
			- **drop :** 패킷을 차단하고 로그에 남김.
			- **reject :** drop rule과 동일하지만 TCP일 경우 TCP Reset을 전송. UDP의 경우 ICMP port unreachable 메시지를 전송함.
			- **sdrop :** 패킷을 차단하지만 로그에 남기지 않음.
	- **프로토콜**
		- TCP/UDP/ICMP/IP 중에서 선택함.
	- **IP Address**
		- 출발지, 목적지 IP를 설정.
		- 복수 설정 가능
			- 10.10.10.0/24, 11.11.11.11
		- 부정 연산자 사용 가능
			- !10.10.10.0/24 (해당 아이피를 제외한 모든 IP)
		- 모든 IP : any로 지정
	- **PORT**
		- 콜론을 이용하여 범위 지정 가능.
		- `1:1023` : 1부터 1023까지
		- `:1024` : 1024 이하
		- `1024::` : 1024 이상
	- **방향 지시자**
		- `->` : 왼쪽이 출발, 오른쪽이 목적지. 반대 방향은 없음.
		- `<>` : 양방향. 출발/목적지 사이에 오가는 모든 패킷.
- **(라) 주요 룰 바디(옵션) 설정**
	- **msg :** alert나 로그 출력 시 이벤트 명으로 사용함.
	- **content :** 패킷의 payload 내부를 검색하는 문자열
	- **offset :** content로부터 지정한 문자열의 검색 시작 오프셋을 의미함.
	- **depth :** offset으로부터 검사할 바이트수를 지정함. 
	- **nocase :** 대소문자 구분 X
	- **sid :** 룰을 식별하기 위한 식별자.
		- 100 미만은 예약, 100~100만 사이는 snort 사이트에서 배포하는 룰.
		- 100만 초과는 커스텀 룰.
	- **flow :**  TCP계층의 reassembly시 함께 동작함.
		- established : 통신이 established 된 패킷만
			- stateless : 상태 상관없이 활성화. 비정상 무작위 공격에 대비.
	- **rev :** rule 버전번호로 수정(revision) 횟수를 표기함. 수정을 할 때마다 1씩 증가한다.

#### 3) snort 룰(시그니처) 예시
- **(가) FTP root 로그인 시도 탐지**
	- `alert tcp any any -> 10.10.10.0/24 21 (msg: "FTP root user access"; contents: "User root"; nocase; sid:100100;)`
	- TCP 프로토콜을 이용하여 21번 포트를 목적지로 하고 FTP 클라이언트로부터 요청 데이터를 탐지하기 위한 것이며 content 옵션을 통해 root 계정 로그인 시 요청 데이터에 포함되는 `USER root` 문자열을 검사하고 있다.
- **(나) NULL 스캔 탐지**
	- `alert tcp any any -> 10.10.10.0/24 21 (msg: "NULL Scan Detect"; flags: !UAPRSF; sid: 100100;)`
	- 모든 패킷은 플래그가 설정됨. 플래그가 설정되지 않은 패킷은 비정상 패킷. 이러한 패킷을 널 패킷이라고 함. 스텔스 스캐닝 기법 중 NULL 스캔을 탐지한다.
	- flags 옵션을 통해 TCP 헤더 제어 플래그 중 URG, ACK, PSH, RST, SYN, FIN이 설정되지 않은 모든 패킷을 탐지하고 있음.

#### Snort의 개요
- **특징**
	- 리눅스 시스템에서 쓸 수 있는 공개형 IDS.
	- 크게 스니퍼 (Sniffer), 프리 프로세서 (Pre-processor), 탐지 엔진, 로깅 (출력)으로 구성되어있다.
	- 주요 기능으로는 패킷 스니퍼, 로거, 네트워크 IDS/IPS가 있다.
- **주요 기능**
	- 탐지 룰을 사용하여 네트워크 트래픽을 분석하고 침입을 탐지할 수 있다.
	- 주요 기능은 아래와 같다.
		- **패킷 스니퍼** : 네트워크의 패킷을 읽고 표시한다.
		- **패킷 로거** : 로깅함
		- **네트워크 IDS** : 네트워크 패킷을 분석하여 공격 탐지. 버퍼 오버플로우, 포트 스캔 등 다양한 공격 감지 가능.

#### Snort의 룰 설정
- **구조**
	- 크게 헤더와 룰 옵션으로 구분됨.
		- **헤더 :** `[동작 방식 (액션)][프로토콜][소스 아이피와 포트][흐름 방향 ( -> 화살표)][목표 아이피와 포트]`
		- **룰 옵션** : General, Payload, non-payload, post-detection 4가지로 분류 가능. 이중 payload 탐지 룰 옵션을 주로 사용함.
		- **룰 옵션의 주요 항목**
			- msg : 출력할 메세지 지정
			- sid: 룰은 1000000 이상으로 함.
			- content : 페이로드 내부에서 검색할 문자열 지정
			- depth : 검사할 바이트 설정
			- offset : 검사 위치 설정
			- distance : 검색할 문자열이 여러가지일 경우 다음 검색하는 문자열을 해당 바이트 이후부터 검색함
			- within : 지정한 바이트 수 내에서만 검사
			- nocase : 대소문자 구분 안함
			- sameip : 소스와 목표 주소가 동일한 것을 검사
	- 예시) `alert tcp any any -> 192.168.10.0/24 80 (msg:"passwd detected"; content:"passwd"; nocase; sid:1000001;)` : 외부에서 내부 80 포트로 이동하는 패킷중 passwd 문자열이 포함된 패킷이 발견되면 "passwd detected"라는 경고 메시지를 발생시킴.
	- **랜드 어택**은 sameip로 손쉽게 체크할 수 있을 것.

## 2. 침입방지시스템(IPS)
#### 1) IPS(Intrusion Prevention System) 개요
- 얘는 탐지부터 대처까지 수행함. IDS는 탐지는 내가 했으니 조치는 니가 하세요
- 호스트 기반 IPS, 네트워크 기반 IPS가 있음...
- **WIPS(Wireless IPS)**
	- 인가되지 않은 무선 단말기의 접속을 자동으로 탐지 및 차단하고 보안에 취약한 무선 공유기(AP)를 탐지하는 솔루션.
	- 유선 방화벽과 유사하게 외부 공격으로부터 내부 시스템을 보호하기 위해 무선랜 환경에서의 보안 위협을 탐지하고 대응하는 시스템을 말한다.
- **NIPS**
	- NIPS는 두 개의 NC를 가지는데, 이것은 외부와 내부에 각각 연결된다. 외부 NIC에 수신된 트래픽은 엔진에 의해 분석된다. 만약 패킷이 안전하다고 판단되면 내부 NIC로 전달된다. 반면 악의적이라고 판단되면 패킷은 버려진다.

#### 2) IPS의 필요성
- 지금은 방화벽이나 IDS로만 해킹, 바이러스, 웜에 대한 공격을 막을 수 없음. 속도 때문.
- **바이러스 월**
	- 특정 파일에 기생하여 이동하는 악성 프로그램을 제거
	- 메일, 파일 공유 등을 통해 전파되는 악성코드를 효과적으로 제거
	- 취약점을 통해 전파되는 공격에 대응불능
