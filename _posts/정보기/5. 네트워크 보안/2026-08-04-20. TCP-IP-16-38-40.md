## 1. 물리 계층
### (1) 개요
#### 1) 데이터와 신호
- **(가) 기본 개념**
	- 응용, 전송, 네트워크, 데이터 링크에서의 통신은 논리적, 물리 계층 통신은 물리적.
	- 교환기도 물리적 통신에 포함됨.
	- 데이터와 데이터를 표현하는 신호는 아날로그, 또는 디지털.
- **(나) 아날로그와 디지털 데이터**
	- 아날로그는 연속인 정보, 디지털 데이터는 이산 값을 가지는 정보. 

## 2. 데이터링크 계층
### (1) 개요
#### 1) 기본 개념
- **(가) 노드와 링크**
	- 데이터링크 계층에서 통신은 노드-대-노드. 인터넷에서 하나의 지점으로부터의 데이터 유닛은 다른 지점에 도달하기 위해 LAN과 WAN 같은 많은 네트워크를 통해 전달될 필요가 있다.
	- 이러한 LAN과 WAN은 라우터를 통해 연결된다. 이것은 노드와 링크로 네트워크를 나타내는 것이 일반적.
- **(나) 서비스**
	- 프레임 짜기 (Framing)
		- 다음 노드에게 데이터그램을 전송하기 위해 네트워크 계층에서 전달받은 패킷인 데이터그램을 프레임에서 캡슐화해야함.
	- 흐름 제어 (Flow Control)
		- 서로 다른 데이터링크 계층 프로토콜은 서로 다른 흐름 제어 전략을 사용한다.
	- 오류 제어 (Error Control)
		- 전기 신호는 오류에 취약, 프레임 또한 그럼.
		- 오류를 검출하는 것이 필요하고, 이후 그를 송신자 노드에서 수정하거나 폐기, 또는 송신노드에게 재전송을 요청해야 한다.
	- 혼잡 제어(Congestion Control)
		- 광역 네트워크 이외의 대부분 데링 계층 프로토콜은 혼잡 제어를 사용하지 않음.
		- 혼잡 제어는 종단-대-종단으로 통신하기 때문에 네트워크/전송 계층의 문제로 여겨짐.

## 3. 네트워크 계층
### (1) 네트워크 계층 개요
#### 1) 네트워크 계층 서비스
- **(가) 라우팅**
	- 네트워크 계층에서의 다른 임무는 라우팅과 포워딩.
	- 패킷이 근원지에서 목적지까지 갈 수 있도록 경로를 짜는 것.
	- 물리적인 네트워크는 네트워크와 네트워크를 연결하는 라우터의 조합.
- **(나) 포워딩**
	- 포워딩은 라우터상의 하나의 인터페이스에 패킷이 도착했을 때 라우터가 취하는 행동으로 정의할 수 있다. 
	- 이런 행동을 위해 사용하는 의사결정 테이블은 포워딩 테이블/라우팅 테이블이라 불리기도 한다.
- **(다) 클래스 기반의 주소 지정**
	- **개요**
		- IPv4 주소는 소/대규모 네트워크를 지원하기 위해 세 가지의 고정된 접두사로 설계됨. (n=8, 16, 24)
		- 전체 주소 공간은 5개의 클래스 A, B, C, D, E로 구분되고 이 기술을 클래스 기반 주소지정이라 함.
			- 클래스 A
				- 첫 바이트의 첫 비트가 0이다. 나머지 7비트는 네트워크 주소. 하위 3바이트는 호스트 주소.
				- A주소는 $2^{24}-2 = 16,777,241$ 개의 호스트를 수용할 수 있기 때문에 큰 규모의 호스트를 가지는 기관에서 사용.
			- 클래스 B
				- 첫 바이트의 첫 두 비트 값이 10이다. 나머지 6비트와 두 번째 바이트가 네트워크 주소, 나머지는 호스트 주소.
				- $2^{16}-2$ 개의 호스트를 수용가능.
			- 클래스 C
				- 처음 세 비트 값이 110이다. 나머지 5비트와 세 번째 바이트까지가 네트워크 주소, 마지막 바이트가 호스트 주소.
				- 네트워크마다 254개의 호스트를 수용할 수 있기 때문에 작은 규모의 네트워크에서 사용됨.
			- 클래스 D
				- 처음 네 비트 값이 1110이다. 클래스 D 주소는 네트워크/호스트 주소 구분이 없고 전체 주소가 멀티캐스트 용으로 사용됨. 정보, 멀티미디어 데이터, 리얼타임 비디오 등을 보내는 데 사용됨.
			- 클래스 E
				- 처음 네 비트 값이 1111. 추후 사용을 위해 예약된 주소.
	- **주소 고갈**
		- 클래스 기반 주소가 더 이상 사용되지 않는 이유는 주소 고갈 때문. 주소가 적절히 분배되지 않았기 때문에 인터넷에 연결하려는 기관, 개인이 사용할 주소가 남아있지 않게 되는 문제가 생김.
	- **서브네팅과 슈퍼네팅**
		- 서브넷 주소지정은 기관의 IP 네트워크 서브넷으로 분리하여 IP 주소 해석 방법에 하나의 계층을 추가했음.
		- *ex)* 기존 B 클래스의 기본 서브넷마스크(255.255.0.0)을 사용하는 경우 $2^{16}$ 개의 네트워크로 구분하여 각 네트워크 당 $2^{16} - 2$ 개의 호스트를 사용할 수 있었지만 다른 서브넷마스크(255.255.255.0)을 사용함으로써 각 네트워크 당 $2^{8} - 2$ 개의 호스트를 가 진 $2^{8}$ 개의 더 작은 서브네트워크로 나누어 사용할 수 있게 된다.
- **(라) 클래스 없는 주소 지정**
	- **개요**
		- 서브네팅, 슈퍼네팅은 실제로 주소 고갈 문제를 해결하지 못했다.
		- 단기적인 관점의 해결책에서는 클래스 없는 주소지정 방시의 IPv4 주소가 사용된다. 즉, 주소 고갈을 해결하기 위해 클래스 권한이 제거됨.
	- **접두사 길이**
		- CIDR에는 주소 클래스가 없기 때문에 주소만으로 네트워크 ID의 크기를 파악할 수 없음. 접두사의 길이를 주소 뒤의 슬래시 다음에 표시함. 이걸 CIDR/슬래시 표기법이라 부른다.

>**CIDR(Classless Inter-Domain Routing)**<br>
>- CIDR은 기존의 클래스 A, B, C 네트워크 주소의 개념을 무시한다. IPv4의 주소 공간을 효율적으로 할당할 수 있게 됨.
>- ISP는 자신이 할당받은 주소 공간 중에서 클라이언트가 요구하는 양만큼 잘라서 공급할 수 있게 되어 귀한 자원인 주소 공간의 낭비를 막을 수 있다.
>- 인터넷 라우팅 테이블의 비대화를 막아준다. 인터넷을 여러 개의 addressing domain으로 나눔으로써 라우팅 정보량을 줄여준다. 한 도메인 내에서는 그 도메인 내의 모든 라우팅 정보가 공유됨.

- **(마) VLSM(Variable Length Subnet Mask, 가변 길이 서브넷 마스킹)**
	- 서브네팅을 여러번 반복하여 네트워크 크기를 다른 여러 서브네트워크 계층으로 구분하는 기법. 
	- 만약 C 클래스 IP 주소를 가진 회사에서 100개의 주소를 필요로 하는 부서의 경우와 25개의 주소를 필요로 하는 4개의 부서를 서브넷팅하는 경우에 적용이 가능함.
- **(바) 특수 주소**
	- 특별한 목적으로 사용되는 디스-호스트(this-host) 주소, 제한된 브로드캐스트 주소, 루프백 주소, 사설 주소, 멀티캐스트 주소의 다섯 가지 특수 주소가 있다.
	- **디스-호스트 주소**
		- 0.0.0.0/32 주소를 디스-호스트 주소라고 함. IP 데이터그램을 보내려 하지만 근원지 주소인 자신의 주소를 모를 때 사용.
	- **제한된 브로드캐스트 주소**
		- 255.255.255.255/32 주소. 
		- 이 주소는 호스트나 라우터가 네트워크상의 모든 장치로 데이터그램을 보낼 때 사용됨.
		- 하지만 네트워크상의 라우터가 이런 패킷을 차단하기 때문에 네트워크 외부로 패킷을 보낼 수 없음.
	- **루프백 주소**
		- 127.0.0.0/8은 자기 자신을 가리킴.
		- 이 블록 내의 주소를 가진 패킷은 호스트를 벗어나지 않고 호스트에 남게 됨.
		- 테스트에 가장 많이 쓰는 주소.
